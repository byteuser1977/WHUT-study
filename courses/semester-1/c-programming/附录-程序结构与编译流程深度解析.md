## 1. C 程序宏观结构

```c
// 典型 C 文件结构（自顶向下）

// ① 预处理指令（以 # 开头，不以分号结尾）
#include <stdio.h>        // 系统头文件
#include "my_header.h"    // 自定义头文件
#define PI 3.14159        // 宏定义
#define MAX(a,b) ((a)>(b)?(a):(b))  // 带参数宏

// ② 全局变量 / 静态变量（文件作用域）
int global_counter = 0;           // 外部链接，其他文件可 extern 访问
static int file_private = 42;     // 内部链接，仅本文件可见

// ③ 函数声明（前向声明，供后面调用）
void helper_function(int x);      // 只有声明，无函数体
int add(int a, int b);            // 参数名可省略：int add(int, int);

// ④ 主函数（程序入口，有且仅有一个）
int main(int argc, char *argv[]) {   // 标准带参形式
    // 局部变量（块作用域）
    int local_var = 10;
    
    // 语句与表达式
    printf("Args: %d\n", argc);
    helper_function(local_var);
    
    return 0;   // 返回给操作系统
}

// ⑤ 函数定义（实现）
void helper_function(int x) {
    static int call_count = 0;   // 静态局部变量：生命周期全程，作用域仅函数内
    call_count++;
    printf("Called %d times, x=%d\n", call_count, x);
}

int add(int a, int b) {
    return a + b;
}
```

> 💡 **作用域 vs 生命周期** 区别：
> - **作用域**：名字可见的代码范围（编译期概念）
> - **生命周期**：变量在内存中存在的时间（运行期概念）
> - `static` 既能修饰全局变量（限制链接属性），也能修饰局部变量（延长生命周期）

## 2. 编译四阶段全景

```mermaid
graph LR
    A[hello.c] -->|预处理 -E| B[hello.i]
    B -->|编译 -S| C[hello.s]
    C -->|汇编 -c| D[hello.o]
    D -->|链接| E[hello/hello.exe]
```

### 2.1 预处理 —— `.c` → `.i`

```bash
gcc -E hello.c -o hello.i
```

**做的事**：
- 展开 `#include`：把头文件内容**原封不动**插入
- 展开 `#define` 宏：文本替换，**不做语法检查**
- 处理条件编译：`#ifdef/#if/#elif/#else/#endif`
- 删除注释（`//` 和 `/* */`）
- 添加行号标记（供编译器报错定位）

**查看 `.i` 关键点**：
```c
# 1 "hello.c"
# 1 "<built-in>"
# 1 "<command-line>"
# 31 "/usr/include/stdio.h"   // 标记来自 stdio.h
// ... stdio.h 全文内容被展开 ...
# 1 "hello.c" 2               // 回到 hello.c 第 2 行
int main(void) {
    printf("Hello, World!\n");
    return 0;
}
```

> ⚠️ **头文件只放声明，不放定义** —— 否则多文件包含同一头文件会导致"重复定义"链接错误。

---

### 2.2 编译 —— `.i` → `.s`（汇编代码）

```bash
gcc -S hello.i -o hello.s
# 或直接
gcc -S hello.c -o hello.s
```

**做的事**：
- 词法/语法/语义分析
- 生成中间表示（GIMPLE/RTL）
- 优化（`-O0` ~ `-O3`、`-Os`）
- 输出目标平台汇编（x86-64 AT&T 语法）

**查看 `.s` 片段**（x86-64，`-O0` 无优化）：

```asm
.file   "hello.c"
.text
.section .rodata
.LC0:
    .string "Hello, World!"
.section .text.unlikely
.section .text.startup
.section .text.hot
.p2align 4
.globl  main
.type   main, @function
main:
.LFB0:
    .cfi_startproc
    endbr64
    pushq   %rbp
    .cfi_def_cfa_offset 16
    .cfi_offset 6, -16
    movq    %rsp, %rbp
    .cfi_def_cfa_register 6
    subq    $16, %rsp
    leaq    .LC0(%rip), %rdi
    call    puts@PLT
    movl    $0, %eax
    leave
    .cfi_def_cfa 7, 8
    ret
    .cfi_endproc
.size   main, .-main
.ident  "GCC: (Ubuntu 13.2.0-23ubuntu4) 13.2.0"
.section .note.GNU-stack,"",@progbits
```

> 💡 **读汇编技巧**：
> - `.LC0`：只读数据段（字符串字面量）
> - `main:`：函数入口标号
> - `pushq %rbp / movq %rsp, %rbp`：建栈帧
> - `call puts@PLT`：调用库函数（PLT = Procedure Linkage Table）
> - `movl $0, %eax`：返回值放在 `%eax` 寄存器

---

### 2.3 汇编 —— `.s` → `.o`（目标文件/二进制目标代码）

```bash
gcc -c hello.s -o hello.o
# 或直接
gcc -c hello.c -o hello.o
```

**做的事**：
- 汇编指令 → 机器码（二进制）
- 生成 **ELF 格式** 目标文件（Linux）/ COFF (Windows)
- 包含：代码段 `.text`、只读数据 `.rodata`、数据段 `.data`、BSS 段 `.bss`、符号表、重定位表

**查看目标文件结构**：

```bash
# 1. 文件类型
file hello.o
# hello.o: ELF 64-bit LSB relocatable, x86-64, version 1 (SYSV), not stripped

# 2. 节区
objdump -h hello.o
# Idx Name          Size      VMA       LMA       File off  Algn
#   0 .text         0000002c  00000000  00000000  00000040  2**4  CONTENTS, ALLOC, LOAD, READONLY, CODE
#   1 .data         00000000  00000000  00000000  00000070  2**0  CONTENTS, ALLOC, LOAD, DATA
#   2 .bss          00000000  00000000  00000000  00000070  2**0  ALLOC
#   3 .rodata       0000000e  00000000  00000000  00000070  2**0  CONTENTS, ALLOC, LOAD, READONLY, DATA

# 3. 符号表
nm hello.o
# 0000000000000000 T main         # T = 代码段全局符号
#                  U puts         # U = 未定义符号（需链接时解决）
```

> 🎯 **目标文件特点**：
> - **不可直接运行**（缺少启动代码、库函数地址）
> - `U puts` 表示"我要用 puts，但地址不知道，链接时填"
> - 多个 `.o` 可归档成静态库 `.a`（Linux）或 `.lib` (Windows)

---

### 2.4 链接 —— `.o` + 库 → 可执行文件

```bash
gcc hello.o -o hello
```

**做的事**：
1. **符号解析**：把所有 `U` (undefined) 符号匹配到定义（`T`/`D`/`B`）
2. **重定位**：修正代码中的相对地址、填入绝对/相对跳转偏移
3. **链接启动代码**：`crt1.o`/`crti.o`/`crtn.o`（`_start` → 调用 `__libc_start_main` → 调用 `main`）
4. **链接标准库**：默认动态链接 `libc.so.6`、`ld-linux-x86-64.so.2`
5. **生成可执行 ELF**：含程序头表、段映射、动态段、入口点 `_start`

**查看可执行文件**：

```bash
# 1. 文件类型
file hello
# hello: ELF 64-bit LSB pie executable, x86-64, version 1 (SYSV), dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, for GNU/Linux 3.2.0, not stripped

# 2. 程序头（加载视角）
readelf -l hello
# Type           Offset   VirtAddr   PhysAddr   FileSiz  MemSiz   Flg Align
# LOAD           0x000000 0x0000000000001000 0x... 0x...    0x...    R E 0x1000   # 代码段
# LOAD           0x001000 0x0000000000002000 0x... 0x...    0x...    R   0x1000   # 只读数据
# LOAD           0x002000 0x0000000000003000 0x... 0x...    0x...    RW  0x1000   # 读写数据

# 3. 动态依赖
ldd hello
# linux-vdso.so.1 =>  (0x00007ffc...)
# libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6 (0x...)
# /lib64/ld-linux-x86-64.so.2 => /lib64/ld-linux-x86-64.so.2 (0x...)

# 4. 入口点
readelf -h hello | grep Entry
# Entry point address: 0x1040   # 实际是 _start，而非 main
```

> 💡 **动态链接 vs 静态链接**：
> - 默认动态链接：可执行文件小、库升级自动生效、内存共享库代码段
> - 静态链接：`gcc -static hello.c -o hello_static`，完全自包含、体积大、部署简单
> - 混合：`-Wl,-Bstatic -lmylib -Wl,-Bdynamic` 指定某库静态链接

## 3. 静态库 vs 动态库

| 维度 | 静态库 `.a` / `.lib` | 动态库 `.so` / `.dll` |
|------|---------------------|----------------------|
| **链接时机** | 编译链接阶段 | 运行时加载 |
| **文件体积** | 打入可执行文件，大 | 仅存引用，可执行文件小 |
| **内存占用** | 每进程一份代码副本 | 多进程共享一份代码段 |
| **更新部署** | 需重新链接分发 | 替换 `.so` 即可（兼容版本） |
| **符号可见性** | 全部导出 | 可控制导出符号（版本脚本） |
| **命名规范** | `libname.a` | `libname.so` / `libname.so.1` |
| **链接参数** | `-lname` (搜 libname.a) | `-lname` (搜 libname.so) |
| **运行时查找** | 无 | `LD_LIBRARY_PATH`、`rpath`、`/etc/ld.so.conf` |

**制作静态库**：
```bash
# 1. 编译目标文件
gcc -c math_add.c -o math_add.o
gcc -c math_sub.c -o math_sub.o

# 2. 归档
ar rcs libmath.a math_add.o math_sub.o

# 3. 使用
gcc main.c -L. -lmath -o main
# -L. 当前目录找库，-lmath 扩展为 libmath.a
```

**制作动态库**：
```bash
# 1. 编译位置无关代码
gcc -fPIC -c math_add.c -o math_add.o
gcc -fPIC -c math_sub.c -o math_sub.o

# 2. 链接成共享库
gcc -shared -o libmath.so math_add.o math_sub.o

# 3. 使用（需指定运行时路径）
gcc main.c -L. -lmath -Wl,-rpath=. -o main
# 或运行时 export LD_LIBRARY_PATH=.
```

> 🎯 **工程实践**：
> - 默认动态链接系统库（glibc、pthread、m、dl、rt）
> - 自研库：内部组件动态链接、对外发布提供静态+动态两版本
> - 嵌入式/无 OS 环境：全静态链接

## 4. 常见编译/链接报错速查

| 报错类型 | 典型信息 | 成因 | 解决 |
|---------|---------|------|------|
| **预处理** | `fatal error: my.h: No such file or directory` | 头文件路径不对 | `-I/path/to/include` 或 `#include "path/my.h"` |
| **编译** | `error: expected ';' before '}' token` | 语法错误（漏分号、括号不匹配） | 看行号、对照语法修 |
| **编译** | `warning: implicit declaration of function 'foo'` | 用函数未声明（C99 禁止隐式声明） | 补 `#include` 或前向声明 |
| **编译** | `error: conflicting types for 'foo'` | 声明与定义不一致 | 统一参数/返回类型 |
| **链接** | `undefined reference to 'foo'` | 声明了但没定义、或没链接库 | 补定义、加 `-lfoo -L/path` |
| **链接** | `multiple definition of 'foo'` | 多文件定义同名全局变量/函数 | 头文件只 `extern` 声明，`.c` 定义一次 |
| **链接** | `undefined reference to 'main'` | 没写 `main` 或拼写错 | 补标准 `int main(void)` |
| **运行** | `error while loading shared libraries: libxxx.so` | 动态库找不到 | `export LD_LIBRARY_PATH=...` 或 `-Wl,-rpath` |

## 5. 多文件编译实战

### 目标结构
```
project/
├── main.c          # 主程序
├── calc.h          # 声明
├── calc.c          # 实现
└── Makefile        # 构建脚本
```

**calc.h**：
```c
#ifndef CALC_H   // 防重复包含卫语句
#define CALC_H

// 仅声明，无定义
int add(int a, int b);
int sub(int a, int b);

#endif
```

**calc.c**：
```c
#include "calc.h"

int add(int a, int b) { return a + b; }
int sub(int a, int b) { return a - b; }
```

**main.c**：
```c
#include <stdio.h>
#include "calc.h"

int main(void) {
    printf("3 + 5 = %d\n", add(3, 5));
    printf("10 - 4 = %d\n", sub(10, 4));
    return 0;
}
```

**手动编译**：
```bash
gcc -Wall -Wextra -std=c17 -c calc.c -o calc.o
gcc -Wall -Wextra -std=c17 -c main.c -o main.o
gcc calc.o main.o -o calc_app
./calc_app
```

## 本讲小结

| 阶段 | 命令 | 输入 | 输出 | 核心作用 |
|------|------|------|------|----------|
| 预处理 | `gcc -E` | `.c` | `.i` | 展开头文件/宏、条件编译 |
| 编译 | `gcc -S` | `.i` | `.s` | 语法分析、优化、生成汇编 |
| 汇编 | `gcc -c` | `.s` | `.o` | 汇编→机器码、生成重定位表 |
| 链接 | `gcc` | `.o` + 库 | 可执行文件 | 符号解析、重定位、加启动代码 |

| 产物 | 格式 | 能否运行 | 用途 |
|------|------|---------|------|
| `.i` | 文本 | 否 | 宏展开调试 |
| `.s` | 文本汇编 | 否 | 看优化、内联汇编 |
| `.o` | ELF relocatable | 否 | 归档静态库、增量编译 |
| 可执行文件 | ELF executable | **是** | 最终交付运行 |
