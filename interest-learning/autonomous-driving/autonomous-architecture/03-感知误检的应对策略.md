# 第03讲：感知误检的应对策略（正文约6分钟 + 练习约4分钟）

## 你将学到
- 误检（假阳性）和漏检（假阴性）分别会把车带向什么后果
- 从感知端到系统级，四层各自的应对手段
- 为什么整套策略必须偏保守，同时又不能保守到车动不了

---

## 1. 两个方向，代价完全不对等

- **误检（假阳性，False Positive）**：路上没有东西，感知说有。后果通常是车**莫名其妙一脚刹、或者无谓地绕一下**。
- **漏检（假阴性，False Negative）**：路上真有东西，感知没看见。后果是车**直接撞上去**。

| | 误检（假阳性） | 漏检（假阴性） |
|---|---|---|
| 表现 | 幽灵障碍物、无谓急刹 | 障碍物不在列表里 |
| 直接被影响 | 舒适性、通行效率、乘客信任 | 安全性 |
| 代价量级 | 一次急刹，乘客骂一句 | 一次碰撞，可能不可逆 |

结论很直白：**误刹的代价远低于漏检的代价**，两者不对称。所以整套策略天然偏向保守——**把"不确定"当成"可能有"来处理**。

> 💡 类比：住宅里的烟雾报警器。炒菜油烟让它误响，会吵醒全家、还得搬凳子去关；但没有人会把灵敏度调到"保证不误报"，因为漏报一次就是火灾。工程师的做法不是调低灵敏度，而是**光电 + 离子双传感器互相印证、要求烟雾持续几十秒才报警**——用多源校验压掉误报，而不是放弃检测。

---

## 2. 四层应对策略

| 层 | 策略 | 一句话做法 |
|---|---|---|
| 感知端 | 多传感器交叉验证 | 视觉说有、激光雷达和毫米波也认可，才算数 |
| 感知端 | 时序一致性 | 连续 N 帧（如 3 帧）都出现才确认，挡掉单帧抖动 |
| 感知端 | 置信度与不确定性 | 输出置信度，并把"不确定"本身当成一种结果传给下游 |
| 规划端 | 保守处理 | 结构物、行人一律按真实障碍处理；代价分级而非 0/1 |
| 规划端 | 通道保留 | 守住可行驶区域约束，保留紧急重规划通道 |
| 控制端 | 限幅与平滑 | 对指令做变化率限制，避免一次误检引出激烈动作 |
| 控制端 | 兜底 | 保留紧急制动通道，独立于常规指令链 |
| 系统级 | 降级与接管 | 失效时降速、靠边、进安全状态；保留遥控接管 |
| 系统级 | 日志与回放 | 黑盒记录原始数据与决策，回放定位误检根因 |

## 3. 关键在"把误报率压下去"，不是"放弃检测"

保守到极端会出事：阈值一味调高、能见度要求一味加严，结果是**车在路上动不动就急刹，甚至干脆动弹不得**——这同样是失败产品。正确的做法是回头去压**误报率**：多帧确认过滤抖动、多源校验过滤单传感器异常、给障碍物分代价等级而不是简单的 0/1。

> ⚠️ 反例：因为怕误刹就把灵敏度调低、把检测范围缩小、甚至关掉某个传感器的结果。这是拿漏检的风险去换误检的舒服，方向正好反了。

> ⚠️ 常见坑：把"降低误报"等同于"把阈值调高"。阈值调高同时会压掉真实目标，正确手段是**加约束条件**（多帧 + 多源 + 位置合理性），不是**加门槛**。

## 🎯 动手练习（约4分钟）

1. 准备一张纸，画一个 2×2 表格：横轴写"感知端 / 规划端"，纵轴写"成本低、易实现 / 成本高、效果好"。把第 2 节的策略拆成卡片（一张一个），贴进四个格子里。
2. 造三个误检场景写下来：① 隧道口强光下地面的水渍被当成障碍物；② 路边广告牌上的汽车图案被检测成车辆；③ 单帧点云噪声形成一个小凸起。每个场景写明：哪一层拦截最合适？
3. 给场景 ① 写一句"如果这层没拦住，后面会发生什么"，把后果一路写到执行器。

> ✅ 你应该看到：多传感器交叉验证与时序一致性落在"成本低"一侧，紧急重规划通道与系统级接管落在"成本高"一侧；三个场景分别主要依赖 光照鲁棒性/语义类别校验、多源交叉验证、时序一致性；场景 ① 若没拦住，链条会一路走到 无谓急刹 或 无谓绕行。

## 本讲小结

| 要点 | 说明 |
|---|---|
| 代价不对称 | 误检让车变慢，漏检让车撞上；策略整体偏保守 |
| 感知端 | 多源交叉验证 + 连续 N 帧确认 + 传置信度与"不确定" |
| 规划端 | 保守处理、代价分级、保留可行驶区域约束与紧急重规划 |
| 控制端 | 指令限幅平滑，保留独立的紧急制动兜底 |
| 系统级 | 失效降级、遥控接管、黑盒日志与场景回放 |
| 正确方向 | 靠多帧确认与多源校验压误报率，不是靠调低灵敏度、放弃检测 |
