# 第01讲：自动驾驶软件架构与数据流（正文约6分钟 + 练习约4分钟）

## 你将学到
- 无人车软件分成哪几块，按什么顺序接力
- 每个模块的输入、输出各是什么，交接的"货物"长什么样
- 为什么整条链路的时间对齐，比单个模块的精度更关键

---

## 1. 先看全景：一条数据流

无人车软件不是一个"大程序"，而是一条**接力链**。每块只干一件事，干完把结果打包交给下一块：

```text
   相机 / 激光雷达 / 毫米波雷达 / IMU / GNSS / 轮速
                     │  原始数据：图像帧、点云、回波、姿态、位置、车速
                     ▼
   【感知 Perception】检测 + 分割 + 跟踪 + 定位
                     │  障碍物列表(位置/速度/尺寸/类别/置信度)
                     │  + 可行驶区域 + 自车位姿
                     ▼
   【预测 Prediction】其他交通参与者未来 3~5 s 的轨迹
                     │  预测轨迹
                     ▼
   【规划 Planning】全局路径 → 局部轨迹(避障 + 速度剖面)
                     │  轨迹：一串带时间戳的位姿 + 速度
                     ▼
   【控制 Control】横向(转向) + 纵向(驱动 / 制动)
                     │  指令：目标转角、目标扭矩、制动请求
                     ▼
   执行器：EPS / EHB / 电机控制器 / VCU
```

> 💡 类比：这条链像**餐厅出餐**。采购（传感器）把食材搬进来，备菜（感知）洗好切好，领班预判（预测）客人接下来还要加什么，排菜（规划）决定先炒哪锅、用多大火，灶台（控制）调火翻勺，服务员（执行器）端上桌。任何一环慢半拍，上桌的都是凉菜。

## 2. 每个模块的输入输出

| 模块 | 输入 | 输出 | 典型频率 |
|---|---|---|---|
| 传感器层 | 物理世界 | 图像帧、点云、毫米波回波、IMU 姿态、GNSS 定位、轮速 | 10~30 Hz |
| 感知 | 原始数据 + 标定参数 | 障碍物列表、可行驶区域、自车位姿 | 10~20 Hz |
| 预测 | 障碍物列表 + 自车位姿 + 地图 | 每个动态目标各自的未来轨迹 | 5~10 Hz |
| 规划 | 预测轨迹 + 地图 + 任务目标 | 局部轨迹（位姿 + 速度 + 时间戳） | 10 Hz |
| 控制 | 局部轨迹 + 车辆反馈（车速、转角） | 转角、扭矩、制动请求 | 50~100 Hz |
| 执行器 | 上述指令 | 前轮转角、制动力、驱动扭矩 | 100 Hz~1 kHz |

两个规律：**越往下频率越高、逻辑越简单**；**越往上算得越重**。

## 3. 为什么一定要分层

- **可替换**：换了激光雷达，只改感知的输入适配，规划控制一行不动。
- **可降级**：某一层变慢时能单独降频，而不是整车卡死。
- **可验证**：每层的输出都是定义清楚的"货物"，可以离线灌数据回放。

软件上落地方式是 ROS 2 的节点与话题：一个模块一个节点，模块之间用话题传消息。节点、话题的概念与建包流程见 [ros2/01](../../perception/ros2/01-ros2是什么.md)；感知模块内部的算法细节（去畸变、颜色阈值、分割）见 [ai-perception/05](../../perception/ai-perception/05-感知流水线与工程集成.md)。本讲不重复展开。

> ⚠️ 常见坑：以为"把每个算法调准就行"，忽略模块之间的**时间对齐**。感知交出去的是 100 ms 前那一帧的结果，控制却按"现在"去算，车就会追着旧信息走——直线上看不出来，一变道就现形。

## 本讲小结

| 要点 | 说明 |
|---|---|
| 数据流 | 传感器 → 感知 → 预测 → 规划 → 控制 → 执行器，单向接力 |
| 交接货物 | 原始数据、障碍物列表、预测轨迹、局部轨迹、控制指令 |
| 频率规律 | 上游重而慢，下游轻而快，控制层频率最高 |
| 分层价值 | 可替换、可降级、可验证 |
| 时间对齐 | 每层输出都带时间戳，忽略它会引发"追着旧信息开车" |
