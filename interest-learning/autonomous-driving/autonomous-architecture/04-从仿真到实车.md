# 第04讲：从仿真到实车（正文约6分钟 + 练习约4分钟）

## 你将学到
- 为什么算法先在仿真里跑，仿真里到底"仿"了些什么
- 仿真和实车差在哪三处，为什么会差
- 一套从仿真到实车的渐进验证顺序，以及每一关的出场条件

---

## 1. 仿真买的是"便宜地撞车"

真车上练一次危险场景，成本是车损与安全风险；仿真里可以一夜跑几万公里、把同一个弯道跑上千遍。它还提供现实中极难拿到的东西：**真值**——仿真里每个物体的真实位置你是知道的，所以那里才是唯一能算准准确率的地方。

| 仿真里的东西 | 对应现实 | 备注 |
|---|---|---|
| 车辆动力学模型 | 质量、轴距、轮胎侧偏刚度 | 参数要实测辨识 |
| 传感器模型 | 成像、点云、回波、噪声 | 噪声模型往往是简化的 |
| 场景 | 道路、车流、行人、锥桶、光照 | 场景库要覆盖极端情况 |
| 真值（GT） | 每个物体的真实位姿 | 实车上几乎拿不到 |

## 2. 仿真与实车的三处差距

| 差距 | 表现 | 怎么补 |
|---|---|---|
| 模型差距 | 轮胎、悬架、地面附着都是近似 | 用实车数据做参数辨识，逐项对齐 |
| 传感器差距 | 真实噪点、过曝、逆光、雨雾、镜头污渍；仿真点云太干净 | 给模型加噪声与退化，录真实数据回灌 |
| 系统差距 | 时延、抖动、丢帧、算力有限、时钟不同步 | 硬件触发或时间同步，留足时间预算 |

一句话：**仿真里默认完美的东西，车上都得单独验一遍。**

> 💡 类比：这就像飞行模拟机。飞行员在模拟机里把发动机失效练了上千遍，模拟机也确实能复现仪表读数和操纵手感；但第一次真飞，教员还是得坐在旁边。差别不在操作，而在模拟机里没有真的风、真的油量和真的恐惧。

## 3. 渐进上车的顺序

| 阶段 | 在测什么 | 过关条件（示例） |
|---|---|---|
| 纯仿真 | 算法逻辑、场景覆盖 | 场景库全通过，无逻辑崩溃 |
| 软件在环（SIL） | 真实代码 + 仿真世界 | 时序、话题收发正确 |
| 硬件在环（HIL） | 真实控制器 + 仿真世界 | 接口、延时、丢帧满足要求 |
| 低速实车 | 真实传感器 + 真实执行器 | 低速直线/绕障稳定 |
| 封闭场地 | 全链路 + 极端场景 | 遥控接管随时可用，兜底有效 |
| 逐步放开 | 速度与场景边界 | 每一档都先小范围、再扩展 |

建模与代码生成的开发流程见 [simulink/04](../../electronic-control/simulink/04-mbd开发流程.md)（MBD，Model-Based Design，基于模型的设计），仿真验证的做法见 [stateflow/05](../../electronic-control/stateflow/05-建模仿真与验证.md)。这两处本讲不重复。

## 4. 仿真跑通、实车不行，怎么查

先开**影子模式**：感知照常跑、结果照常记录，但不接入控制，用真实数据先看感知本身对不对。再**回放黑盒日志**，一个模块一个模块换真值进去，看偏差从哪一层开始出现。

排查顺序口诀：**能用真值比出来的，才是算法问题；比不出来的，先怀疑标定和时钟。**

> ⚠️ 常见坑：把实车上的偏差直接归因成"算法不行"，回头去改模型。多数情况下先坏的是标定没对齐、时间戳差了几十毫秒、或者某个话题在实车上掉帧。

## 🎯 动手练习（约4分钟）

1. 把第 3 节的表格画成一张**阶梯图**（从左下到右上六级台阶），每级台阶上写三个词：在测什么、最高车速、谁来兜底。
2. 在第 2 节的三处差距里选一处，写两句话解释："如果它在仿真里被忽略，实车上会表现出什么症状？"
3. 给"影子模式"画一个极简框图：标出哪些线连到控制、哪些线只连到记录，并标出被剪断的那一根。

> ✅ 你应该看到：阶梯图上一级比一级快（从 0 到封闭场地的低速，再到逐步放开），每一级都必须有遥控接管兜底；模型差距的症状是同一段路仿真里过得很干净、实车会轻微跑偏或顿挫；影子模式的框图上，感知→记录 是实线，感知→控制 是虚线或断开。

## 本讲小结

| 要点 | 说明 |
|---|---|
| 仿真的价值 | 便宜、可重复、危险场景安全，且能拿到实车拿不到的真值 |
| 三处差距 | 模型近似、传感器理想化、系统时延与丢帧 |
| 上车顺序 | 仿真 → SIL → HIL → 低速实车 → 封闭场地 → 逐步放开 |
| 排查口诀 | 能拿真值比的才是算法问题，比不出来的先怀疑标定与时钟 |
| 兜底 | 每一级都必须保留遥控接管与紧急制动 |
