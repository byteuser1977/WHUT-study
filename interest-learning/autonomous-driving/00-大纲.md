# WUTIB 智能巴哈车队 · 无人组 学习笔记

> 从"能看懂代码"到"能讲清一辆无人车是怎么跑起来的"：算法基础、ROS 构建、软件架构与数据流、感知误检应对。
> 3 个学习模块 10 讲 + 1 讲自测，每讲约 10 分钟。零基础可读。
>
> **★ 已有笔记讲过的内容，本教程不重复，只做指路** —— 集中列在第 5 节。

## 一、这份笔记解决什么问题

无人组要干三件事：

1. **让代码跑起来** —— 代码跑在 Linux 上，用 ROS 组织成一个个功能包，靠构建系统编译成能执行的东西
2. **想清楚系统怎么运转** —— 感知 → 预测 → 规划 → 控制 → 执行器，数据在哪一环、谁影响谁
3. **写出能用的算法** —— 把一个问题拆成明确步骤，并知道怎么在几个方案里选

读完这份笔记，你应该能：

- 说清 `CMakeLists.txt` 在 ROS 包里起什么作用，并写出一个最小可用版本
- 画出自动驾驶软件架构的数据流图，举例说明**感知结果如何影响规划与控制输出**
- 说出感知误检时各层该怎么应对，以及为什么安全策略整体要偏保守
- 写出 2 种以上排序算法，并比较它们的复杂度、稳定性与适用场景

## 四、知识点 → 讲次索引

### 算法与编程

| 知识点 | 对应讲次 | 要点 |
|---|---|---|
| 三种直观排序 | [algorithms/01](algorithms/01-排序问题与三种直观解法.md) | 冒泡相邻交换、选择每轮选最小、插入像理牌；平均都是 **O(n²)** |
| 分治与更快排序 | [algorithms/02](algorithms/02-更快的排序与分治思想.md) | 快排按基准分区（**最坏 O(n²)**）；归并折半后线性合并（**稳定 O(n log n)**） |
| 复杂度与稳定性 | [algorithms/03](algorithms/03-算法怎么选与实测对比.md) | 冒泡/插入/归并**稳定**；选择/快排**不稳定**；归并要 O(n) 额外空间 |
| 工程选型 | [algorithms/03](algorithms/03-算法怎么选与实测对比.md) | Python `sorted()` 是 **Timsort**；C++ `std::sort` 是**内省排序**，要稳定用 `std::stable_sort` |

### ROS 构建

| 知识点 | 对应讲次 | 要点 |
|---|---|---|
| 构建系统的作用 | [ros-build/01](ros-build/01-功能包与构建系统.md) | 告诉机器"源码怎么变成可执行文件"：找依赖、编译、链接、安装 |
| 两种包的差别 | [ros-build/01](ros-build/01-功能包与构建系统.md) | **C++ 包（`ament_cmake`）要 CMakeLists.txt；Python 包（`ament_python`）只要 setup.py** |
| 六个必备件 | [ros-build/02](ros-build/02-cmakelists逐段解读.md) | `cmake_minimum_required`、`project`、`find_package(ament_cmake REQUIRED)`、`add_executable`、`ament_target_dependencies`、`install(... DESTINATION lib/${PROJECT_NAME})` |
| `ament_package()` | [ros-build/02](ros-build/02-cmakelists逐段解读.md) | **必须写在最后一行**：它注册 ament 索引并生成 CMake 配置，写在中间会让后面的 `install()` 失效 |
| 三个常见坑 | [ros-build/02](ros-build/02-cmakelists逐段解读.md) | 漏 `ament_package()` 包不被识别；漏 `install` 则 `ros2 run` 找不到；`package.xml` 未声明依赖会"本机能编译、换机就失败" |
| 编译流程 | [ros-build/03](ros-build/03-动手编译一个包.md) | `colcon build` → `source install/setup.bash` → `ros2 run`；`--packages-select` 只编一个包 |
