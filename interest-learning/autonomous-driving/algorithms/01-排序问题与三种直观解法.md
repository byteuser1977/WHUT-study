## 1. 排序问题：其实只有两件事

给一串数据，按指定规则排成有序，这就是排序。规则里用来比大小的那个字段叫**关键字（key）**，比如障碍物的距离、汽车的编号。整个过程中真正反复发生的只有两件事：**比较**两个元素谁大谁小、**交换**两个元素的位置。三种直观解法，区别只在这两件事用得聪不聪明。

## 2. 冒泡排序（Bubble Sort）：相邻两个比，大的往右挪

从前往后扫一遍，只要左边比右边大就交换。一轮扫完，最大的那个必然被顶到最右端，像气泡浮上水面。剩下的部分再来一轮，一共 n−1 轮。可以加个开关：某一轮一次都没换过，说明已经有序，提前收工。

## 3. 选择排序（Selection Sort）：每轮挑出最小的

第 i 轮在 a[i:] 这一段里找最小值的位置，把它和 a[i] 交换。它的交换次数最少，最多 n−1 次；但比较次数跟数据长什么样无关，固定是 n(n−1)/2 次，属于下笨功夫。

## 4. 插入排序（Insertion Sort）：像整理手里的牌

把 a[i] 先取出来存进 key，在前面的有序区里从右往左腾位置，腾到合适的地方再插进去。数据本来就接近有序时，几乎不用腾，效率明显好于前两种。

> 💡 类比：插入排序像**整理手里的扑克牌**——左手那叠已经理好，右手每摸一张，就顺着往左比，插进它该在的位置；牌越整齐，插得越快。

完整可跑的一段代码（10 个随机整数）：

```python
import random

def bubble_sort(a):
    a = a[:]
    for i in range(len(a) - 1):
        swapped = False
        for j in range(len(a) - 1 - i):
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
                swapped = True
        if not swapped:
            break
    return a

def selection_sort(a):
    a = a[:]
    for i in range(len(a) - 1):
        k = i
        for j in range(i + 1, len(a)):
            if a[j] < a[k]:
                k = j
        a[i], a[k] = a[k], a[i]
    return a

def insertion_sort(a):
    a = a[:]
    for i in range(1, len(a)):
        key = a[i]
        j = i - 1
        while j >= 0 and a[j] > key:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = key
    return a

random.seed(1)
data = [random.randint(1, 99) for _ in range(10)]
print("原始:", data)
print("冒泡:", bubble_sort(data))
print("选择:", selection_sort(data))
print("插入:", insertion_sort(data))
```

真实输出：

```text
原始: [18, 73, 98, 9, 33, 16, 64, 98, 58, 61]
冒泡: [9, 16, 18, 33, 58, 61, 64, 73, 98, 98]
选择: [9, 16, 18, 33, 58, 61, 64, 73, 98, 98]
插入: [9, 16, 18, 33, 58, 61, 64, 73, 98, 98]
```

> ⚠️ 常见坑：三个函数一进来先 `a = a[:]` 复制了一份。如果直接改传进来的列表，第一个函数跑完原始数据就已经有序了，后面两个跑的是"已经排好的数据"，你会误以为它们变快了。

1. 把上面的代码存成 `sorts.py`，在终端里运行 `python3 sorts.py`。
2. 删掉 `random.seed(1)` 那一行，多跑几次，看输出怎么变。
3. 把 `range(10)` 改成 `range(2000)`，加 `import time`，用 `perf_counter()` 给三个函数各计一次耗时。

**✅ 你应该看到**：三种写法输出同一个有序列表；n 从 10 涨到 2000 后，冒泡的耗时涨得最凶——按 O(n²) 估算，数据量每翻一倍，耗时约变 4 倍。

## 本讲小结

| 要点 | 说明 |
|---|---|
| 排序的本质 | 反复做两件事：比较大小、交换位置 |
| 冒泡排序 | 相邻两两比较、大的后移，n−1 轮，可提前结束 |
| 选择排序 | 每轮选最小的放到前面，交换最少、比较固定 |
| 插入排序 | 取出来往有序区里插，接近有序时明显更快 |
| 共同短板 | 平均都要 O(n²) 次比较，数据一大就撑不住 |
| 代码细节 | 先复制列表再排序，别污染原始数据 |
