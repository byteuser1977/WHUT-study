## 1. 大 O：只看数据量涨了，耗时怎么涨

**大 O 记号（Big O）** 描述增长趋势，不是秒数。n 翻倍时，O(n) 大致翻倍，O(n²) 大致变成 4 倍，O(n log n) 略多于 2 倍。

| 算法 | 平均 | 最坏 | 额外空间 | 稳定性 |
|---|---|---|---|---|
| 冒泡 | O(n²) | O(n²) | O(1) | 稳定 |
| 选择 | O(n²) | O(n²) | O(1) | 不稳定 |
| 插入 | O(n²) | O(n²) | O(1) | 稳定 |
| 快速 | O(n log n) | **O(n²)** | O(log n) 递归栈 | 不稳定 |
| 归并 | O(n log n) | O(n log n) | O(n) | 稳定 |

## 2. 实测：同一台机器上的真实耗时

用 `time.perf_counter()` 计时，输入是随机整数，每规模跑 3 次取最快：

| 算法 | n=1000 | n=5000 |
|---|---|---|
| 冒泡 | 0.0401 s | 1.0950 s |
| 选择 | 0.0182 s | 0.4604 s |
| 插入 | 0.0181 s | 0.4878 s |
| 快速 | 0.0010 s | 0.0057 s |
| 归并 | 0.0015 s | 0.0095 s |
| 内置 sorted() | 0.0001 s | 0.0004 s |

计时方法（把 5 个手写函数依次放进这个循环即可复现上表）：

```python
import random
import time

def insertion_sort(a):            # 第01讲的写法
    a = a[:]
    for i in range(1, len(a)):
        key = a[i]
        j = i - 1
        while j >= 0 and a[j] > key:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = key
    return a

random.seed(42)
for n in (1000, 5000):
    data = [random.randint(0, 100000) for _ in range(n)]
    for name, fn in (("插入", insertion_sort), ("内置", sorted)):
        t0 = time.perf_counter()
        fn(data)
        print(n, name, f"{time.perf_counter() - t0:.4f} s")
```

## 3. 换成"已经排好序"的输入，名次会变

同一批函数跑 `list(range(n))`，n=5000：冒泡 0.0003 s、插入 0.0005 s（骤降），选择 0.4558 s（几乎不变），快速 0.7254 s（比随机数据慢约 127 倍），归并 0.0061 s。快排最坏情况的规模增长（已有序）：

已有序输入下 n=500/1000/2000/4000 的耗时：0.0062 / 0.0259 / 0.1045 / 0.4434 s，数据量每翻一倍耗时约变 4 倍——这就是 O(n²)。用随机基准或三数取中可避开。

## 4. 工程收尾：实战直接用语言自带的排序

Python 的 `sorted()` 与 `list.sort()` 用的是 **Timsort**（归并+插入混合，稳定），对部分有序数据接近 O(n)，这也是它最快的原因。C++ 的 `std::sort` 用的是**内省排序（introsort）**——快排、堆排、插入的混合，**不稳定**；要稳定就写 `std::stable_sort`。

> 💡 类比：选排序算法像**出门选交通工具**——不是最快的就最好，要看路多远、几个人；通勤坐公交（自带排序），公交到不了的地方（内存极紧、规则特殊）才值得自己造。

**结论：实战优先用语言自带的排序**，手写算法是为了理解原理、应付特殊约束。

> ⚠️ 常见坑：只跑一次就下结论。同一次运行内可公平比较，但换机器、换一次运行，秒数浮动 30% 以上很常见——只比数量级、固定种子、多跑几次取最快。

## 本讲小结

| 要点 | 说明 |
|---|---|
| 大 O | 只描述增长趋势，不写秒数 |
| 实测差距 | n=5000 时冒泡比内置排序慢约 2700 倍 |
| 最坏情况 | 有序输入 + 基准取首元素 → 快排退化；此时插入、冒泡反而变快 |
| 稳定性 | 冒泡、插入、归并稳定；选择、快排不稳定 |
| 实战选择 | Python 用 `sorted()`（Timsort）；C++ 用 `std::sort`，要稳定用 `stable_sort` |
