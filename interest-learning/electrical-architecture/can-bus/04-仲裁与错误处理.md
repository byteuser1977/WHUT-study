# 第04讲：仲裁与错误处理（正文约6分钟 + 练习约4分钟）

## 你将学到
- 多个节点同时开口，为什么不会撞车
- 为什么"ID 越小优先级越高"是算出来的、不是规定的
- CAN 靠哪几种手段查出错误
- 节点出错后会被怎么"罚下场"，又怎么回到场上

---

## 1. 没有主节点的总线，谁先说

CAN 没有"主持人"轮询，任何节点只要看到总线空闲都可以尝试发送。两个节点同时开口时，靠**逐位仲裁（Arbitration）** 分出胜负，而且**报文不会被破坏**——这叫**非破坏性仲裁（Non-destructive Arbitration）**。

## 2. 仲裁怎么逐位进行

所有想发的节点同时发出自己帧的**仲裁场**（标准帧是 11 位 ID，之后还有 RTR，Remote Transmission Request 远程帧请求位），并且**边发边听回读**：

1. 每个节点发送一位的同时，回读这一位结束后总线上的实际电平。
2. 如果它发的是**隐性（1）**，读到的是**显性（0）**——说明有别的节点发了显性，自己输了，立刻停止发送、转为接收。
3. 发显性的节点不受影响，继续发下一位。
4. 一路比到最后只剩一个节点，它就是胜者，继续把整帧发完。

因为显性覆盖隐性，**ID 的二进制里 0 越多，压住别人的能力越强，优先级越高**。所以"ID 越小优先级越高"是逐位比较的必然结果，不是人为规定的排序。输掉的节点既不报错也不丢数据——它自动转为接收方，并在总线再次空闲时重发。

> 💡 类比：一群人同时用同一条"低音 / 高音"的嗓子报自己的编号，从编号第一位开始。你明明想说"高音（1）"，耳朵里却听到"低音（0）"，说明有人在这一位比你更强——你很自然地闭嘴。全程没有裁判喊停，最后只有一个人把编号报完。

## 3. CAN 的五种错误类型

| 错误类型 | 触发条件 | 谁发现 |
|---|---|---|
| 位错误 Bit Error | 发送方回读的电平与刚发出的不一致 | 发送方 |
| 填充错误 Stuff Error | 连续 5 个同极性位后必须插入 1 位相反位，未出现则错 | 收发双方 |
| CRC 错误 | 接收方按同样算法算出的校验与帧里的不符 | 接收方 |
| 格式错误 Form Error | 固定的格式位场里出现了非法电平 | 接收方 |
| 应答错误 ACK Error | 发送方没有收到任何节点回显的应答位 | 发送方 |

**位填充（Bit Stuffing）** 值得单说：它保证总线上不会长时间保持同一电平，这样其他节点才能靠电平跳变维持位同步——长时间没有跳变，各节点的时钟就会漂开，收出来的位就错位了。

## 4. 出错怎么罚：错误计数与三种状态

每个节点内部有**发送错误计数 TEC（Transmit Error Counter）** 和**接收错误计数 REC（Receive Error Counter）**：检出错误按规则大幅加计数，成功收发则递减，于是节点状态会迁移：

| 状态 | 进入条件 | 行为 |
|---|---|---|
| 错误主动 Error Active | TEC、REC ≤ 127 | 正常收发，可发显性错误帧 |
| 错误被动 Error Passive | TEC 或 REC > 127 | 仍能收发，但只能发隐性错误标志，且发送后必须等待间歇 |
| 总线关闭 Bus-Off | TEC > 255 | 主动脱离总线，停止收发 |

Bus-Off 是"罚下场"，目的是防止一个坏节点用错误帧把整条总线拖垮。规范要求节点自动尝试恢复（快恢复、慢恢复），所以现场常看到"某节点时而掉线、时而回来"，根因往往是**物理层问题**：终端电阻缺失、线序接反、波特率不一致。

> ⚠️ 错误帧不是"数据"。抓到错误帧只说明有节点没发送成功，排查顺序永远是**物理层优先**——先用第 01、02 讲的方法量终端电阻和两线电压，再怀疑软件配置。

## 🎯 动手练习

1. TSMaster 连上硬件，打开总线统计窗口，记下当前错误帧计数。
2. 让总线上同时有两个发送者（TSMaster 周期发 0x100，另一节点周期发 0x7FF），观察报文窗口里的到达节奏。
3. 比较这两个 ID 的周期抖动，看谁更稳。
4. 拔掉一端的终端电阻，再看错误帧计数与总线状态。
5. 断开 CAN_L 一根线，观察节点状态栏是否进入错误被动乃至总线关闭。
6. 恢复接线，观察错误计数回落后节点是否自动回到通信状态。

> ✅ 你应该看到：低 ID 的报文周期抖动很小，高 ID 的报文在冲突时被推迟，但**报文本身没被破坏**（非破坏性仲裁）；线路出问题后错误帧计数快速上涨，节点可能进入错误被动甚至 Bus-Off，故障排除后自动恢复。

## 本讲小结

| 要点 | 说明 |
|---|---|
| 仲裁 | 边发边听、逐位比较，显性压隐性，输者转为接收 |
| 优先级 | ID 二进制里 0（显性）越多优先级越高，故 ID 越小越优先 |
| 位填充 | 5 个同极性位后插 1 位相反位，用于维持位同步 |
| 错误类型 | 位错误 / 填充错误 / CRC / 格式 / 应答，共五类 |
| 错误计数 | TEC 与 REC，出错递增、成功收发递减 |
| 三种状态 | 错误主动 → 错误被动 → 总线关闭，Bus-Off 后自动尝试恢复 |
