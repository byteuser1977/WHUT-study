# 第03讲：报文与信号的关系（正文约6分钟 + 练习约4分钟）

## 你将学到
- 一帧 CAN 报文里装的是什么
- 信号不是"一根线"，而是数据场里的一段位
- 一个报文能装几个信号，一个信号能不能跨报文
- DBC 为什么是读懂总线的钥匙

---

## 1. 报文：总线上独立传输的数据单元

**报文（Message，也称帧 Frame）** 是 CAN 上一次传输的最小完整单元，经典 CAN 的一帧大致长这样：

| 字段 | 内容 | 说明 |
|---|---|---|
| 帧起始 SOF（Start of Frame） | 1 位显性 | 宣告"总线归我用" |
| 仲裁场 | 11 位 ID（标准帧）或 29 位 ID（扩展帧） | 报文身份，兼优先级 |
| 控制场 | DLC（Data Length Code，数据长度码） | 数据场长度，经典 CAN 0~8 字节 |
| 数据场 | 0~8 字节（CAN FD，Flexible Data-rate 最多 64 字节） | 真正要传的内容 |
| CRC 场（Cyclic Redundancy Check，循环冗余校验） | 15 位校验加界定符 | 检错 |
| ACK 场（Acknowledge，应答） | 应答位 | 只要有节点收对就回显性 |
| 帧结束 EOF（End of Frame） | 7 位隐性 | 收尾 |

**ID（Identifier，标识符）** 是最关键的字段：它既是"这是谁的报文"的身份标签，也决定优先级。注意 ID **不是发送者地址**，CAN 是**面向内容**而不是面向地址的——同一个 ID 在全网只能有一个发送者，其余节点都是接收者。

## 2. 信号：数据场里一段有物理含义的位

**信号（Signal）** 是报文数据场中**一段连续的位字段**，被赋予了物理意义。描述一个信号至少要这些信息：

| 属性 | 含义 | 举例 |
|---|---|---|
| 起始位 / 长度 | 从第几位开始、占几位 | 起始位 0，长度 16 |
| 字节序 | Intel（小端）/ Motorola（大端） | Intel |
| 因子 / 偏移 | 物理值 = 原始值 × 因子 + 偏移 | 0.1 / 0 |
| 单位 / 范围 | 工程单位与合法区间 | km/h，0~200 |

一个信号可以只占几位，也可以跨字节——**12 位的信号会横跨两个字节**，所以解析必须按位做，不能按整个字节切。

## 3. 打包关系：报文装信号

- **一个报文可以承载多个信号**：例如 ID 0x180 这帧的 8 字节里，可以同时塞进车速、电机转速、踏板开度、挡位。
- **一个信号只属于一个报文**：信号被"打包"在某一帧里，想传一个新信号，就得先在某个报文里给它划出一段位。

> 💡 类比：报文像**一个快递包裹**，ID 就是包裹单号；信号是包裹里的一件件货物，每件都有自己的标签（名字、量纲、规格）。快递员只管把包裹送到，不关心里面装了什么；要读懂里面每件货是什么，得靠那张**装箱单**——它就是 DBC。

## 4. DBC：让工具看懂位字段

**DBC（Database CAN，CAN 数据库文件）** 是描述 CAN 网络的文本文件，里面写着：有哪些报文、ID 与 DLC 是多少、每帧里有哪些信号、各自的起始位与长度、因子偏移单位、哪些节点是接收者。**同一段数据场，没有 DBC 你看到的只是十六进制；有了 DBC，工具才能把它翻译成"车速 32.4 km/h"这种能用的物理值。**

> ⚠️ 换车型或换固件版本时 DBC 必须同步更新。用旧 DBC 去解析新报文，软件照样显示数值，但那些数值可能是错的位、错的比例——**看起来正常的数据，比明显报错更危险**。

## 🎯 动手练习

1. 打开 TSMaster，新建工程，加载一个 DBC 文件；没有现成 DBC 就自己先建一帧报文和两个信号。
2. 在报文窗口找到这一帧（例如 ID 0x180、DLC 8）。
3. 切到信号视图，数一数这一帧下面挂着几条信号，记下各自的起始位、长度、因子与单位。
4. 记录它数据场的 8 字节原始值（十六进制）。
5. 按 物理值 = 原始值 × 因子 + 偏移 手算其中一条信号。
6. 与 TSMaster 显示的值对照。

> ✅ 你应该看到：同一帧 ID 下**不止一条信号**；手算结果与软件显示吻合。如果差了一个固定倍数，多半是因子看漏了；如果差得离谱，多半是起始位或字节序弄错了。

## 本讲小结

| 要点 | 说明 |
|---|---|
| 报文 | 总线上独立传输的数据单元：ID + 数据场 + CRC + ACK 等 |
| 数据场长度 | 经典 CAN 0~8 字节，CAN FD 最多 64 字节 |
| ID | 身份标签兼优先级，是内容标签而非发送者地址 |
| 信号 | 数据场中一段有物理含义的位字段，可以跨字节 |
| 打包关系 | 一个报文可含多个信号，一个信号只属于一个报文 |
| DBC | 描述报文与信号含义的文件，是把原始数据翻译成物理值的钥匙 |
