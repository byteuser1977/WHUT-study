## 1. 三条路，各有各的活

车上的数据用一个网络包不下来：**控制指令要确定性、传感器数据要带宽、调试数据要简单**，于是分三条路走。

- **CAN（Controller Area Network，控制器局域网）**：多主、广播式总线。所有节点挂在 CAN_H / CAN_L 两根双绞线上，速率不高但**确定性好**——谁先说话由 ID 仲裁决定，不会出现"急事被大流量堵住"。整车控制指令与状态量走它。
- **车载以太网（Automotive Ethernet）**：点对点连接，中间用交换机组成星型。100BASE-T1 用一对双绞线跑 100 Mbps 全双工，1000BASE-T1 可到 1 Gbps。带宽大，激光雷达点云、摄像头图像这类"大块头"走它。
- **串口（Serial Port，异步串行通信，常见 UART）**：点对点，没有地址也没有仲裁，一收一发。速率低（常见 115200 bps），但**延迟小、实现最简单**，惯导、遥控接收机、调试口都爱用它。

> 💡 类比：CAN 像**对讲机频道**——大家都在听，谁的 ID 数值小谁就接着说；车载以太网像**宽带光纤**——管子粗，能灌高清视频；串口像**两家之间的专线电话**——只连两头，简单直接。

## 2. 一张表看清差别

| 维度 | CAN | 车载以太网 | 串口 |
|---|---|---|---|
| 拓扑 | 总线型，一挂多 | 点对点 + 交换机（星型） | 点对点 |
| 常用速率 | 经典 500 kbps；CAN FD 数据段最高 5 Mbps | 100 Mbps / 1 Gbps | 常见 115200 bps |
| 实时性 | 按 ID 仲裁，确定性好 | 带宽大，靠 QoS 保障 | 延迟低，无仲裁 |
| 典型负载 | VCU、BMS、电机控制器、EPS、EHB | 激光雷达、视觉传感器 | 惯导、遥控接收机、调试口 |
| 成本布线 | 便宜，两根线挂多节点 | 较贵，需 PHY 与交换机 | 最便宜，两根线点对点 |

## 3. 选路的四个问题

拿到一个部件，按这四条问一遍，路径基本就定了：

| 问题 | 判断 |
|---|---|
| 要传多少数据？ | 几十字节级状态量 → CAN；点云/图像 → 以太网 |
| 要不要确定性？ | 控制闭环必须按时到达 → CAN；能容忍排队 → 以太网 |
| 线束能扛多重？ | 短距离点对点 → 串口；多节点共享 → CAN |
| 失效了什么后果？ | 转向/制动类 → 优先考虑冗余，别把鸡蛋放一个篮子 |

> ⚠️ 常见误解：以为"带宽越大越先进，全上车载以太网最好"。控制类信号要的是**确定性**和**低成本布线**，硬搬到以太网上反而要额外做 QoS、交换机和线束——**先问要传多少、要多快、要不要确定性，再选路。**

## 🎯 动手练习（约4分钟）

1. 在纸上列一张表，把下面 11 个部件逐个填上它该挂的网络：域控制器、VCU、EPS、EHB、BMS、电机控制器、激光雷达、视觉传感器、毫米波雷达、惯性导航、遥控接收机。
2. 挑出其中**三个**，用第 3 节的四个问题各写一句理由。
3. 翻一个你手边传感器的规格书（或队里的资料），确认它实际用的是什么接口，和你判断的是否一致。
4. 打开 TSMaster（同星智能），连上硬件看一次真实总线的报文列表，记下两个报文的 ID 与周期（操作步骤见 [can-bus/05](../can-bus/05-tsmaster模拟vcu发报文.md)）。

**✅ 你应该看到**：11 个部件里，走车载以太网的是激光雷达与视觉传感器，其余多数走 CAN，惯导与遥控偏串口；规格书上写的接口与你的判断大概率一致——不一致的地方，通常是队里做了工程取舍，值得记下来。

## 本讲小结

| 要点 | 说明 |
|---|---|
| CAN | 总线型多主广播，按 ID 仲裁，确定性好，服务控制类指令与状态量 |
| 车载以太网 | 点对点 + 交换机，100 Mbps~1 Gbps，服务点云与图像 |
| 串口 | 点对点、无仲裁、延迟低，惯导/遥控/调试常用 |
| 选路四问 | 数据量、确定性、线束重量、失效后果 |
| 易错 | 不是"带宽越大越好"，控制类硬上以太网会引入额外复杂度 |
