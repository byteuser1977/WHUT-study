# 第03讲：域控制器与整车拓扑（正文约6分钟 + 练习约4分钟）

## 你将学到
- 域控制器和 VCU 各管什么，为什么是两层而不是一层
- 整车拓扑长什么样：骨干 CAN、以太网支路、终端电阻在哪
- 报文在两台控制器之间怎么流，为什么不能透传

---

## 1. 两层架构：域控负责"想"，VCU 负责"动"

- **域控制器（Domain Controller，自动驾驶域）**：按功能域集中算力与高速接口，把激光雷达、摄像头、惯导、毫米波雷达的数据收上来，跑感知与规划控制，输出目标速度、目标转角这类"意图"。
- **VCU（Vehicle Control Unit，整车控制器）**：执行层的总协调，管上下电、运行模式、指令仲裁与限幅、故障诊断，把意图翻译成对电机控制器、EPS、EHB 的具体指令，并且**保留最终否决权**（急停、限扭、断驱动）。

分工一句话：**域控出方案，VCU 下命令**。分开的好处是算力与实时性解耦，安全逻辑集中在 VCU 一处，感知那边软件崩了也不会直接把车带跑偏。

## 2. 一张整车拓扑

```
   遥控接收机 ──串口──┐                    ┌──以太网── 激光雷达
                     ├──▶┌──────────┐◀────┼──以太网── 视觉传感器
   惯性导航   ──串口──┘   │ 域控制器  │◀────┼──CAN──── 毫米波雷达
                         └─────┬────┘
                               │ CAN 主干 500 kbps
                               │ ★两端各一个 120 Ω★
        ┌──────────┬───────────┼───────────┬───────────┐
       VCU        BMS      电机控制器      EPS          EHB
```

三个要点：①骨干 CAN **两端各一个 120 Ω**，其余节点都是 T 型分支挂上去；②大带宽传感器全部挂在域控的以太网口上，不占 CAN 带宽；③域控与 VCU 之间除 CAN 外可再留一条以太网，做诊断与大数据回传。

## 3. 节点与接口分配

| 层 | 节点 | 挂在哪 | 角色 |
|---|---|---|---|
| 计算层 | 域控制器 | 以太网中心 | 感知、规划、决策 |
| 控制层 | VCU | CAN 主干 | 模式管理、仲裁、限幅、诊断 |
| 执行层 | 电机控制器、EPS、EHB | CAN 主干 | 执行 VCU 指令并回传状态 |
| 感知层 | 激光雷达、摄像头、毫米波雷达、惯导、遥控接收机 | 域控接口 | 提供环境与自身状态 |

| 域控接口 | 连接对象 | 接口类型 | 线径 / 颜色建议 |
|---|---|---|---|
| 网口 1 | 激光雷达 | 100BASE-T1 | 车载以太网屏蔽双绞 / 蓝 |
| 网口 2 | 视觉传感器 | 100BASE-T1 | 车载以太网屏蔽双绞 / 蓝 |
| UART 1 | 惯性导航 | 串口 115200 bps | 0.35 mm² / 黄、绿 |
| UART 2 | 遥控接收机 | 串口 | 0.35 mm² / 黄、绿 |
| CAN 1 | CAN 主干（与 VCU、BMS 等共线） | 500 kbps，双绞 | 0.35 mm² 双绞 / 白、棕 |

## 4. 报文怎么流：解析、仲裁、转发

域控把感知结果打包成少数几条报文发到 CAN；VCU 收到后**不是原样透传**，而是按 **DBC 文件**把字节解析成信号（目标速度、目标转角、制动请求），做仲裁、限幅、模式判断，再组包发给各执行器。跨网段的部分由网关做**报文路由**——这类路由通常就做在域控或 VCU 内部，只把需要的报文放进另一条网段，而不是把整条总线的流量搬过去。

> 💡 类比：域控制器像**参谋部**（看地图、出方案），VCU 像**值班指挥员**（看方案、下命令、有权叫停）。参谋部再聪明，也不能绕过指挥员直接给前沿部队下令。

> ⚠️ 常见错误：把域控发来的原始报文直接透传给 EPS/EHB，跳过 VCU 的仲裁与限幅。这样急停、限扭这些兜底逻辑全都失效，一条野指令就能直接驱动执行器。

## 🎯 动手练习

1. Visio 新建"网络 / 基本网络图"模板（模板名**以你机器上为准**）；用服务器图标代表域控，用交换机图标代表以太网交换机。
2. 先画一条水平的 CAN 主干，**只在两端**放电阻符号（标 120 Ω）。
3. 每个节点画方框，用竖线做 T 型分支挂到主干，分支尽量短。
4. 大带宽传感器用另一种线型单独连到域控，**不并入 CAN 主干**。
5. 在每段线上标注协议与速率（500 kbps / 100BASE-T1），导出 PDF 存档。

> ✅ 你应该看到：图上没有任何节点串在主干线路中间，120 Ω 只出现两处；每个传感器都有明确的接口归属；域控与 VCU 之间的报文方向是双向箭头而不是单向。

## 本讲小结

| 要点 | 说明 |
|---|---|
| 域控 | 集中算力与高速接口，输出目标速度/转角等"意图" |
| VCU | 模式管理、仲裁限幅、诊断与安全兜底，掌握最终否决权 |
| 骨干 CAN | 两端各 120 Ω，节点 T 型分支，大带宽传感器另走以太网 |
| 接口分配 | 网口给激光雷达/摄像头，串口给惯导/遥控，CAN 给控制类 |
| 报文流 | 域控组包 → VCU 按 DBC 解析成信号 → 仲裁限幅 → 再组包下发 |
| 禁忌 | 原始报文透传会绕过安全逻辑，必须经 VCU 处理 |
