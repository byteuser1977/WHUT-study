## 1. 用"连线"代替"敲代码"

Simulink 是 MATLAB 里的**图形化建模与仿真环境**。普通编程是写一行行语句按顺序执行；Simulink 是**把运算画成方块（模块），用带箭头的线（信号线）把数据从一处送到另一处**——你画出来的就是数据的流动路径，不用自己写循环和变量赋值。

模型跑起来时，求解器按固定节奏反复"推进时间"，每一步让所有模块算出新输出、沿信号线传给下一个模块。所以它天生适合描述**连续变化的物理量**：转速、转角、电压、扭矩。

> 💡 类比：写代码像**照着菜谱一步步做菜**；Simulink 像**画一张工厂流水线图**——原料从哪进、经过哪几台机器、成品从哪出，一眼看全，改动了哪台机器当场看得见后果。

## 2. 四个必须记住的概念

| 概念 | 是什么 | 类比 |
|---|---|---|
| 模块（Block） | 基本运算单元，如 `Gain`（增益）、`Sum`（求和）、`Integrator`（积分） | 车间里的机器 |
| 信号线（Signal Line） | 模块之间的数据通道，有方向、有数据类型 | 传送带 |
| 子系统（Subsystem） | 把一堆模块打包成一个方块，只露输入输出 | 把机器封成一个车间 |
| 求解器（Solver） | 决定每一步怎么算、步长多大 | 时钟节拍 |

**子系统**是让模型"能看"的关键：几十个模块堆在一层会变成一团乱麻，`Ctrl+G` 打成子系统后顶层只剩几个大方块，正好对应"一个功能模块对内复杂、对外接口简单"。

## 3. 为什么控制开发爱用它

1. **能仿真**：不用等硬件、不用烧板子，参数改一下立刻看到曲线变化，一天能试几十版控制逻辑。
2. **模型就是文档**：新队员打开模型就能看懂信号怎么走，比读几千行 C 代码快得多。
3. **能自动出代码**：配上 `Embedded Coder`（嵌入式代码生成器），模型可直接生成可编译的 C 代码，这是 MBD 的基石（第 04 讲展开）。
4. **逻辑与数值分工**：数值计算用 Simulink 模块，模式切换、状态判断这类逻辑用 **Stateflow**（表现为 `Chart` 模块），两者在同一张图里配合。

> ⚠️ 别把 Simulink 当"画图软件"：模型里每个模块最终都要变成代码跑在车上。参数单位写错、限幅漏加，仿真里可能看不出来，上车就是真故障。

## 4. `.slx` 文件与工具链的关系

`.slx` 是**模型文件**，双击用 Simulink 打开，里面装着整张框图与所有参数，**它可以进版本管理**（是二进制格式，建议配合 Git LFS，或只看差异摘要）。`.m` 脚本管参数与自动化跑仿真，`.slxc` 是编译缓存可以不提交。

一句话理清：**Simulink 是平台，`.slx` 是文件，Stateflow 是嵌在 `.slx` 里专管逻辑的建模工具**。

## 🎯 动手练习（约4分钟）

1. 打开 MATLAB，命令行输入 `simulink`，等 Start Page 出来。
2. 点 `Blank Model` 新建，立刻 `Ctrl+S` 存为 `practice01.slx`。
3. 在 Library Browser 里搜 `Sine Wave`（正弦），拖进画布；再搜 `Scope`（示波器）拖进来。
4. 按住 `Sine Wave` 右侧的小箭头拖到 `Scope` 左侧，连成一条信号线。
5. 点工具栏 `Run`，双击 `Scope` 看波形。
6. 双击 `Sine Wave` 把 `Frequency`（频率）从默认值改成 `2`，再 `Run` 对比波形。

> ✅ 你应该看到：`Scope` 里是一条平滑的正弦波；频率改成 2 后，**同样时间内波峰数量翻倍**（周期变短）。改参数即改结果，一行代码都没写。

## 本讲小结

| 概念 | 要点 |
|---|---|
| Simulink | 图形化建模＋仿真环境，画数据流而不是写语句 |
| 模块 / 信号线 | 运算单元 / 数据通道，有方向、有数据类型 |
| 子系统 | 打包降复杂度只露接口，顶层才读得懂 |
| 求解器 | 决定算法与步长，步长直接决定仿真精度与速度 |
| `.slx` | 模型文件，含框图与参数，可进版本管理 |
| 与 Stateflow 的关系 | Stateflow 是 `.slx` 里的 `Chart` 模块，专管逻辑 |
