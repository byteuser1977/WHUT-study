# 第04讲：MBD 开发流程（正文约6分钟 + 练习约4分钟）

## 你将学到
- **MBD 是什么、流程怎么走** —— 从需求到实车的完整链路
- V 模型五阶段：需求 → 模型与 MIL → SIL → 代码生成 → PIL/HIL → 实车标定
- 一条铁律：先仿真后上车；工具链与四笔收益

---

## 1. MBD 是什么

**MBD = Model-Based Design，基于模型的设计**：把**模型当作唯一设计源**——需求、设计、仿真、代码、测试全部围绕同一个 `.slx` 模型展开。模型不是"画着好看的图"，而是能直接产出成品的图纸。

| | 传统开发 | MBD |
|---|---|---|
| 设计载体 | 需求文档 + 手写 C 代码 | 可执行的 Simulink 模型 |
| 验证时机 | 代码写完、上车才测 | 模型阶段就仿真验证 |
| 改需求 | 改代码，容易漏改 | 改模型，代码自动重新生成 |

一句话：**MBD 把调试从车上搬到了电脑上。**

> 💡 类比：传统开发像**裁缝按口头描述直接下剪刀**，做错只能重新裁布；MBD 像**先在电脑上做 3D 打版、虚拟试穿**，版型确认了再量产——返工成本从"一块布"降到"改个参数"。

## 2. V 模型五阶段（必背）

V 字左半边往下是逐步细化设计，底部是实现，右半边往上逐步验证：

1. **需求与系统设计**：把要什么写成可验证的指标，如"急停按下后 100 ms 内禁止输出驱动力"。
2. **模型开发与 MIL**（Model-in-the-Loop，模型在环）：在 Simulink 里搭模型跑仿真，验证**算法逻辑对不对**。
3. **SIL**（Software-in-the-Loop，软件在环）：把模型生成的 C 代码在 PC 上编译运行，与模型仿真结果逐点比对，验证**代码与模型等价**。
4. **代码生成**：用 `Embedded Coder` 出工程代码（第 05 讲展开）。
5. **PIL / HIL**（Processor-in-the-Loop 处理器在环 / Hardware-in-the-Loop 硬件在环）：PIL 把代码放到**真 VCU 板子**上跑、被控对象在 PC 里仿；HIL 反过来——**控制器是真的、车是仿的**，用实时机模拟电机、传感器与 CAN 报文，在台架上把急停、掉线、故障这些危险工况全试一遍。
6. **实车标定**：上车后用 CANape / INCA 一类工具在线改参数（PID 增益、限幅值），把控制效果调到赛场状态。

**铁律：先仿真后上车。** 先在 MIL 里把逻辑跑通，再往台架、实车推进。跳过仿真直接上车，等于拿车当调试器，撞坏一次的成本远超搭模型的时间。

> ⚠️ 别把 HIL 和实车测试搞混：HIL 里"车"是实时机仿出来的，可控、可复现，**急停与通信中断这类极端工况只能在 HIL 上安全复现**；实车既测不全，也测不起。

## 3. 工具链与收益

**工具链**：MATLAB / Simulink + Stateflow（建模）→ Simulink Coder（通用代码）/ **Embedded Coder**（面向嵌入式的优化代码）→ 目标编译器（TI CCS / Keil / GNU）→ 调试器与 CAN 工具（刷写、标定）。

**四笔收益**：① 逻辑错误在早期暴露，改一行参数比改一个焊点便宜得多；② 模型与子系统可复用（去年的扭矩限幅模块今年直接搬）；③ 模型即文档，新人看信号流向就能接手；④ 软硬件并行——硬件还在画板子时，软件已经在仿真里跑完整套逻辑了。

## 🎯 动手练习（约4分钟）

1. 打开 `practice03.slx`，`Ctrl+E` → 切到 `Code Generation` 页，看看 `System target file` 当前是什么（默认通常是 `grt.tlc`）。
2. 明确这个模型的"需求"：阶跃输入下输出稳定收敛，不超调发散。
3. 把 `Solver` 页的 `Stop time` 改成 `20`，`Run`，确认更长时间下依然稳定（这就是 MIL 验证）。
4. `Ctrl+E` → `Code Generation`，点 `Build` 生成一次代码。
5. 到 MATLAB 当前目录（或模型同级目录）找生成出来的 `.c` / `.h` 文件，打开 `.c` 看看里面有没有自动生成的时间步进函数。

> ✅ 你应该看到：`Build` 完成后提示构建成功，并生成一个以模型名命名、带 `_ert_rtw` 或 `_grt_rtw` 后缀的文件夹，里面有 `.c` / `.h`——**你一行 C 代码都没写**，代码是模型自动产出的，这就是 MBD 最直观的证据。

## 本讲小结

| 阶段 | 内容 | 验证了什么 |
|---|---|---|
| 需求与系统设计 | 把需求写成可验证的指标 | 要做的对不对 |
| 模型开发 + MIL | 模型在环，在 Simulink 里跑仿真 | 算法逻辑对不对 |
| SIL | 软件在环，PC 上跑生成的 C 代码 | 代码与模型是否等价 |
| 代码生成 | `Embedded Coder` 出 `.c` / `.h` | 能不能落地 |
| PIL / HIL | 处理器在环 / 硬件在环，台架试极端工况 | 在真板子上行不行 |
| 实车标定 | 上车在线调参到赛场状态 | 实际效果好不好 |
