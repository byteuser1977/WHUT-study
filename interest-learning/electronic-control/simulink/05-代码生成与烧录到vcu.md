# 第05讲：代码生成与烧录到 VCU（正文约6分钟 + 练习约4分钟）

## 你将学到
- **怎么部署烧录到我们的赛车 VCU** —— 从模型到固件的前半程
- 四步链路：定义可生成接口 → 配置模型 → 生成 C 代码并编译 → 烧录验证
- 三个必踩的坑：数据类型、限幅、版本记录

---

## 1. 第一步：把输入输出定义成"可生成的接口"

模型顶层必须用 **`Inport`（输入端口）/ `Outport`（输出端口）** 模块，不能拖个 `Constant` 顶替——它们对应将来 C 函数的一个参数与返回值，如 `RC_Online`（遥控通信正常）、`Target_Torque`（目标扭矩）。

**数据类型必须固定**：车上不用 `double`，统一成 `single`（单精度）或 `int16`/`uint8` 定点整型，并写明量纲与缩放（如 `Tq = raw × 0.1 N·m`）。采样周期也在这一步定，要与 VCU 任务周期（常见 1 ms 或 10 ms）一致。

> ⚠️ 车上**不要用 `double`**：VCU 主控多为定点 MCU，浮点要么无硬件支持、要么耗时不可控。

## 2. 第二步：配置 Model Configuration Parameters

`Ctrl+E` 打开 `Model Configuration Parameters`（模型配置参数），重点两页：

| 页 | 要设什么 | 典型值 |
|---|---|---|
| `Solver` | `Type` 选定步长，与 VCU 任务周期一致 | `Fixed-step`，`0.001` s |
| `Code Generation` | `System target file` 选 **`ert.tlc`**；接口风格与目标硬件 | `ert.tlc` + 按 VCU 选芯片族 |

**`ert.tlc` 是重点**：它是"嵌入式实时目标"，生成的代码精简、不依赖操作系统、变量静态分配，是车用代码的标准选择；默认的 `grt.tlc` 偏 PC 仿真，不适合烧进板子。

## 3. 第三步：生成 C 代码并编译链接

点 `Build`（`Ctrl+B`），`Embedded Coder` 把模型翻译成一套 C 工程：**`.c` 源文件、`.h` 头文件、参数表文件与一份 HTML 代码报告**（能逐行指回模块）。

再用**目标板工具链**编译链接：TI 的 CCS（C2000）、Keil MDK（ARM Cortex-M）、或 GNU 工具链，产出可烧写的 **`.hex` / `.bin` / `.out`** 固件。

> 💡 类比：模型是**乐高图纸**，生成的 C 代码是**分好类的积木零件**，编译器是**装配工**——装不装得上，看零件规格与目标板对不对得上。

## 4. 第四步：烧录到 VCU

1. **调试器直连下载**：JTAG / SWD（J-Link、XDS100 等）接 VCU 调试口，在 CCS/Keil 里点 `Flash`；开发阶段走这条，方便打断点。
2. **CAN / 串口 bootloader 刷写**：用一根 CAN 线把固件刷进去，不必拆壳接调试口；车队现场刷固件基本走这条。
3. **台架 HIL 先验**：上实车前先在台架跑急停、通信中断、传感器丢数这些工况。
4. **上车标定**：用 CANape / INCA 一类工具**在线改参数**（PID 增益、限幅值），不改代码只改标定量。

## 5. 三个必踩的坑

1. **数据类型没固定就生成**：模型里全用 `double` 跑得漂亮，生成到定点板子精度全错。生成前逐个接口核对类型与量纲。
2. **限幅只靠"看着对"**：仿真不超界不代表车上不会，`Saturation` 与 `Rate Limiter` **必须显式加在最终输出前**，这是最后一道防线。
3. **不记录版本**：烧完发现行为变了，却说不清跑的是哪个模型版本。每次烧录记录**版本号、生成时间、固件哈希**，与标定文件一起归档。

## 🎯 动手练习（约4分钟）

1. 打开 `practice03.slx`，把 `Step` 换成 `Inport`、接 `Scope` 的信号加一路 `Outport`，并把 `Inport` 类型从 `double` 改成 `single`。
2. 在 `Gain` 后串 `Saturation`（上限 `5`、下限 `-5`）与 `Rate Limiter`（上升斜率 `10`）。
3. `Ctrl+E`：`Solver` 选 `Fixed-step` / `0.001`；`Code Generation` 的 `System target file` 设为 `ert.tlc`。
4. `Ctrl+B` 生成代码，在 `.h` 里确认 `Inport` / `Outport` 变量与类型，并在 HTML 代码报告里追溯回模块。

> ✅ 你应该看到：生成成功提示，目录里有 `.c` / `.h`；输入输出变量类型是 `single` 而非 `double`。这就是从模型到固件的前半程。

## 本讲小结

| 步骤 | 关键动作 | 对应到车里 |
|---|---|---|
| ① 定义接口 | `Inport` / `Outport` + 固定数据类型（`single` / 定点） | 对应 C 函数入参与返回值 |
| ② 配置模型 | `Ctrl+E`：定步长 + `ert.tlc` + 目标硬件 | 与 VCU 任务周期、芯片对齐 |
| ③ 生成与编译 | `Build` 出 `.c` / `.h`，工具链编成 `.hex` / `.bin` | 固件文件 |
| ④ 烧录与验证 | JTAG/SWD 下载或 CAN bootloader 刷写 → 台架 HIL → 上车标定 | 车上的实际行为 |
| 三个坑 | 不固定数据类型 / 限幅靠"看着对" / 不记录版本 | 精度错、损坏执行机构、无法回滚 |
