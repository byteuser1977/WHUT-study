# 第01讲：VCU 是什么与主要功能（正文约6分钟 + 练习约4分钟）

## 你将学到
- VCU 是什么、在整车控制链里处于什么位置
- 它的六项主要功能，以及它们串成的一条控制链
- 六项功能怎么串成一条控制链
- 为什么"把安全逻辑集中在一处"是它的核心价值

---

## 1. VCU 是什么

**VCU = Vehicle Control Unit，整车控制器**，是车辆的"中央协调者"。车上真正出力的是**执行机构**——电机控制器、线控转向执行器、电控液压制动（EHB）；VCU 不直接出力，它**决定谁在什么时候出多少力**。

> 💡 类比：剧组的总调度员。灯光、道具、演员都不是他操作的，但"什么时候上、上多少"由他一个人统一发令；没有他，各工种各自为战，事故正好出在交界处。

注意分层：VCU 管**整车级**的决策与协调，电机控制器管**一个电机**的电流环——两者同级、各管一段，别混为一谈。遥控接收机、自主驾驶域控制器也各有分工，VCU 站在它们和执行机构之间。

## 2. 六项主要功能

| # | 功能 | 具体干什么 |
|---|------|-----------|
| 1 | 信号采集与解析 | 把开关、传感器、CAN 报文的原始数据翻译成有物理意义的量（车速 xx m/s、转角 xx°），并做有效性检查 |
| 2 | 驾驶模式管理 | 在待机 / 遥控 / 自主 / 紧急之间切换，即模块三的状态机 |
| 3 | 指令仲裁与协调 | 多来源指令谁生效、冲突怎么裁决、限幅与平滑（如扭矩变化率限制） |
| 4 | 指令输出 | 把决策结果变成执行机构能收的指令：驱动扭矩、转向转角、制动请求 |
| 5 | 故障诊断与安全保护 | 看门狗、故障分级、失效时进安全状态（禁驱动力 + 出制动请求） |
| 6 | 通信与上下电管理 | CAN/串口与遥控、自主系统、电机控制器、BMS 交互；上电自检、下电顺序、数据记录 |

记法：**收（1）→ 判（2、3）→ 发（4）→ 保（5、6）**。

> ⚠️ 第①条不是"打个包转发"：原始值必须做量程、合理性和超时检查（遥控掉线、转角跳变、报文超时），否则后面所有判定都建立在脏数据上。自测时点出"有效性检查"这几个字，是拉开差距的地方。

## 3. 六项功能串成一条闭环链

单看六条容易背成清单，串起来才看得懂：

```text
传感器/开关/CAN 报文 → ①采集解析 → ②模式判定 → ③仲裁限幅
                                                      ↓
   执行机构动作 ← ④指令输出 ←───────────────┘
        ↓
   车辆状态变化 →（反馈回到①，同时⑤实时监视、⑥负责对外通信）
```

关键点是**⑤不是最后一步，而是全程并行**：故障诊断每个周期都在跑，任何时刻发现严重故障都要能立刻把系统推向安全状态。⑥则是 VCU 与外部世界的通道，缺了它，遥控、自主系统、电机控制器、BMS 谁也连不上。

## 4. 核心价值：把安全逻辑集中在一处

如果限幅、急停、失效降级散落在各个执行器和各块代码里，就会出现"三处都以为自己管安全、实际谁都没管"的局面。VCU 把它们收拢成一份逻辑：**急停最高优先级、模式互斥、故障必进安全态**三条规则只在 VCU 里写一遍，执行机构只管老实执行。这样改安全策略时只改一个地方，验证时也只需盯一个模型。

> ⚠️ 别把 VCU 写成"转发器"：把上层指令原样透传给执行器、不做仲裁和限幅，就只讲到"通信中转"，讲不到"整车控制"这一层。

## 本讲小结

| 项 | 要点 |
|----|------|
| 全称 | VCU = Vehicle Control Unit，整车控制器 |
| 定位 | 车辆的中央协调者：不直接出力，决定谁在什么时候出多少力 |
| 六项功能 | 信号采集解析 / 驾驶模式管理 / 指令仲裁限幅 / 指令输出 / 故障诊断与安全保护 / 通信与上下电管理 |
| 控制链 | 采集 → 模式判定 → 仲裁限幅 → 指令输出 → 执行机构 → 反馈回采集（诊断全程并行） |
| 分层 | VCU 管整车级决策，电机控制器管单个电机的电流环，不要混 |
| 核心价值 | 把安全逻辑集中在一处：急停最高、模式互斥、故障进安全态 |
