# 第02讲：线控执行器与安全冗余（正文约6分钟 + 练习约4分钟）

- 为什么"故障必进安全状态"要写在 VCU 里

---

## 1. 执行器盘点：谁在真正干活

VCU 只出指令，真正动手的是执行器。**每个执行器都配着自己的传感器，构成一个本地闭环。**

| 执行器 | 关键部件 | 闭环反馈量 |
|--------|---------|-----------|
| 线控转向 | 转向电机（无刷直流/永磁同步）+ 减速机构 | 方向盘转角传感器、**齿条/轮端转角传感器** |
| EHB 线控制动 | 电机泵、蓄能器、**电磁阀块** | 主缸压力、轮缸/管路压力传感器 |
| EMB 线控制动 | 每个卡钳一个电机 + 夹紧机构 | 夹紧力/电流、位移传感器 |
| 驱动 | 电机控制器 + 驱动电机 | 转速、相电流 |

为什么一定要反馈？**开环的电机只会"以为"自己转到位了。** VCU 发的是"目标转角 15°"，执行器必须靠转角传感器确认真的到了 15°，否则一切闭环控制都是空谈。

## 2. 冗余设计三招

线控没有机械备份，所以**冗余不是额外要求，是底线**。

1. **双路供电 / 双绕组电机**：执行器由两路独立电源（各自保险、各自线束）供电，电机定子里放两套独立绕组。一路断，另一路仍能输出**降额但可用**的力。
2. **双 CAN 通道**：关键报文在两条 CAN 上冗余发送，VCU 与执行器都挂两条总线，一条丢帧还有另一条；两条互为备份，还要能识别"两边数据打架"。
3. **机械限位作为最终兜底**：电子手段全失效时，靠**物理限位块**挡住转向极限、靠**失效安全弹簧/阀**保住一点残余制动力。机械兜底不聪明，但它不依赖电。

> 💡 类比：冗余像**爬山的双绳**——不是"一根绳更结实"，而是"任何一根断了，人还挂在另一根上"。机械限位就是最后那根系在岩钉上的短绳：平时用不上，用上时保命。

## 3. 失效模式与降级策略

| 失效模式 | 现象 | 降级策略 |
|---------|------|---------|
| CAN 通信丢失 | 收不到目标值或状态 | 超时判定 → 保持最后有效值不超过限定时间 → 回待机/进紧急；双通道交叉校验 |
| 传感器失效 | 转角/压力读数不动或超范围 | 换用冗余传感器、或用模型估算值降级运行，再限速 |
| 电源欠压 | 电压低于阈值，执行器出力不足 | 降额输出、禁大扭矩请求；持续欠压 → 进紧急制动 |
| 电机过温/过流 | 执行器自身保护动作 | 限功率运行，保证转向仍可用 |
| 严重故障 | 多路同时异常 | **立即进紧急模式**：扭矩清零 + 制动请求置 1 |

降级的关键词是"**分级**"：能修的先限幅，不能修的回 `Standby`，最坏才进 `Emergency`。**任何一路都不能让车同时失去转向和制动。**

## 4. 为什么安全逻辑写在 VCU，而不是各执行器里

- **单一裁决点**：执行器各自"自保"会出现互相推诿——谁兜住整车？只有 VCU 能看到全局（当前模式、遥控是否在线、自主系统是否 OK）。
- **统一口径**：故障等级与进入安全态的阈值只在一处定义，改一处全车生效，不会出现"转向 ECU 和制动 ECU 判断不一致"。
- **与状态机天然一致**：模块三的 `Emergency` 状态就是这条规则的落地——`Emergency_Stop || Vehicle_Fault` 一成立，VCU 立刻切 Emergency，输出 `Target_Torque = 0`、`Brake_Request = 1`。
- 执行器仍保留**本地保护**（过温过流），但那只是最后一道防线，**决策权在 VCU**。

> ⚠️ 别把"降级"写成"有故障就停车"。车上更常见的做法是**跛行（limp-home）**：限速限扭矩，但保留基本转向与制动，让车能安全靠边；一有故障就断电停车，反而可能在高速中造成更严重的后果。

## 本讲小结

| 概念 | 要点 |
|------|------|
| 执行器闭环 | 转向电机 + 转角传感器；EHB 泵/蓄能器 + 电磁阀块 + 压力传感器；EMB 卡钳电机 |
| 冗余三招 | 双路供电/双绕组、双 CAN、机械限位兜底 |
| 降级分级 | 限幅 → 回 `Standby` → 进 `Emergency` |
| 失效策略 | 通信丢失看超时 + 双通道校验；传感器失效换冗余/估算；欠压降额后进安全态 |
| 安全逻辑位置 | **写在 VCU**：单一裁决点、统一阈值、与状态机 `Emergency` 状态一致 |
