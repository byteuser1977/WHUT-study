## 1. 状态机是什么

> 💡 类比：状态机像**红绿灯** —— 灯任一时刻只有一种"身份"（红/绿/黄），下一步去哪只看当前是哪种灯、计时到没到，不用翻历史账。

三个问题就能定义一个状态机：**现在在哪个状态**、**什么条件才能走**、**走的时候输出什么**。车辆运行模式管理天生适合它：车不可能同时"在遥控"又"在自主"，模式之间是清楚地跳转，而不是同时生效。

## 2. 五个要素

| 要素 | 含义 | 车辆运行模式里的样子 |
|---|---|---|
| 状态 State | 系统某一时刻的身份，互斥 | Standby / Manual / Auto / Emergency |
| 转移 Transition | 状态之间带箭头的线 | Standby → Manual |
| 事件 Event | 引起评估的信号变化 | 急停开关被按下 |
| 条件 Condition | 方括号里的逻辑表达式 | `[Manual_Enable && RC_Online]` |
| 动作 Action | 进 / 停留 / 出时执行的赋值 | `VCU_Mode = 1;` |

五个要素缺一个状态机就不完整：没条件会乱跳，没动作等于白切。

关联讲次：优先级与层次结构 → 第 03 讲；条件与动作语法 → 第 02 讲；完整设计 → 第 04 讲。

## 3. 为什么不用一堆 if-else

| 角度 | if-else 堆 | 状态机 |
|---|---|---|
| 互斥性 | 靠自己小心，容易两种模式同时置真 | 结构上同时只有一个状态激活 |
| 可读性 | 嵌套越写越深 | 一张图看完 |
| 安全性 | 优先级藏在行号里，改一行就崩 | 父状态出边天然优先 |
| 可验证 | 难以穷举 | 转移可逐条列表 + 仿真核对 |

一句话记住区别：状态机能让你**指着图**说清"车为什么进了紧急模式"，if-else 只能让你翻代码一行行找。答辩时这就是亮点。

## 4. Stateflow 在哪，怎么和 Simulink 分工

在 Simulink 库浏览器里找 **`Stateflow`** → 把 **`Chart`**（状态图模块）拖进模型，**双击进 Stateflow 编辑器**（左侧是绘图工具：状态、默认转移、历史节点等；具体按钮位置**以你机器上为准**）。

分工一句话：**逻辑与模式判断放 Stateflow，数值计算放 Simulink 模块**。本设计里 `Chart` 只管"在哪个模式、输出什么"，`VCU_Mode` / `Target_Torque` / `Brake_Request` 从输出口接出去，再由 `Gain` / `Sum` 等模块做数值处理。

> ⚠️ 别一上来就画。先把四个状态名、每条转移条件在纸上列清再开 Stateflow —— 边想边画必然返工。

## 🎯 动手练习

1. 新建 Simulink 模型，存为 `vcu_mode.slx`。
2. 从库中拖入 `Stateflow` → `Chart`，双击进入编辑器。
3. 用左侧工具画 4 个状态，命名 `Standby` / `Manual` / `Auto` / `Emergency`。
4. 从空白处拉一条**默认转移**箭头指向 `Standby`。
5. 画 `Standby → Manual`，标签写 `[Manual_Enable && RC_Online]`。
6. 退出编辑器看 `Chart` 的输入 / 输出口 —— 先不接信号，只为熟悉界面。

> ✅ 你应该看到：双击 `Chart` 能看到 4 个状态框、1 条默认转移、1 条带方括号条件的转移箭头，且全图无红色报错。

## 本讲小结

| 概念 | 要点 |
|---|---|
| 状态机 | 用"当前状态 + 转移条件 + 动作"描述逻辑 |
| 五要素 | 状态 / 转移 / 事件 / 条件 / 动作 |
| 相比 if-else | 互斥性、可读性、安全性、可验证性都更好 |
| Stateflow 入口 | `Stateflow` → `Chart`，双击进编辑器 |
| 分工 | 逻辑用 Stateflow，数值计算用 Simulink 模块 |
