# 第03讲：优先级与层次结构（正文约6分钟 + 练习约4分钟）

## 你将学到
- 超状态（superstate）与排他（OR）分解
- 为什么"超状态的出边优先于子状态的出边"
- 执行顺序（Execution Order）怎么查、怎么改
- 安全设计三原则怎么落到本设计

---

## 1. 超状态与 OR 分解

把一个矩形框套在若干状态外面，外面的框就是**父状态 / 超状态（superstate）**，框内的是它的**子状态**。默认分解方式是**排他（OR）分解**：任一时刻**有且只有一个子状态激活**。

> 💡 类比：像**公司部门** —— 你在"技术部"里，同一时刻只能是"软件组"或"硬件组"其中一个；而整个部门级别的安排（如"全员开会"）能压过组里的计划。

本设计用法：父状态 `Operational` 包住 `Standby` / `Manual` / `Auto`；`Emergency` 是 `Operational` 的**兄弟状态**（与它平级），不是它的子状态。父状态同样可以有 `entry` / `during` / `exit` 动作，但本设计的输出动作都写在子状态里，父状态只负责"包住 + 一条通往急停的出边"。

## 2. 优先级由结构决定

Stateflow 规则：**激活状态的出边，层级越高越先评估** —— 超状态的出边优先级高于其内部子状态的出边。所以 `Operational → Emergency`（条件 `[Emergency_Stop || Vehicle_Fault]`）会先于 `Manual → Standby` 之类被判定。**"任何情况下急停都赢"是画出来的，不是排出来的**，这就是本设计结构化解法的全部价值。

## 3. 执行顺序（Execution Order）

同一个状态上有多条出边、条件**同时为真**时，靠**执行顺序**裁决：序号小的先判定，先满足的先走。

- **怎么查**：右键该状态，打开执行顺序 / 排序设置（不同版本入口不同，**以你机器上为准**），能看到每条出边的序号。
- **怎么改**：在同一个对话框里把箭头上下移动，或直接改序号。

本设计只在一种情况下用到：`Standby` 里若 `Manual_Enable` 与 `Auto_Enable` 同时为真，`→ Manual` 与 `→ Auto` 都成立 —— 把 **`→ Manual` 排在前**（遥控是人工直接操作，优先）。

## 4. 历史节点与安全三原则

**历史节点（History Junction）**：让父状态被重新激活时回到"上次离开时的那个子状态"，而不是默认子状态。本设计**不用** —— 急停恢复必须回 `Standby`，防止无人操控时直接回到 Manual / Auto。

| 安全原则 | 本设计落点 |
|---|---|
| 优先级 | `Operational → Emergency` 超状态出边层级最高 |
| 互斥 | Manual 与 Auto 是 OR 兄弟状态 + 执行顺序仲裁 |
| 失效安全 | 故障 / 急停必进 Emergency，输出制动请求、禁驱动力 |

> ⚠️ 别把 `Emergency` 画进 `Operational` 里当子状态 —— 急停条件就变成"只在非紧急模式下评估"，逻辑自锁，急停永远进不去。

## 🎯 动手练习

1. 用矩形工具画一个大状态框，改名 `Operational`。
2. 把 `Standby` / `Manual` / `Auto` 三个状态框**拖进** `Operational`（必须真的落在框内）。
3. 把 `Emergency` 画在框外，作为它的兄弟状态。
4. 从 `Operational` 的**框边**拉出转移指向 `Emergency`，条件写 `[Emergency_Stop || Vehicle_Fault]`。
5. 右键 `Standby` 打开执行顺序设置，确认 `→ Manual` 的序号小于 `→ Auto`，不是就调整。
6. 拖一个 `History Junction` 进 `Operational` 看一眼（本设计不用，认识即可），再删掉。

> ✅ 你应该看到：`Operational` 是一个大框、三个子状态在其中，`Emergency` 在同一层级的框外；转移箭头从 `Operational` 的框边出发，而不是从某个子状态出发。

## 本讲小结

| 概念 | 要点 |
|---|---|
| 超状态 | 包住子状态的父状态，本设计为 `Operational` |
| OR 分解 | 任一时刻只有一个子状态激活（模式互斥的结构保证） |
| 出边优先级 | 超状态出边 > 子状态出边 → 急停最高优先级 |
| 执行顺序 | 同一状态多条出边同时为真靠它裁决，可手动排序 |
| 历史节点 | 本设计不用，急停恢复必须固定回 `Standby` |
