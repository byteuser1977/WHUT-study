## 1. 进程 vs 程序

| 概念 | 说明 |
|------|------|
| **程序** | 存在磁盘上的可执行文件（静态） |
| **进程** | 正在运行的程序（动态），有 PID（进程号） |

## 2. 查看进程

```bash
# 查看当前终端的进程
ps

# 查看所有进程（最常用）
ps aux

# 按关键词查进程（推荐 pgrep：直接给出 PID，且不会被自己干扰）
pgrep -a nginx

# 用 ps 过滤时要注意这个经典坑：grep 自己也会出现在结果里
ps aux | grep -v grep | grep nginx

# 查看特定用户的进程（$USER 就是当前用户名；换成任意已存在的用户名也行）
ps -u "$USER"
```

`ps aux` 输出示例：
```
USER         PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root           1  0.0  0.0 167284 13068 ?        Ss   21:03   0:02 /sbin/init
bit         1234  0.0  0.0  11424  3220 pts/0    Ss+  10:00   0:00 -bash
bit         5678  1.2  0.5  98765 23456 pts/0    Sl   10:05   0:15 python3 app.py
```

| 列 | 含义 |
|---|------|
| USER | 进程属于哪个用户 |
| PID | 进程号（唯一标识） |
| %CPU / %MEM | CPU / 内存占用率 |
| VSZ | 虚拟内存大小（KB） |
| RSS | 实际占用的物理内存（KB）——排查内存问题必看 |
| TTY | 绑定的终端（`?` 表示没有终端，通常是后台/系统进程） |
| STAT | 进程状态 |
| START | 启动时间 |
| TIME | 累计占用 CPU 的时间 |
| COMMAND | 运行的命令 |

**STAT 常见字母**：

| 字母 | 含义 |
|------|------|
| `R` | 正在运行 |
| `S` | 睡眠，等待事件（最常见） |
| `D` | 不可中断睡眠（多在等磁盘 I/O，杀不掉） |
| `T` | 已停止（被挂起） |
| `Z` | 僵尸进程（已结束，但父进程没回收） |
| `I` | 空闲的内核线程 |

后缀：`s` = 会话首领，`l` = 多线程，`+` = 前台进程组，`<` = 高优先级。

> 💡 `Z`（僵尸进程）的成因：子进程已退出，但父进程还没读取它的退出码。偶发几个不影响系统，长期大量堆积说明父进程写得有问题；`kill` 杀不掉僵尸，要处理它的父进程。

## 3. 实时监控：top / htop

```bash
top       # 系统自带的实时任务管理器
htop      # 更好看的版本（需要安装：sudo apt install htop）
```

`top` 常用按键：
- `P`：按 CPU 排序
- `M`：按内存排序
- `q`：退出

`htop` 操作：
- 按 `F9`：发送信号（终止进程）
- 按 `F6`：按 CPU/内存排序
- 按 `F10` 或 `q`：退出

> 💡 `htop` 比 `top` 好用 10 倍：彩色界面、鼠标支持、直观操作。

## 4. 终止进程

```bash
# 按 PID 终止
kill 5678

# 强制终止（SIGKILL）
kill -9 5678

# 按名称终止
killall nginx

# 按名称模糊匹配终止
pkill python3

# 列出全部信号
kill -l
```

| 信号 | 编号 | 含义 |
|------|------|------|
| SIGTERM | 15 | 温和终止（默认），程序可以做清理 |
| SIGKILL | 9 | 强制杀死，立即停止，不做清理 |
| SIGINT | 2 | 中断（你在终端按 `Ctrl + C` 发的就是这个） |

### 🎯 优先用 kill PID，杀不掉才用 kill -9

`kill PID` 相当于跟程序说"请收拾一下就退出"，程序有机会保存数据、关闭文件；`kill -9` 是直接拔电，可能丢数据、留下锁文件。

## 5. 后台运行

```bash
# 在命令末尾加 & 放入后台
python3 app.py &

# 不挂断运行（关终端也不会停）
nohup python3 app.py &

# 更推荐：显式指定日志文件（nohup 默认写到当前目录的 nohup.out）
nohup python3 app.py > app.log 2>&1 &

# 查看后台任务
jobs

# 把后台任务调回前台
fg %1
```

> 💡 `nohup` = "no hang up"（不挂断）。服务器上跑长任务必备。

> 💡 后台跑起来的程序怎么停？先 `pgrep -f app.py` 拿到 PID，再 `kill 那个PID`。

## 🎯 课后练习（约5分钟）

下面这些命令要在**同一个终端窗口**里按顺序执行（`kill %1` 依赖当前窗口的后台任务列表）。

```bash
# 1. 查看所有进程
ps aux | head -20

# 2. 用 top 看看系统状态（按 q 退出）
top

# 3. 用 htop 看看（按 q 退出）；没装先装：sudo apt install htop
htop

# 4. 查找 bash 进程
ps aux | grep bash

# 5. 在后台运行 sleep 命令
sleep 300 &
jobs

# 6. 终止它
kill %1
```

> ✅ 你应该看到（类似）：
> ```
> USER         PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
> root           1  0.0  0.0 167284 13068 ?        Ss   21:03   0:02 /sbin/init
> ...
> [1] 12345
> [1]+  Running                 sleep 300 &
> [1]+  Terminated              sleep 300
> ```

## 本讲小结

| 命令 | 用途 |
|------|------|
| `ps aux` | 查看所有进程 |
| `pgrep -a 关键词` | 按关键词找进程（不会被 grep 自己干扰） |
| `top`/`htop` | 实时监控 |
| `kill PID` | 终止进程（优先用） |
| `kill -9 PID` | ⚠️ 强制终止（可能丢数据，最后手段） |
| `killall name` | 按名称终止 |
| `nohup cmd > app.log 2>&1 &` | 后台不挂断运行并留日志 |
