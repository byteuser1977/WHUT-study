## 1. ROS 2 核心概念

> ROS 2 是什么、节点/话题/服务这些概念，见 [perception/ros2/01-ros2是什么.md](../../perception/ros2/01-ros2是什么.md)。

### 速查表

| 术语 | 一句话解释 |
|------|-----------|
| 节点 Node | 一个独立运行的程序单元，干一件事 |
| 话题 Topic | 节点之间的异步消息通道（单向广播） |
| 发布 Publish | 往话题上发消息 |
| 订阅 Subscribe | 从话题上收消息 |
| 消息 Message | 话题中传输的数据结构（如 Twist、Pose） |
| 回调 Callback | 收到消息后触发的处理函数 |
| 定时器 Timer | 按固定频率触发回调 |
| 时间戳 Timestamp | 消息附带的时间信息，用于对齐 |
| 生命周期节点 Lifecycle | 可管理状态的节点（未激活→激活→关闭） |

> ⚠️ 常见坑：话题名有全局（`/cmd_vel`）和相对（`cmd_vel`）之分，混用会导致"明明发布了但收不到"。

## 2. SSH 远程连接

> SSH 基础见 [linux/09-网络基础.md](../../linux/09-网络基础.md)。

SSH（Secure Shell）是加密的远程终端协议，用于从一台电脑操控另一台。

### 两台电脑网线直连操作流程

```bash
# 电脑 A（控制端）设置 IP
sudo ip addr add 192.168.1.1/24 dev eth0

# 电脑 B（被控端）设置 IP
sudo ip addr add 192.168.1.2/24 dev eth0

# 电脑 A 连接电脑 B
ssh user@192.168.1.2

# 验证连通性
ping 192.168.1.2
```

**关键步骤：**
1. 两台电脑用网线物理连接
2. 手动配置同一网段的 IP（如 192.168.1.x/24）
3. 确保防火墙允许 SSH（端口 22）
4. 用 `ssh user@ip` 连接

## 3. 双系统 vs 虚拟机

| 对比项 | 双系统 | 虚拟机 |
|--------|--------|--------|
| 性能 | 原生性能，无损耗 | 有虚拟化开销，GPU 受限 |
| 硬件访问 | 直接访问所有硬件 | 部分硬件受限（如 USB 设备） |
| 切换方式 | 重启切换 | 随时切换，可同时运行 |
| 磁盘占用 | 需要独立分区 | 单个文件即可 |
| 适用场景 | ROS 2 开发、传感器驱动、实车部署 | 学习 Linux、轻量级开发、Windows 依赖 |
| 安装难度 | 需要分区，有风险 | 一键安装，风险低 |

**团队建议：**
- 日常学习用虚拟机（方便、安全）
- 实际开发和实车部署用双系统（性能和硬件访问）
- 传感器驱动（如 USB 摄像头、LiDAR）必须双系统或原生 Linux

## 4. Git 版本控制

> 完整教程见 [perception/git/01-git是什么与三大区域.md](../../perception/git/01-git是什么与三大区域.md)。

### Git 三大区域

| 区域 | 作用 | 对应命令 |
|------|------|----------|
| 工作区 Working Directory | 你编辑的文件 | 直接编辑 |
| 暂存区 Staging Area | 准备提交的快照 | `git add` |
| 仓库 Repository | 历史版本记录 | `git commit` |

### Git vs GitHub

| 对比项 | Git | GitHub |
|--------|-----|--------|
| 本质 | 本地版本控制工具 | 云端代码托管平台 |
| 是否需要网络 | 不需要 | 需要 |
| 协作方式 | 手动传递补丁文件 | Pull Request / Fork |
| 核心功能 | 版本管理、分支、合并 | + Issue、Actions、Pages |

**团队协作流程：**
1. `git clone` 从 GitHub 拉取仓库
2. `git checkout -b feature/xxx` 创建功能分支
3. 开发完成后 `git push` 推送到 GitHub
4. 发起 Pull Request，队友 Review 后合并
