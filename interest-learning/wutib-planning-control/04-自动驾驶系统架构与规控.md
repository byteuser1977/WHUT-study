## 1. Frenet 坐标系

### 什么是 Frenet 坐标系

Frenet 坐标系是一种**沿路径建立的局部坐标系**，用两个轴描述位置：

- **s 轴**：沿路径方向的弧长（纵向距离）
- **d 轴**：垂直于路径方向的横向偏移（左正右负）

```text
        d (横向)
        ↑
        │   ● 车辆位置 (s, d)
        │  /
        │ /
        └──────────→ s (沿路径弧长)
       路径起点
```

> 💡 类比：想象一条弯曲的高速公路。GPS 给你经纬度（很难判断你在路的哪一侧），但 Frenet 坐标直接告诉你"沿路走了 50 米，偏左 1.2 米"——这对控制来说直观得多。

### Frenet 在规控中的应用

| 应用场景 | Frenet 的作用 |
|----------|---------------|
| 转弯降速 | 根据路径曲率 κ 判断是否需要减速：κ 越大 → 速度越低 |
| 道路偏离距离 | d 轴值直接就是偏离中心线的距离，无需坐标变换 |
| 收束可行路段 | 在 Frenet 下将道路简化为 s-d 平面的矩形区域，便于筛选 |
| 输出可用路径 | 规划结果用 (s, d) 表示，再转换回笛卡尔坐标供控制执行 |

## 2. DP 代价函数设计

DP（Dynamic Programming，动态规划）用于在离散化的路径点中寻找最优路径。

### 需要考虑的代价因素

| 代价项 | 说明 | 权重方向 |
|--------|------|----------|
| 路径长度 | 路径越短越好 | 越小越好 |
| 曲率/平滑度 | 转弯越急代价越高 | 越小越好 |
| 障碍物距离 | 离障碍物越近代价越高 | 越大越好（或倒数） |
| 路面平整度 | 颠簸路段代价高 | 越小越好 |
| 车道保持 | 偏离车道中心线代价高 | 越小越好 |
| 目标点对齐 | 终点方向与目标方向的偏差 | 越小越好 |

### 代价函数示例

```text
Cost = w1 × 路径长度
     + w2 × 曲率²
     + w3 × (1 / 到最近障碍物距离)
     + w4 × 路面不平度
```

其中 w1~w4 为权重，需要根据实际场景调参。

## 3. 传感器数据在规控中的角色

### 规划层需要的传感器数据

| 数据 | 来源 | 用途 |
|------|------|------|
| GPS/INS 位姿 | GNSS + 惯导融合 | 确定自车全局位置 |
| 点云/图像 | LiDAR / Camera | 障碍物检测、可通行区域分割 |
| 高精地图 | 预采集路径文件 | 路径参考、曲率信息 |
| 地面平整度 | 激光/视觉 | 代价函数中的路面质量项 |

### 控制层需要的传感器数据

| 数据 | 来源 | 用途 |
|------|------|------|
| 车速 | 编码器 / 轮速传感器 | Stanley 算法的速度输入 |
| 横摆角速度 | IMU | 阻尼项计算 |
| 航向角 | IMU + GPS 融合 | 航向误差计算 |
| 转向角 | 转角传感器 | 闭环反馈、安全限幅 |

## 4. 路径规划的起点

在规划时，车辆被**收束为一个点**——即**前轴中心**。

原因：
- Stanley 控制器的横向误差是基于前轴中心计算的
- 前轴是转向执行点，以此为原点建模最自然
- 后轴中心也可以，但需要额外考虑轴距补偿

## 5. 信号延迟的工程应对

当传感器信号出现大幅延迟时（如 GPS 滞后），会导致：
- 定位滞后：车已前进 2 米，但系统认为还在原地
- 规划错误：基于错误位置生成的路径完全不可用
- 控制振荡：控制器在"纠正"一个不存在的误差

### 解决方案

| 方法 | 原理 | 适用场景 |
|------|------|----------|
| 时间戳对齐 | 所有传感器数据打时间戳，用最近的有效数据 | 通用 |
| 状态预测 | 用 IMU 积分预测当前位姿，补偿 GPS 延迟 | 高速场景 |
| 卡尔曼滤波 | 融合多传感器，用模型预测+观测修正 | 标准方案 |
| 延迟检测与降级 | 检测到延迟超过阈值时切换到安全模式 | 安全关键系统 |
| 通信链路优化 | 有线替代无线、降低采样频率 | 硬件层面 |

> ⚠️ 工程经验：IMU 是对抗 GPS 延迟的第一道防线。即使 GPS 丢信号 1~2 秒，IMU 积分仍能提供可用的位姿估计。

## 6. 完全自主驾驶

### A3 模式（跟随预设路径）

- 路径提前采集并存储
- 规划器只需做局部避障调整
- 控制器跟踪预设路径
- 难度较低，适合比赛初级阶段

### A5 模式（完全自主驾驶）

- 需要**自主感知**环境（障碍物、道路边界）
- 需要**自主规划**路径（全局 + 局部）
- 需要**自主决策**（避让、超车、停车）

### 常见全局规划算法

| 算法 | 特点 | 适用场景 |
|------|------|----------|
| A* | 启发式搜索，保证最优 | 离散栅格地图 |
| Dijkstra | 无启发式，暴力搜索 | 小规模地图 |
| RRT | 随机采样，适合高维空间 | 复杂环境 |
| PRM | 概率路线图，预计算 | 多次查询场景 |
| Lattice | 状态格子规划，考虑动力学 | 结构化道路 |

> 完全自主驾驶的难点不在单一算法，而在**系统集成**——感知延迟、规划刷新率、控制执行之间的时间对齐。

|------|------|
