## 1. 先想一个问题：机器人为什么不能"裸写代码"

假设你要给一辆巴哈赛车写感知程序，需求很简单：读摄像头 → 识别可行驶区域 → 把方向结果发给底盘。最朴素的做法是写一个大 `main.cpp`：开摄像头、处理图像、算方向、调串口发指令。写个实验室 demo 完全够用，但放到真车上，四个问题躲不开：

1. **硬件会换**。今天用 USB 摄像头，明天换成工业相机，图像接口全变了，你得回头改主程序。
2. **一个人写不完**。感知、定位、控制、通信通常多人分工。所有人改同一个 `main.cpp`，冲突不断。
3. **调试无从下手**。程序卡住了，是摄像头没出图？算法太慢？还是串口堵了？没有任何"分段观察"的入口。
4. **模块死绑**。算方向的那段代码直接调了串口库，你想在电脑上跑仿真，做不到。

ROS 2 存在的理由就是解决这四件事：**把程序拆开、把数据接口标准化、把模块之间的通信交给框架去管。**

> 💡 类比：裸写代码像"自己盖房子，水电木工全一个人干，还得自己发明电线的插头标准"；ROS 2 像"一套带标准插座的房子 + 物业"。插座（接口）是统一规格的，你只管把冰箱插上去；物业（中间件）负责把电送到每个房间，你不需要知道电线走哪堵墙。

> ⚠️ 常见坑：ROS 2 **不是**操作系统，也不是编程语言，更不是图像处理库。它是跑在 Ubuntu 之上的一层**通信框架 + 配套工具**。它是胶水，不替代 OpenCV、不替代 Python——该用的库照用。

## 2. 中间件（Middleware）到底是什么

**中间件（middleware）**：夹在操作系统和你的应用程序之间的一层软件，专门负责"让不同的程序互相传数据"，这样每个程序都不用自己写一遍网络通信。

ROS 2 底层的中间件叫 **DDS**（Data Distribution Service，数据分发服务），是一个工业界已经用了很多年的通信标准。你在代码里写"我要广播这个数据"，DDS 负责把它送到所有需要的人手里——不管这两段程序是在同一台电脑的两个进程里，还是在一辆车的两块板子上。

| 对比项 | 裸写代码 | 用 ROS 2 |
|--------|----------|----------|
| 模块间通信 | 每人自己写 socket/串口 | 框架统一提供，一处配置处处可用 |
| 换硬件 | 改主程序 | 换一个节点即可，其他节点不动 |
| 多人协作 | 抢同一个文件 | 各写各的节点，接口对齐就行 |
| 调试 | 只能看日志 | 命令行随时偷看数据流（第03讲） |
| 仿真/实车切换 | 基本要重写 | 同一套节点，换个数据源即可 |

## 3. 节点（Node）：机器人的"器官"

**节点（Node）**：一个独立运行的小程序，只干一件事。ROS 2 里，一个可执行文件可以启动一个或多个节点，节点是它的运行实例。

> 💡 类比：节点就像公司里的岗位。有人只负责拍照片（相机节点），有人只负责算路线（感知节点），有人只负责踩油门（控制节点）。岗位之间**不互相指挥**，而是把结果贴到公告栏上，谁需要谁自己去取。所以负责感知的同学不用等控制同学写完代码，接口定好就能各自开工。

一辆巴哈车的节点划分大致长这样：

| 节点 | 干什么 | 输入 | 输出 |
|------|--------|------|------|
| `camera_node` | 驱动相机出图 | 硬件 | 图像话题 |
| `perception_node` | 找可行驶区域/障碍物 | 图像话题 | 区域/障碍物话题 |
| `control_node` | 算油门刹车方向 | 感知结果 | 底盘指令 |
| `can_node` | 和底盘 ECU 对话 | 底盘指令 | CAN 报文 |

每个节点都能单独启动、单独重启、单独看它的输入输出。**排查问题时，你可以先只让相机节点跑起来，确认有图，再启动感知节点**——这就是"分段观察"。

## 4. ROS 1 和 ROS 2：为什么现在必须学 ROS 2

ROS 1 从 2007 年开始流行，但它的设计缺陷在真车上很致命。ROS 2 是重写版，不是升级版。

| 维度 | ROS 1 | ROS 2 |
|------|-------|-------|
| 通信机制 | 自研 TCP/UDP + 一个中心节点 `roscore` | 基于 DDS，无中心节点 |
| 单点故障 | `roscore` 挂了全系统瘫痪 | 去中心化，没有单点 |
| 实时性 | 差，不适合控制回路 | 支持实时，可做底盘控制 |
| 多机器人 | 很麻烦 | 原生支持（同域内自动发现） |
| 平台支持 | 主要 Linux | Linux / Windows / macOS / 嵌入式 RTOS |
| 支持状态 | ROS 1 Noetic 已停止维护 | ROS 2 是官方唯一主线 |

> ⚠️ 常见坑：ROS 1 的 `roscore`、`rostopic`、`catkin_make` 在 ROS 2 里**全部不存在或改名了**。你在网上搜教程时，看到 `rosrun`、`rostopic`、`catkin` 就直接关掉——那是 ROS 1 的资料，照抄会一头雾水。

## 5. 装好它：安装 ROS 2 Humble

**基准环境**：Ubuntu 22.04（WSL2 也可以）+ ROS 2 Humble Hawksbill + Python 3.10。Humble 是 Ubuntu 22.04 的官方长期支持（LTS）版本，支持到 2027 年 5 月，车队用的就是它。

```bash
# 1. 装依赖并添加 ROS 2 的软件源
sudo apt update && sudo apt install -y curl gnupg lsb-release
sudo curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key \
  -o /usr/share/keyrings/ros-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] http://packages.ros.org/ros2/ubuntu $(. /etc/os-release && echo $UBUNTU_CODENAME) main" \
  | sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null

# 2. 安装桌面版（含 rviz、rqt 等图形工具）
sudo apt update
sudo apt install -y ros-humble-desktop python3-colcon-common-extensions python3-rosdep
```

**source 环境**：ROS 2 的命令（`ros2`）不是装完就能直接用，必须先把它的环境变量"加载"进当前终端，这叫 **source**。

```bash
# 只在当前终端生效
source /opt/ros/humble/setup.bash

# 让每个新终端都自动生效（推荐）
echo "source /opt/ros/humble/setup.bash" >> ~/.bashrc

# 验证
printenv ROS_DISTRO        # 应输出：humble
ros2 --version             # 部分安装方式下该参数未实现，报 unrecognized arguments 属正常
```

> 💡 类比：source 就像"把工具箱挂到身上"。装了 ROS 2 只等于工具箱放在仓库里，不 source 的话你在终端敲 `ros2` 会提示 command not found——是没挂上，不是没装好。

> ⚠️ 常见坑：**每开一个新终端都要重新 source**（除非写进了 `~/.bashrc`）。另外，如果你以后要 source 自己编译的工作空间，顺序是先 `/opt/ros/humble/setup.bash`，再你自己的 `install/setup.bash`，反过来会被覆盖。

## 🎯 课后练习（约7分钟）

```bash
# 1. 确认 ROS 2 已就位
source /opt/ros/humble/setup.bash
printenv ROS_DISTRO

# 2. 装一个小乌龟仿真器，后面五讲都拿它当实验台
sudo apt install -y ros-humble-turtlesim

# 3. 启动乌龟节点（这个窗口会占住，先别关）
ros2 run turtlesim turtlesim_node
```

再开**第二个终端**，看看系统里现在有哪些节点：

```bash
ros2 node list
```

> ✅ 你应该看到：
> ```
> humble
> /turtlesim
> ```
> 第一个终端会弹出一个蓝色小乌龟窗口，并打印类似
> `[INFO] [turtlesim_node-1]: process started with pid [12345]`。

试着按 `Ctrl+C` 关掉乌龟节点，再回第二个终端执行 `ros2 node list`——你会发现 `/turtlesim` 消失了。**节点是活的东西，启动才存在，关掉就没了。**

## 本讲小结

| 概念 | 要点 |
|------|------|
| 中间件 | 夹在操作系统和应用程序之间、负责通信的一层软件；ROS 2 用的是 DDS |
| 节点 Node | 一个独立运行、只干一件事的小程序，可单独启停和观察 |
| 为什么拆节点 | 换硬件少改代码、多人并行开发、出问题能分段定位 |
| ROS 1 vs ROS 2 | ROS 2 基于 DDS 去中心化、支持实时、跨平台，是唯一主线 |
| 环境 | Ubuntu 22.04 + ROS 2 Humble；用 `source` 加载，`printenv ROS_DISTRO` 验证 |
| 本讲命令 | `ros2 run`（启动节点）、`ros2 node list`（看有哪些节点） |
