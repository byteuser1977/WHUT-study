## 1. 图像 = 一张巨大的数字表格

打开一张照片看，你看到的是人、车、赛道。但电脑看不见"人"，它只看见数字。

一张图片到了电脑内部，会被表示成一堆**数字**，按行列排好，像一张 Excel 表格：

```
列 →  0    1    2    3  ...
行
 0   [12] [15] [18] [20]
 1   [30] [33] [35] [40]
 2   [55] [57] [60] [62]
```

表格里的每一个格子叫一个**像素（pixel，picture element 的缩写）**，格子里的数字就是这块小方块的颜色/亮度值。

- 一个像素 = 图上最小的一个点
- 一张 640×480 的图 = 640×480 = **307200 个像素**，也就是 30 多万个格子

> 💡 类比：图片就像一张**十字绣图纸**。远看是一只猫，近看是一格一格的线。每个格子里写的是"这一格用什么颜色的线"——电脑里的"颜色编号"就是数字。

在 Python 里，我们用来装这种"数字表格"的工具叫 **NumPy 数组（numpy array）**。OpenCV 读进来的图片，本质就是一个 NumPy 数组。这句话极其重要：**所以你学的那点 NumPy 知识，全部可以直接拿来处理图片。**

## 2. 像素颜色是怎么用数字表示的：BGR 三通道

黑白（灰度）图的每个像素只要 1 个数字就够了：0 = 纯黑，255 = 纯白，中间是各种灰。

但**彩色**图不行，一个数字表示不出"红色"还是"蓝色"。所以彩色图每个像素用 **3 个数字**，分别记录三种原色的强度：

| 通道 | 含义 | 值越大 |
|------|------|--------|
| **B** | Blue 蓝 | 越蓝 |
| **G** | Green 绿 | 越绿 |
| **R** | Red 红 | 越红 |

⚠️ 注意顺序：OpenCV 用的是 **BGR**，不是大家在网页/画图软件里见惯的 RGB。**同一个像素 `[0, 0, 255]`：按 BGR 读 = 纯红，按 RGB 读 = 纯蓝。** 新手画出来的红色变成蓝色，99% 是这个原因。

> 💡 类比：BGR 就像"调料瓶摆错了顺序"。同样写着「糖、盐、辣椒」，厨师 A 的瓶子从左到右是糖盐辣，厨师 B 的是辣盐糖——配方字面一样，做出来完全是两道菜。OpenCV 是那个把辣椒放最左边的厨师。

> ⚠️ 常见坑：用 `cv2.imwrite` 保存、用 `cv2.imshow` 显示都没问题（OpenCV 自己知道是 BGR）。但如果你把图片交给 **matplotlib（`plt.imshow`）或 PIL** 显示，它们默认是 RGB，就会出现"红蓝互换"的鬼畜图。解决办法一行：
> ```python
> plt.imshow(cv2.cvtColor(img, cv2.COLOR_BGR2RGB))
> ```

## 3. 重头戏：shape `(480, 640, 3)` 三个数字分别是什么

**自测题**：一张彩色图片的 NumPy 数组 `shape` 为 `(480, 640, 3)`，这三个数字分别代表图片的什么属性？

答案是：

| 位置 | 数值 | 含义 | 通俗说法 | 另一个名字 |
|------|------|------|----------|-----------|
| 第 1 个 | 480 | **高度（height）**，即**行数（rows）** | 图片竖直方向有多少个像素 | 480 行 |
| 第 2 个 | 640 | **宽度（width）**，即**列数（columns）** | 图片水平方向有多少个像素 | 640 列 |
| 第 3 个 | 3 | **通道数（channels）** | 每个像素用 3 个数字描述（B、G、R） | 3 通道 |

一句话记忆：**「高、宽、层」，即"先数行、再数列、最后数每个格子有几层"。**

```
img.shape = (480, 640, 3)
             │     │    └── 每个像素 3 个数字 → 蓝色、绿色、红色
             │     └─────── 宽度 width = 640 列
             └───────────── 高度 height = 480 行
```

验证一下（三种写法输出完全一样）：

```python
import cv2

img = cv2.imread("test.jpg")
print(img.shape)          # (480, 640, 3)
print(img.shape[0])       # 480  → 高度（行数）
print(img.shape[1])       # 640  → 宽度（列数）
print(img.shape[2])       # 3    → 通道数
print(img.size)           # 921600 = 480*640*3，总元素个数
```

> ✅ 你应该看到：
> ```
> (480, 640, 3)
> 480
> 640
> 3
> 921600
> ```

> 💡 类比：把图片想成一本**480 行 × 640 列**的方格本。你会说"这本书有 480 行"（高），不会说"有 480 列"。`shape` 就是按"行数在前、列数在后"来报的，和矩阵的行列顺序一致。

> ⚠️ 常见坑一：**顺序反了**。很多人记成 `(宽, 高, 3)`，于是把 480 说成宽度。记住 OpenCV 的世界里是 **rows 在前**（第 02 讲的切片语法 `img[行, 列]` 也是这个顺序，前后呼应）。
>
> ⚠️ 常见坑二：**"3" 不是"3 倍清晰度"也不是"三通道压缩"**，它就是"每个像素有 3 个分量"。

## 4. dtype：为什么最大值是 255

打印数组时你会看到 `dtype=uint8`。`dtype` 是 **data type（数据类型）** 的意思。

`uint8` 拆开看：`u` = unsigned（无符号，不能是负数），`int` = 整数，`8` = 占 **8 位（bit）**。

8 位二进制能表示 0~255 共 256 个数：

```
8 位二进制最大值 = 11111111 = 1+2+4+8+16+32+64+128 = 255
```

所以每个通道的取值范围天然就是 **0~255**：

| 值 | 含义（以灰度为例） |
|----|-------------------|
| 0 | 纯黑 |
| 64 | 暗灰 |
| 128 | 中灰 |
| 255 | 纯白 |

> 💡 类比：`uint8` 就是一个**只能写 0~255 的老式计算器**，多一个键都没有。它省内存（1 个像素 3 个字节），但也意味着**算出来的数超过 255 会"绕回去"**。

⚠️ **这是本章最大的坑**：uint8 做加减法会溢出（overflow）。
- 200 + 100 = 44（300 减 256 绕回）
- 10 - 20 = 246

所以调亮度不要直接 `img + 50`，要用 OpenCV 提供的带截断（saturate）功能的函数：

```python
bright = cv2.add(img, 50)     # ✅ 超过 255 就停在 255，不会绕回去变黑
bad    = img + 50             # ❌ 会溢出，亮的变成暗的
```

> ⚠️ 如果确实要算，可以先把类型换成更大的：`img.astype("float32")`，算完再 `np.clip(x, 0, 255).astype("uint8")` 转回来。

## 5. 灰度图为什么没有第三维

灰度图每个像素只需要 **1 个数字**（0~255 的灰度值），不需要"3 个分量"，所以它的 `shape` 只有两维：

| 图片类型 | shape | 元素个数 | 说明 |
|----------|-------|----------|------|
| 彩色图 | `(480, 640, 3)` | 480×640×3 = 921600 | 每像素 3 个数（BGR） |
| 灰度图 | `(480, 640)` | 480×640 = 307200 | 每像素 1 个数（亮度） |
| 二值图 | `(480, 640)` | 480×640 | 每像素 0 或 255，仍是灰度图的一种 |

**一句话回答"为什么没有第三维"：因为灰度图每个像素只有 1 个数值，而第三维的长度就是"每个像素有几个数值"。** 只有 1 个值的时候，这一维就没有存在的必要了，NumPy 会直接省掉。

> 💡 类比：黑白照片的底片只需要"多黑"，不需要配色表；彩色照片才需要三原色配方。配方只有一项时，那一栏就取消了。

判断方法：`len(img.shape) == 3` 是彩色，`== 2` 是灰度。也可以用 `img.ndim`。

## 6. 彩色转灰度：`cv2.cvtColor`

```python
import cv2

img  = cv2.imread("test.jpg")                      # 彩色读入，shape (480, 640, 3)
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)       # 转换
print(img.shape, gray.shape)                       # (480, 640, 3) (480, 640)
```

> ✅ 你应该看到：
> ```
> (480, 640, 3) (480, 640)
> ```

`cv2.cvtColor` = **color convert（颜色空间转换）**，第二个参数告诉它"从什么转到什么"：

| 参数 | 含义 |
|------|------|
| `cv2.COLOR_BGR2GRAY` | 彩色 → 灰度（最常用） |
| `cv2.COLOR_BGR2RGB` | BGR → RGB（喂给 matplotlib/PIL 时用） |
| `cv2.COLOR_BGR2HSV` | BGR → HSV（第 03 大类讲颜色阈值时用） |

**为什么要把彩色转灰度？** ① 数据量减到 1/3，算得快；② 边缘检测、形态学等算法本来就只需要亮度信息；③ 排除颜色干扰，抗光照变化更强。

⚠️ 第一个参数必须是彩色图（3 通道），传灰度图进去会直接报错：
```
OpenCV(4.x.x) error: (-215:Assertion failed) !_src.empty() in function 'cvtColor'
```
（`_src.empty()` 多半是**文件路径不对导致图片没读进来**；如果路径对，就是**通道数不匹配**。）

# ex01.py
import cv2
import numpy as np

img = cv2.imread("test.jpg")
print("1) shape         =", img.shape)          # 期望 (480, 640, 3)
print("2) 高度(行)      =", img.shape[0])       # 期望 480

print("5) dtype         =", img.dtype)          # 期望 uint8
print("6) 像素总数      =", img.size)           # 期望 921600

# 取正中间那个像素，看它的 BGR 值
h, w, _ = img.shape
print("7) 中心像素 BGR  =", img[h // 2, w // 2])

# 转灰度
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
print("8) 灰度 shape    =", gray.shape)         # 期望 (480, 640)

# 演示 uint8 溢出（注意：要传数组，cv2.add 不接受裸标量）
a = np.array([[200]], dtype="uint8")           # 一个只有 200 的小数组
print("9) 200+100       =", (a + 100).ravel()[0])        # 期望 44（溢出！）
print("10) cv2.add 后   =", cv2.add(a, 100).ravel()[0])  # 期望 255（截断）
```

> ⚠️ 第 9 行 NumPy 还会顺带打印一句 `RuntimeWarning: overflow encountered in scalar add`——这就是溢出的"报警声"。看到它，就说明你该用 `cv2.add` 了。

> ✅ 你应该看到（前 4 行涂红区域内的像素是 `[0 0 255]`，中心行是第 240 行，属于下半部分灰区）：
> ```
> 1) shape         = (480, 640, 3)
> 2) 高度(行)      = 480
> 3) 宽度(列)      = 640
> 4) 通道数        = 3
> 5) dtype         = uint8
> 6) 像素总数      = 921600
> 7) 中心像素 BGR  = [ 61  61 125]
> 8) 灰度 shape    = (480, 640)
> 9) 200+100       = 44
> 10) cv2.add 后   = 255
> ```
>
> ⚠️ 第 7 行老实说：灰区本来涂的是 `(80, 80, 80)`，但**JPEG 是有损压缩**，第 240 行紧挨着红色区域，压缩时颜色会"渗"过来，所以实测值偏红（`R=125`）。不同机器上这个数字会略有出入——**只要三个数接近就正常，别死记具体数值**。想得到完全精确的像素值，把 `cv2.imwrite("test.jpg", ...)` 改成 `.png`（无损格式）。

## 本讲小结

| 概念 | 要点 |
|------|------|
| 像素 pixel | 图片的最小单位，一个格子；图片 = 一大堆数字排成的表格 |
| NumPy 数组 | OpenCV 里图片的载体，所以 NumPy 切片/运算都能直接用 |
| BGR 三通道 | OpenCV 顺序是蓝绿红（不是 RGB）；`[0,0,255]` 是**红色** |
| `shape=(480,640,3)` | **480 = 高度/行数，640 = 宽度/列数，3 = BGR 三通道（本讲核心）** |
| `dtype=uint8` | 8 位无符号整数，每通道 0~255；直接加减会溢出，用 `cv2.add` |
| 灰度图 | `shape=(480,640)`，每像素 1 个数，**所以没有第三维** |
| `cv2.cvtColor` | 颜色空间转换；`COLOR_BGR2GRAY` 转灰度，`COLOR_BGR2RGB` 给 matplotlib |
