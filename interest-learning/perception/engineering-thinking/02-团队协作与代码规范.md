## 你将学到

## 1. 好代码的唯一标准：别人看得懂

> 💡 类比：厨房。自己一个人住，调料随便扔也行；但只要有人跟你一起做饭，就必须"用完放回原位 + 贴上标签"。代码里"看得懂"就是给队友贴标签——他不用问你就能找到酱油。

代码是写给人看的，顺便让机器能跑。判断标准很简单：**三个月后的你自己，能不能在 30 秒内说出这段代码在干什么。**

## 2. 命名规范

| 对象 | 规范 | 正例 | 反例 |
|------|------|------|------|
| 变量 / 函数 | 小写 + 下划线（snake_case） | `lane_left_x`、`def find_lane()` | `a1`、`def f()`、`LaneLeft` |
| 类名 | 大驼峰（CamelCase） | `CameraPublisher`、`LaneDetector` | `camera_publisher` |
| 常量 | 全大写 + 下划线 | `MAX_FPS`、`ROI_TOP` | `maxfps` |
| 布尔值 | 用 `is_` / `has_` 开头 | `is_detected`、`has_camera` | `flag`、`ok` |
| 带单位的值 | 单位写进名字 | `timeout_ms`、`distance_m` | `timeout`、`dist` |

- **变量名要说"是什么"，不是"是什么类型"**：`frame_list` 好过 `arr2`
- **不要用拼音**：`chepai_quyu` → `plate_roi`
- **名字长度适中**：`i`、`j` 这种短名只留给循环下标

> ⚠️ 常见坑：`data1`、`data2`、`tmp`、`a`、`b` 满屏飞。写的时候爽，两天后你自己都不知道 `data2` 是原图还是处理后的图。

## 3. 注释：写"为什么"，不写"是什么"

```python
# ❌ 废话注释：代码已经说了
x = x + 1  # x 加 1

# ✅ 有用注释：解释意图、来源、坑
x = x + 1  # 行号从 0 开始，画矩形要转成从 1 开始（OpenCV 的 line 参数习惯）

# ✅ 交代魔法数字的来历（感知代码里最常见的"看不懂"）
THRESHOLD = 145   # 实测：下午强光下 130~160 都稳，选中间值
ROI = (240, 480)  # 只处理图像下半部分，路面区域

# ✅ 标注未完成 / 已知问题
# TODO(bit): 逆光时阈值会失效，待换成自适应阈值
# FIXME: 摄像头被占用时会崩，需要加 try/except
```

## 4. 函数拆分与单一职责

**单一职责**：一个函数只做一件事。判断方法——函数名里出现了"和/并且"，或者函数超过一屏（约 40 行），就该拆。

```python

    cap = cv2.VideoCapture(0)
    while True:
        ret, frame = cap.read()
        gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
        blur = cv2.GaussianBlur(gray, (5, 5), 0)
        _, bw = cv2.threshold(blur, 145, 255, cv2.THRESH_BINARY)
        ...  # 后面还有 80 行

# ✅ 拆成流水线，每一步都能单独测、单独换
def read_frame(cap):        # 读一帧
    ret, frame = cap.read()
    return frame if ret else None

def preprocess(frame):      # 预处理：灰度 + 模糊
    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
    return cv2.GaussianBlur(gray, (5, 5), 0)

def segment(blur):          # 分割：阈值 + 形态学
    ...

def draw_result(frame, mask):  # 可视化
    ...
```

> 💡 类比：流水线工位。每个工位只干一道工序，出了问题能立刻定位是哪个工位；一个人从头做到尾，出了次品你只能重新看一遍全程。

好处很实在：改阈值只动 `segment()`，换相机只动 `read_frame()`，测试可以只测 `preprocess()`。

## 5. 删掉调试代码

提交前检查并删除：

- 满屏的 `print(frame.shape)`（跑起来刷得比报错还快）
- 被 `#` 注释掉的一大段旧代码（交给 git 记，别留尸体）
- 写死的个人路径 `/home/bit/桌面/test.jpg`
- 临时 debug 用的 `cv2.imshow` + `cv2.waitKey(0)`（会卡住队友的循环）

> ⚠️ 常见坑：调试用的 `cv2.waitKey(0)` 忘了改回 `waitKey(1)`，队友跑起来程序"假死"，排查半小时。

## 6. README 写什么

````markdown
# 项目名（一句话说明它是干什么的）

## 1. 功能
- 打开 USB 摄像头，发布 /camera/image_raw
- 识别可行驶区域并绘制掩膜

## 2. 环境要求
- Ubuntu 22.04 / ROS 2 Humble / Python 3.10
- 依赖安装：sudo apt install ros-humble-cv-bridge python3-opencv

## 3. 怎么跑
```bash
colcon build --packages-select robo_cam
source install/setup.bash
ros2 run robo_cam camera_publisher --ros-args -p device_id:=0
```

## 4. 参数说明
| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| device_id | int | 0 | 摄像头编号 |
| fps | int | 30 | 采集帧率 |

## 5. 目录结构 / 6. 常见问题（摄像头被占用、无权限…）
````

README 的核心是**让一个新人在 5 分钟内把项目跑起来**——写的时候把自己当那个新人。

## 7. 不该提交的东西

| 类型 | 例子 | 为什么 |
|------|------|--------|
| 虚拟环境 / 依赖目录 | `.venv/`、`venv/`、`node_modules/` | 几百 MB，人人能自己装 |
| 编译与缓存产物 | `build/`、`install/`、`log/`、`__pycache__/` | 每次构建都会变，冲突不断 |
| 数据集与权重 | `*.bag`、`*.pt`、`*.onnx` | 体积巨大，git 仓库会被撑爆 |
| **密钥与账号** | `token.txt`、`.env`、`id_rsa` | ⚠️ 一旦提交，历史里永久留存，必须立刻作废重发 |
| 个人配置 | `.vscode/`、`*.swp`、`.DS_Store` | 只对你自己的机器有意义 |

`.gitignore` 示例：

```gitignore
# Python
__pycache__/
*.py[cod]
.venv/
venv/

# ROS 2
build/
install/
log/

# 大文件 / 数据
*.bag
*.mp4
*.pt
*.onnx

# 密钥与个人配置
.env
*.key
.vscode/
.DS_Store
```

> 💡 提交前先跑 `git status`，看清楚将要提交哪些文件——这一步能挡掉 90% 的误提交。

## 8. 求助信息模板（照着填就行）

| 字段 | 填什么 | 示例 |
|------|--------|------|
| **1. 环境与版本** | 系统 / ROS / Python / 关键库版本，是否在虚拟环境 | Ubuntu 22.04、ROS 2 Humble、Python 3.10.12、OpenCV 4.5.4 |
| **2. 复现步骤** | 第 1、2、3 步精确到命令 | 1. `source install/setup.bash` 2. `ros2 run robo_cam cam_node` 3. 约 3 秒后崩溃 |
| **3. 期望结果** | 你认为应该发生什么 | 终端持续输出 "publishing..."，rqt_image_view 能看到画面 |
| **4. 实际结果** | 真实发生了什么（不要"不行"） | 终端立即退出，退出码 1，无画面 |
| **5. 已尝试过的方案** | 试了什么、结果如何变化 | 试过 `apt install ros-humble-cv-bridge`，提示已是最新；换摄像头 ID=1 同样报错 |
| **6. 完整报错文本** | **复制文字全文**，不要截图半句 | `[ERROR] ... ModuleNotFoundError: No module named 'rclpy'`（含 traceback 全部） |
| **7. 相关代码片段** | 出错那个函数，或文件 + 行号链接 | `camera_publisher.py:24` 的 `CvBridge()` 调用处 |

> ⚠️ 常见坑：只发一句"我的代码跑不起来，帮我看看"——对方第一句一定是"贴报错"，白等一轮。模板七个字段一次填全，别人**一次就能答**。

## 9. 代码评审怎么说话：对事不对人

| ❌ 这样说 | ✅ 改成 |
|-----------|--------|
| "你这代码写得不行" | "第 42 行直接把路径写死了，换台机器会跑不通，能改成参数吗？" |
| "这变量名看不懂" | "`d` 我读不出含义，改成 `distance_m` 会更清楚，你看行吗？" |
| "为什么不用 XXX" | "这里用参数化会不会更好？理由是换相机时不用改代码" |
| "算了，我自己改" | "这块我提个建议：…… 你觉得呢？" |

原则：**评论代码，不评论人**；说清"哪里 + 为什么 + 建议怎么做"三件事；有疑问用"会不会 / 能吗"，不用"你错了"。

## 10. 提交信息写清楚

```bash
git commit -m "feat: 增加 ROI 裁剪，只处理图像下半部分"
git commit -m "fix: 修复摄像头被占用时节点崩溃的问题"
git commit -m "docs: 补充 README 的参数说明"
git commit -m "refactor: 把 main 拆成预处理/分割/可视化三个函数"
```

前缀含义：`feat` 新功能 / `fix` 修 Bug / `docs` 文档 / `refactor` 重构（不改功能）。一句话说清"**做了什么**"，而不是"改了改"。

## 🎯 课后练习（约8分钟）

```bash
mkdir -p ~/clean-code && cd ~/clean-code
git init -q
git config user.name "trainee" && git config user.email "t@example.com"

# 1. 写一个"很不规范"的脚本，然后按本讲改成规范版
cat > messy.py <<'EOF'
import cv2
d = 0
def f(a):
    g = cv2.cvtColor(a, cv2.COLOR_BGR2GRAY)
    b = cv2.GaussianBlur(g, (5,5), 0)
    _, t = cv2.threshold(b, 145, 255, cv2.THRESH_BINARY)
    print(t.shape)   # 调试打印
    return t
EOF

# 2. 写 .gitignore
cat > .gitignore <<'EOF'
__pycache__/
*.py[cod]
.venv/
venv/
build/
install/
log/
*.bag
*.pt
.env
.vscode/
.DS_Store
EOF

# 3. 制造一个"会被误提交"的文件，看看 git 有没有拦住
mkdir -p .venv __pycache__ && touch .venv/lib.so __pycache__/x.pyc secret.env
git add -A
git status --short
```

> ✅ 你应该看到（类似）：只有 `.gitignore` 和 `messy.py` 出现在暂存区，`.venv/`、`__pycache__/`、`secret.env` 全部被忽略——`git status` 里看不到它们，就说明 `.gitignore` 生效了。

动手任务：把 `messy.py` 改写成规范版（有意义的函数名、常量 `THRESHOLD` 带注释、删掉 `print`），并在文件顶部用三行 README 注释说明它干什么、怎么跑。

> 📝 做完这道练习，你就能回答试题思维 2 的两问：**前半问**答命名、注释、函数拆分、删调试代码、README、.gitignore（不提交 .venv/密钥/大文件）；**后半问**直接答本讲第 8 节那七个字段的求助模板。

## 本讲小结

| 概念 | 要点 |
|------|------|
| 命名规范 | 变量/函数 snake_case、类 CamelCase、常量全大写、布尔加 `is_/has_`、单位进名字 |
| 注释 | 写"为什么"和坑，不写"是什么"；魔法数字要交代来历 |
| 函数拆分 | 单一职责，超过一屏或名字里有"和"就拆；拆完能单测、能单独替换 |
| 不该提交 | .venv/、__pycache__/、build/install/、大文件、密钥、个人配置 |
| README | 功能 / 环境 / 怎么跑 / 参数表 / 目录结构 / 常见问题 |
| 求助模板 | 环境版本、复现步骤、期望结果、实际结果、已尝试、完整报错、相关代码 |
| 代码评审 | 对事不对人：说清"哪里 + 为什么 + 建议" |
