## 1. 先测量，再优化

"卡"是个模糊的词。你得先知道三件事：**一帧要多久、时间花在哪一段、目标帧率是多少。**

```python
import time

t0 = time.perf_counter()
mask = segment(frame)          # 你怀疑很慢的那一段
t1 = time.perf_counter()
print(f"segment 耗时 {(t1 - t0) * 1000:.1f} ms")   # 毫秒
```

分段计时打印几次，你会发现"卡"往往集中在**一两个环节**，而不是整条流水线。

> 💡 类比：外卖高峰期的小厨房。锅只有一口、厨师只有一个，你不能换厨房，只能：少炒几道菜（简化算法）、提前把菜切好备着（缓存）、只接最赚钱的单（ROI 只处理感兴趣区域）。**先看看哪道菜最占灶，再动手。**

> ⚠️ 常见坑：不看耗时占比就"到处优化"，把本来只占 5% 的环节优化到极致，整体帧率纹丝不动。

## 2. 九条可落地的优化手段

### ① 降低输入分辨率

**为什么省**：像素数按面积下降。`640×480`（30.7 万像素）降到 `320×240`（7.7 万像素），要处理的像素只剩 **1/4**，绝大多数逐像素算法的耗时几乎同比减少。

**代价**：远处的小目标看不清（30 米外的锥桶可能只剩几个像素）；标定参数、ROI 坐标、阈值都要跟着重调。

### ② ROI 裁剪：只处理感兴趣区域

**为什么省**：天空、车身、观众席这些区域本来就不用管。只取图像下方 1/2，像素量直接减半，且这部分正是路面所在。

**代价**：ROI 之外的目标彻底丢失（上方突然出现的障碍物看不见）；ROI 区域如果随车体颠簸乱跳，会引入不稳定，需要留余量。

```python
h, w = frame.shape[:2]
roi = frame[h // 2:, :]        # 只取下半部分，路面区域
# 处理完再把结果坐标平移回原图：y += h // 2
```

### ③ 抽帧 / 跳帧

**为什么省**：从 30 FPS 降到 10 FPS，单位时间的工作量只剩 **1/3**。配合"隔帧跟踪、关键帧检测"效果更好。

**代价**：响应延迟变大（10 FPS 下从"看到"到"做出反应"至少 100 ms）；快速运动的物体会在两帧间"跳"很远，容易跟丢。

### ④ 算法简化与降级

**为什么省**：复杂度差一个量级。颜色阈值 + 形态学可能只要 3 ms，同分辨率的深度学习分割要 50 ms 以上。

**代价**：鲁棒性下降，逆光、泥水、强反光下误检漏检明显增多。推荐**级联降级**：先用便宜方法快速筛出可疑区域，只有可疑时才上大模型细看。

### ⑤ 模型量化与剪枝蒸馏

**为什么省**：`FP32 → FP16` 直接砍掉一半显存带宽，`INT8` 再砍一半，且整数运算在嵌入式芯片上更快；剪枝（prune）去掉不重要的连接；蒸馏（distillation）让小模型学大模型。

**代价**：精度会有零点几个百分点的损失；INT8 需要一批校准（calibration）数据；**量化后必须重新跑一遍回归测试**，否则可能悄悄漏检。

### ⑥ OpenCV 用 C++ 或开启多线程

**为什么省**：Python 里写 `for` 循环逐像素处理，速度可能比 NumPy 向量化慢上百倍。能用 NumPy 向量化就向量化；需要极致性能时把热点模块用 C++ 写；`cv2.setNumThreads(4)` 让 OpenCV 内部算法用满多核。

**代价**：C++ 开发和编译成本高，环境依赖变复杂；线程数开太大反而会和其他节点抢 CPU、增加调度开销。

### ⑦ GPU / TensorRT 加速

**为什么省**：GPU 天生并行；TensorRT 还会做**层融合**（把多个算子合成一个）和内核调优，常见能拿到 2~5 倍加速。

**代价**：部署复杂（模型要转换、版本要严格匹配）；首次构建引擎耗时长；功耗与散热压力大，电池本来就紧张。

### ⑧ 缓存与查表：别重复算

**为什么省**：相机内参映射、去畸变坐标、颜色查找表（LUT）这些东西**每次输入都一样**，算一次存起来，后面直接查。查表是 O(1)，重复计算可能是 O(像素数)。

**代价**：初始化时间变长、内存占用上升；参数一旦改变（换了相机、改了分辨率）必须重建缓存，否则结果悄悄错掉。

### ⑨ 减少内存拷贝与颜色空间转换

**为什么省**：每次 `cvtColor`、`.copy()`、`np.float32(img)` 都是**整张图遍历一遍**。`640×480×3` 的图，多余的一次转换就是几十万次运算。

**代价**：代码要重构，可读性会降；改错了容易产生"某处用了旧数据"这类很难查的 Bug。原则：**BGR→HSV 只转一次，只做灰度识别就别保留彩色副本。**

```python
# ❌ 一段循环里连续多次转换
for f in frames:
    gray = cv2.cvtColor(f, cv2.COLOR_BGR2GRAY)
    gray2 = cv2.cvtColor(f, cv2.COLOR_BGR2GRAY)   # 完全重复

# ✅ 转一次，复用；不需要时别用 float64（float32 就够）
gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
```

## 3. 取舍对比表（拿去做讨论稿）

| 优化手段 | 省算力幅度 | 代价 | 适用场景 |
|---------|-----------|------|---------|
| 降分辨率 | ⭐⭐⭐⭐⭐ 约 4 倍（640×480→320×240） | 小目标看不清、参数需重调 | 全局吃力时的第一步 |
| ROI 裁剪 | ⭐⭐⭐⭐ 减半或更多 | ROI 外目标丢失、颠簸时 ROI 抖 | 只关心路面 / 固定安装视角 |
| 抽帧跳帧 | ⭐⭐⭐⭐ 30→10 FPS 即 3 倍 | 延迟变大、快速目标易跟丢 | 目标变化慢、可配跟踪补偿 |
| 算法简化降级 | ⭐⭐⭐⭐⭐ 可达 10 倍以上 | 鲁棒性下降、误检增多 | 光照良好 / 用作快速初筛 |
| 量化剪枝蒸馏 | ⭐⭐⭐ 2~4 倍（INT8） | 精度损失、需校准与回归测试 | 必须用深度模型的边缘端 |
| C++ / 多线程 | ⭐⭐⭐⭐ 1 个数量级（干掉 Python 循环） | 开发成本、编译依赖、抢 CPU | 热点函数已被定位清楚 |
| GPU / TensorRT | ⭐⭐⭐⭐ 2~5 倍 | 部署复杂、功耗散热 | 有 Jetson 等带 GPU 的板子 |
| 缓存查表 | ⭐⭐⭐（视重复度，最高可达数倍） | 初始化慢、内存涨、参数变了要重建 | 内参映射、LUT、固定几何变换 |
| 减拷贝与色彩转换 | ⭐⭐ 10%~30% | 代码可读性下降、易出隐性 Bug | 所有场景，属于"顺手就能做" |

组合使用效果示例：`320×240` + 下半图 ROI + 10 FPS + 双线性简化算法，轻松把单帧耗时从 80 ms 压到 5 ms 以内。

> ⚠️ 常见坑：**一次上多个优化**——帧率是上去了，但你不知道是哪个起了作用，出了问题也说不清是哪一步引入的。像第 01 讲说的那样：**一次只改一处，改完立刻测。**

## 🎯 课后练习（约8分钟）

用 NumPy 亲手量一量"降分辨率"和"ROI"到底省多少。

```python
import time
import numpy as np

def work(img):
    """模拟一份逐像素处理：灰度化 + 阈值"""
    gray = img.astype(np.float32).mean(axis=2)
    return gray > 120

full = np.random.randint(0, 255, (480, 640, 3), dtype=np.uint8)
small = np.random.randint(0, 255, (240, 320, 3), dtype=np.uint8)
roi = full[240:, :]          # 下半部分：240 行 × 640 列

for name, img in [("640x480 全图", full),
                  ("320x240 全图", small),
                  ("640x480 的 ROI 下半部分", roi)]:
    t0 = time.perf_counter()
    for _ in range(20):
        work(img)
    dt = (time.perf_counter() - t0) / 20 * 1000
    print(f"{name}: {dt:.2f} ms/帧  约 {1000 / dt:.0f} FPS")
```

> ✅ 你应该看到（类似，具体数值和 CPU 有关）：
> ```
> 640x480 全图: 2.10 ms/帧  约 476 FPS
> 320x240 全图: 0.55 ms/帧  约 1818 FPS
> 640x480 的 ROI 下半部分: 1.05 ms/帧  约 952 FPS
> ```
> 规律应该很清晰：**分辨率降到 1/4，耗时也降到约 1/4；ROI 取一半，耗时约减半。**

## 本讲小结

| 概念 | 要点 |
|------|------|
| 优化流程 | 先测量定位瓶颈，再动手；一次只改一处 |
| 降分辨率 | 像素按面积减少，代价是小目标看不清、参数要重调 |
| ROI 裁剪 | 只处理路面区域，代价是区域外目标丢失 |
| 抽帧跳帧 | 降帧率线性省算力，代价是延迟与跟丢风险 |
| 算法简化降级 | 便宜方法初筛 + 大模型细看（级联） |
| 量化剪枝蒸馏 | INT8/FP16 省带宽算力，代价是精度损失与校准成本 |
| 工程级手段 | C++/多线程、GPU/TensorRT、缓存查表、减少拷贝与色彩转换 |
| 核心原则 | 每条优化都有代价，优化是取舍不是白赚 |
