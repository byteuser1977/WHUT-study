# 第01讲：报错处理方法论（正文约12分钟 + 练习约8分钟）

## 你将学到
- 一大串英文报错，先看哪一行、再按什么顺序往下看
- 怎么从报错里挑出真正能搜到答案的关键词
- 改代码之前怎么"存档"，不让代码越改越乱
- 找别人或找 AI 求助前，自己先过一遍的自查清单

## 1. 报错不是乱码，它有固定结构

终端里刷出来的那一大串英文叫 **traceback**（回溯），它的意思是"程序从哪一路调用到出错位置的路线图"。

它只有三层信息，从下往上读：

```text
Traceback (most recent call last):
  File "detect_lane.py", line 12, in <module>          ← ② 第一处"你自己的文件"
    from cv_bridge import CvBridge
  File "/home/bit/.local/lib/python3.10/site-packages/cv_bridge/__init__.py", line 3, in <module>   ← ③ 库里内部的行（噪音）
    import rclpy
ModuleNotFoundError: No module named 'rclpy'           ← ① 最后一行：异常类型 + 原因
```

| 位置 | 说的是什么 | 你该干什么 |
|------|-----------|-----------|
| **最后一行** | 异常类型 + 一句话原因 | 先看这里，它才是"病因" |
| **往上第一处 `File "xxx.py"`（文件名是你自己写的那个）** | 你的代码在哪一行触发了它 | 去编辑器打开那一行 |
| **中间夹着的那个库内部路径** | 库自己内部的调用（`site-packages/...`） | 一般不用管，它是"受害者的日记" |

> 💡 类比：报错就像餐厅后厨出的岔子。最后一行是"结果"（客人吃到的是凉菜）；你自己的那行是"责任岗位"（凉菜是从哪个档口端出来的）；中间的库路径是"传菜员的路线"，通常不是问题所在。你要做的是先看结果、再找责任岗位，而不是从传菜员第一脚开始逐帧回放。

## 2. 阅读顺序四步法

1. **看最后一行**：认出异常类型（下表），心里先有个方向
2. **向上扫**：找第一处 `File "你的文件名.py", line N`——这才是要改的地方
3. **再往上扫一眼**：确认调用链，看看是不是别处传进来的坏数据（比如别人传了个 `None` 给你）
4. **回到最后一行**：用关键词去搜（下一节讲）

常见异常类型速查：

| 异常名 | 通俗解释 | 最常见原因 |
|--------|---------|-----------|
| `ModuleNotFoundError` | 找不到这个模块 | 没装库 / 装到了另一个 Python 环境 / 包名拼错 |
| `ImportError` | 模块找到了，要导出的东西却拿不到 | 版本不对，函数被改名或删除（例如 `cv2.findContours` 返回值个数变过） |
| `FileNotFoundError` | 路径下没有这个文件 | 相对路径搞错、当前目录不对 |
| `AttributeError` | 这个对象没有这个属性 | 变量其实是 `None`、API 改名 |
| `TypeError` | 参数类型不对 | 传了字符串给需要数字的地方 |
| `IndexError` / `KeyError` | 下标越界 / 字典没这个键 | 数组长度算错、键名拼错 |
| `cv2.error` | OpenCV 报的错 | 图像是空的（读图失败）、数据类型不对 |
| `SyntaxError` | 语法错误 | 少括号、少冒号、Tab 与空格混用缩进 |

> ⚠️ 常见坑：一看到红字就往上翻，从头读到尾。真正有用的信息量 90% 集中在最后一行和第一处你自己的文件名上，中间那段库内部路径基本可以跳过。

## 3. 关键词提取法：把噪音削掉

报错里大量内容是**噪音**：绝对路径、Python 版本号、内存地址（`0x7f3c...`）、库内部行号、时间戳。把它们删掉，只留：

- **异常名**（`ModuleNotFoundError`）
- **异常描述里的关键对象**（`No module named 'rclpy'` 里的 `rclpy`）
- **关键动作词 / 函数名**（`cv_bridge`、`imshow`、`VideoCapture`）

| 原始报错（噪音多） | 提取后（能搜到答案） |
|--------------------|---------------------|
| `File "/home/bit/.local/lib/python3.10/site-packages/cv_bridge/__init__.py", line 3, in <module>` | `cv_bridge python3.10` |
| `ModuleNotFoundError: No module named 'rclpy'`（Python 3.10.12） | `"ModuleNotFoundError: No module named 'rclpy'" ROS 2 Humble` |
| `OpenCV(4.5.4) /home/.../cap.cpp:1234: error: (-215:Assertion failed) !_src.empty()` | `"(-215:Assertion failed) !_src.empty()"` |

搜索技巧（按顺序试）：

1. **用英文原文搜**，不要翻译成中文——报错是英文的，答案也是英文的
2. **加双引号**，把完整异常句当整体搜，能过滤掉大量无关结果
3. **加技术栈关键词**：`ROS 2 Humble`、`Ubuntu 22.04`、`OpenCV 4.5.4`、`rclpy`
4. **先单独搜异常名**搞懂它是什么意思，再搜带具体描述的那一句

## 4. 改代码前的"存档三件套"

新手最惨的不是报错，而是"改着改着原来能跑的版本也没了"。

> 💡 类比：打游戏闯关前先存档。你不会因为"这关我肯定能过"就不存档——代码也一样，改之前先留一个"刚才还能跑"的点，改坏了直接读档，比事后一行行找回快一百倍。

| 措施 | 具体怎么做 | 适合场景 |
|------|-----------|---------|
| **① git 快照** | `git add -A && git commit -m "wip: 改之前的可运行版本"` | 已经在用 git 的项目（推荐，最强） |
| **② 复制备份** | `cp detect_lane.py detect_lane.py.bak` | 临时脚本、还没进 git |
| **③ 一次只改一处 + 立刻验证** | 改完一行马上跑一次，报错变了就知道是这行 | 所有场景，最重要的一条 |
| **④ 先注释掉新代码** | 把新加的那几行注释掉再跑一次 | 判断"是不是我这次引入的" |

> ⚠️ 常见坑：一口气改十处再一起跑——报错变了你也说不清是哪一处干的；用 AI "帮我改好整个文件" 直接把能跑的版本覆盖掉；把 `.bak` 也提交进仓库。

## 5. 求助前自查清单（照着念）

- [ ] 报错**全文**（文字，不是屏幕照片；照片里的半句常常缺了最关键的异常名）
- [ ] 我能**复现**吗？最小复现步骤是什么（第几步、点了什么、跑了哪条命令）
- [ ] 报错里**第一处我自己文件名 + 行号**是哪里？那一行在干什么？
- [ ] **环境**：系统版本、Python 版本、库版本、是不是在虚拟环境 / conda 环境里
- [ ] 我**已经试过**什么？试完报错有没有变化（这条最能省对方时间）

## 🎯 课后练习（约8分钟）

故意制造三种报错，然后只读最后一行和第一处自己的文件。

```bash
mkdir -p ~/err-lab && cd ~/err-lab

# ① 制造 ModuleNotFoundError（没装 ROS 2 也会得到同样的报错，正好用来练）
python3 -c "import cv_bridge"

# ② 制造 IndexError
cat > idx.py <<'EOF'
data = [1, 2, 3]
print("第 5 个元素是：", data[5])
EOF
python3 idx.py

# ③ 存档演练：先提交一个能跑的版本，再改坏，最后读档
git init -q demo && cd demo
git config user.name "trainee" && git config user.email "t@example.com"
printf 'print("v1 ok")\n' > app.py
git add -A && git commit -qm "v1: 能跑的版本"
printf 'print("v2 broken")\n' > app.py     # 改成"改坏了"的版本
git status --short                          # 看到 app.py 被修改
git restore app.py                          # 读档
python3 app.py
```

> ✅ 你应该看到（类似）：
> ```
> ModuleNotFoundError: No module named 'cv_bridge'
> IndexError: list index out of range
>  M app.py
> v1 ok
> ```

> 📝 做完这道练习，你就已经能回答试题"面对一大串报错你会优先看哪里、提取什么关键词、改前采取什么措施"了——把你的答案写成三句话：**看最后一行拿异常类型 → 往上找第一处自己的文件行号 → 提取"异常名 + 关键对象"用英文加引号搜；改前 git commit 存档、一次只改一处、改完立刻验证。**

## 本讲小结

| 概念 | 要点 |
|------|------|
| traceback | 报错的三层结构：最后一行是病因，第一处自己的文件是责任岗位 |
| 阅读顺序 | 最后一行 → 异常类型 → 第一处 `File "我的文件.py", line N` → 调用链 |
| 关键词提取 | 去掉路径/版本号/内存地址，只留异常名 + 关键对象 |
| 搜索技巧 | 英文原文、加双引号、加技术栈与版本关键词 |
| 存档三件套 | git commit 快照 / 复制 .bak / 一次只改一处并立即验证 |
| 求助自查 | 完整报错、复现步骤、环境版本、已试过的方案 |
