- "如何编写一个 ROS 2 节点来打开电脑摄像头"的完整提示词实录（4 轮，可直接抄）
- 怎么让 AI 自己查错，以及什么时候不该信它

## 1. 提示词不是聊天，是写需求单

跟 AI 说话最常见的失败不是"AI 太笨"，而是**你没把话说清**。AI 看不见你的电脑、不知道你装了哪个版本的 ROS、不知道你是要跑通 demo 还是要上真车——你不说，它就只能猜，猜错了你还要重问三轮。

> 💡 类比：让装修队干活。说"给我装个厨房"，来的是什么风格、多大面积、预算多少全凭对方猜；说清"8 平米、要洗碗机、台面 60 cm 高、预算 3 万、周末不能施工"，一趟就能干对。**提示词就是给 AI 的施工需求单。**

> ⚠️ 常见坑：把"这个报错怎么解决"当作一条完整提问。AI 会给你一段听起来对、但和你环境完全不匹配的答案。

## 2. 高效提示词的八要素

| 要素 | 写什么 | 反面例子 |
|------|--------|---------|
| **1. 角色** | 让 AI 站在哪个专业位置上 | 不写 → 回答很泛 |
| **2. 目标** | 一句话说清最终要什么 | "帮我看看摄像头" |
| **3. 环境与版本** | 系统 / ROS / Python / 库版本 | 不写 → 给你 ROS 1 的代码 |
| **4. 输入材料** | 报错全文、代码片段、图片路径、数据形状 | 只说"报错了" |
| **5. 约束** | 不要做什么、必须用什么 | 不写 → 一上来给 200 行你不敢用 |
| **6. 输出格式** | 分点 / 表格 / 完整代码 / 只要 diff | 不写 → 一堆大段文字 |
| **7. 验收标准** | 什么算成功 | 不写 → 无法判断对不对 |
| **8. 示例** | 给一个"期望的样子"样例 | 不写 → 格式来回返工 |

模板（背下来，按需删减）：

```text
【角色】你是<某领域>的工程师。
【目标】我要<一句话说清要什么>。
【环境】<系统 + 版本 + 语言 + 关键库版本>。
【输入材料】<报错全文 / 代码片段 / 数据结构>。
【约束】<必须用 …；不要 …；先不要写代码，只给方案>。
【输出格式】<分点 / 表格 / 完整代码块 / 只给需要改的行>。
【验收标准】<怎么算成功，例如"能直接复制运行并 /camera/image_raw 有数据">。
【示例】<给一个期望输出的样子>。
```

## 3. 多轮迭代：先问最小可行问题

一次问到底 ≠ 高效。正确节奏是**先要方案轮廓，再要代码，再纠错，最后要自检**——每一轮都建立在上一条回答被验证过的基础上。

> 💡 类比：点菜。先问"有没有不辣的"，再问"招牌是哪道"，最后才说"那来一份"。一上来把全部要求糊成一长段，AI 容易抓错重点；分轮问，你每一步都能检查。

## 4. 实录：如何编写一个 ROS 2 节点来打开电脑摄像头

> 这四轮就是可以直接抄走的。每轮后面跟一段"**为什么这么问**"的短评。
> 📌 建议把给 AI 的**全部提示词**都留存下来——从第一轮起就建一个 `prompts.md`，每问一次粘一条进去。

### 第 1 轮：要整体方案与依赖，不要代码

```text
【角色】你是有 3 年经验的 ROS 2 视觉工程师。
【目标】我要写一个 ROS 2 节点，打开电脑自带摄像头，把画面以 sensor_msgs/Image
发布到话题 /camera/image_raw，并且能在 rqt_image_view 里看到画面。
【环境】Ubuntu 22.04 + ROS 2 Humble + Python 3.10，使用 rclpy；OpenCV 4.5.4。
【约束】这一轮先不要写完整代码。只给我整体方案：
 1) 需要哪些依赖，apt 和 pip 各给一条安装命令；
 2) 这个节点该放在哪个功能包的哪个目录，包用 ament_python 还是 ament_cmake；
 3) 涉及哪些核心 API（一句话说清每个 API 干什么）。
【输出格式】分点列出，命令用代码块。
【验收标准】我照着这套方案能自己判断出"我缺哪个依赖"。
```

**为什么这么问**：把环境和"不要写代码"两条约束前置，避免 AI 一上来甩 200 行你根本读不完的代码；先只拿方案，你能用 1 分钟判断它的方向对不对，方向不对立刻止损。

### 第 2 轮：要完整可运行代码与构建步骤

```text
基于你上一轮的方案，现在给我完整可运行的实现。具体要求：
 1) 包名 robo_cam，节点文件 camera_publisher.py，用 rclpy，类名 CameraPublisher；
 2) 参数用 declare_parameter 声明并在运行时可通过 --ros-args -p 修改：
    device_id（int, 默认 0）、fps（int, 默认 30）、topic_name（str, 默认 /camera/image_raw）；
 3) 用 cv2.VideoCapture 读帧，用 cv_bridge 的 CvBridge 转成 sensor_msgs/Image，
    header.stamp 用 self.get_clock().now().to_msg()；
 4) 完整给出 package.xml 和 setup.py（ament_python 方式）中需要修改的部分；
 5) 给出从创建包到运行的完整 colcon 命令序列（含 source）；
 6) 代码里关键行加中文注释，解释为什么这么写；
 7) 最后给一段"验证步骤"，并说明我该看到什么（含 ros2 topic hz 的预期数值）。
【约束】代码必须能直接复制运行，不要省略成 # 省略若干行；不要引入额外的第三方依赖。
【输出格式】代码块 + 命令块，分小节。
```

**为什么这么问**：把"可运行"翻译成了可检验的具体条件（包名/文件名/类名/参数名/构建方式），AI 就不会自己另造一套目录结构；要构建文件和验证预期是因为**新手 90% 的失败发生在构建与运行这一步，而不是代码本身**；"不要省略成 # 省略若干行"能直接挡掉 AI 最爱用的偷懒写法。

### 第 3 轮：拿报错精准纠错（不要重写整个文件）

```text
我按你的步骤操作：colcon build 成功，source 后 ros2 run 时出现以下报错（完整粘贴）：

Traceback (most recent call last):
  File "/home/bit/ros2_ws/install/robo_cam/lib/python3.10/site-packages/robo_cam/camera_publisher.py", line 6, in <module>
    from cv_bridge import CvBridge
ModuleNotFoundError: No module named 'cv_bridge'

【环境】Ubuntu 22.04 + ROS 2 Humble，Python 3.10.12，我用的是系统 Python，没有 conda。
【已尝试】已执行 sudo apt install ros-humble-cv-bridge，终端提示 "已是最新版本"；
          也试过 pip install cv_bridge，报编译错误。
请回答：
 1) 这个报错的根本原因是什么（结合我"apt 说已装但 import 不到"这个现象分析）；
 2) 给出按顺序执行的具体修复命令，并说明每一步在干什么；
 3) 说明这个修复会不会影响我其他节点；
 4) 只给我需要改动的行，不要重写整个文件。
```

**为什么这么问**：贴完整 traceback（第 01 讲的方法）+ 说明"我已经试过 apt 和 pip"——这两条直接省掉一轮"你是不是没装"。最后一句"不要重写整个文件"是关键：AI 一旦重写，很可能把上一轮已经跑通的部分一起改坏，你就从"一个报错"变成"一堆报错"。

真实环境里这一步最常见的四个坑：
- `cv_bridge` 装在系统 Python，但你用 conda 环境跑 → 环境不匹配，`apt` 装了也 import 不到
- 摄像头被其他程序占用 → `[WARN] ... device busy`，要先关掉占用程序
- `encoding='bgr8'` 与图像实际格式不一致 → rqt_image_view 里颜色发蓝或直接报错
- 节点跑起来了但 `ros2 topic hz` 显示 0 Hz → 话题名拼错或根本没进 `publish` 分支

### 第 4 轮：要自检清单与参数说明（顺带让 AI 自我批判）

```text
现在代码能跑通了。请在**不重写代码**的前提下给我四样东西：
 1) 一份上线前自检清单（至少 8 条，勾选式），覆盖：依赖是否齐全、参数是否正确、
    话题名与频率、CPU 占用、摄像头断开时的异常处理、退出时资源释放；
 2) 一张参数表：参数名 / 类型 / 默认值 / 合理取值范围 / 调大或调小的后果；
 3) 三个最常见的失败模式，以及每个用什么命令能快速定位；
 4) 回头指出你上面给的代码里最容易出问题的 3 处，并说明理由。
【输出格式】清单用 - [ ]，参数用 Markdown 表格。
```

**为什么这么问**：第 4 问"指出你自己代码里最容易出问题的 3 处"是**让 AI 自我批判**——它常常会在这里补出前面没说清的假设（比如"没判断 ret 返回值，摄像头断开会崩"）。你真正拿到的不是三处问题，而是一份原来没意识到的风险清单。

## 5. 让 AI 自查与交叉验证

| 技巧 | 怎么问 | 有什么用 |
|------|--------|---------|
| 复述需求 | "先用一段话复述我的需求，确认你没理解错，再动手" | 提前暴露误解，比你发现代码不对再回头省时间 |
| 先思路后代码 | "先讲思路和关键步骤，我确认后你再写代码" | 思路错了不用读代码就能掐掉 |
| 自我批判 | "指出你这段代码最可能出错的 3 个地方" | 逼出它隐藏的假设与风险 |
| 反方提问 | "你结论的反面成立需要什么条件？" | 防止一面之词 |
| 交叉验证 | 换一个模型 / 换一种问法问同一个问题 | 两个 AI 说同一件事，比一个 AI 说得自信可信得多 |
| 以跑为准 | 一切以本机真实运行结果为准 | 代码跑得通 > AI 说跑得通 |

> ⚠️ 常见坑：把"AI 说能跑通"当成"已经跑通"。感知项目里唯一可信的验收是：**在本机 + 本车 + 真实光照下跑过一遍。**

## 6. 何时不该信 AI

| 场景 | 风险 | 正确做法 |
|------|------|---------|
| 库版本与 API 变化 | 给你已删除的函数名，编辑时不报错、运行时才崩 | 查官方文档；`python3 -c "import cv2; print(cv2.__version__)"` 对版本 |
| 比赛规则 / 赛程细节 / 截止时间 | 完全可能编出"看起来像真的"条款 | 以官方文件和群公告为准，AI 一个字都不能当依据 |
| 安全相关代码 | 急停、电机上电、舵机限位写错会撞车伤人 | 人工评审 + 车下先测，绝不直接上真车 |
| 硬件参数 | 电压电流、线序、引脚定义 | 查芯片数据手册，不问 AI |
| 需要联网 / 收费 API | 给出的接口在你环境里根本不可用 | 先确认可用性再集成 |
| 你自己的专业判断 | 没搞懂的代码，出问题时你根本查不下去 | 每条 AI 给的结论，你都要能用一句话解释"为什么" |

> ⚠️ 最常见的一个坑：AI 给出的代码"看起来对"，但里面 import 了一个不存在的模块、或者用了改名前的旧 API。**先跑最小样例，再往项目里搬。**

## 🎯 课后练习（约15分钟）

**任务一（10 分钟）**：把第 4 节的四轮提示词**真的对着 AI 走一遍**，把每一条提示词、以及 AI 回答的关键结论，存进一个文件：

```bash
mkdir -p ~/prompt-lab && cd ~/prompt-lab
cat > prompts.md <<'EOF'
# ROS 2 摄像头节点 —— 提示词实录

## 第 1 轮（方案与依赖）
（粘贴你的第一条提示词）
> AI 回答要点：……

## 第 2 轮（完整代码与构建）
……

## 第 3 轮（报错纠错）
……

## 第 4 轮（自检清单与参数）
……
EOF
```

**任务二（5 分钟）**：故意制造一个报错，练"精准纠错"这一轮：

```bash
# 制造一个必定出现的 Python 报错（和摄像头无关，只为练格式）
python3 -c "
import vision_module
print(vision_module.hello())
"
```

> ✅ 你应该看到（类似）：
> ```
> Traceback (most recent call last):
>   File "<string>", line 2, in <module>
>     import vision_module
> ModuleNotFoundError: No module named 'vision_module'
> ```

现在把这段报错**完整**粘给 AI，并附上环境（Python 3.10.12、Ubuntu 22.04）、已尝试（"没有这个模块，是我自己没写的文件"）、要求（"告诉我应该怎么建这个文件，最少几步能跑通，只给必要代码"）。观察它的回答是不是比"报错了怎么办"这种问法精准得多。

> 📝 这一讲的整理结构建议就是：**先写你的提示词编写原则（八要素表 + 多轮迭代节奏）→ 再附四轮实录 → 最后加一段"如何验证 AI 答案"，** 也就是本讲的第 2、3、4、5、6 节。

## 本讲小结

| 概念 | 要点 |
|------|------|
| 八要素 | 角色、目标、环境与版本、输入材料、约束、输出格式、验收标准、示例 |
| 多轮迭代 | 先要方案 → 再要代码 → 报错纠错 → 要自检清单，每轮都验证过再往下 |
| 纠错要诀 | 贴完整报错 + 说明已试过什么 + "只给需要改的行，别重写整个文件" |
| AI 自查 | 复述需求、先讲思路、自我批判 3 处、反方提问、换模型交叉验证 |
| 不信 AI 的场景 | 版本差异、比赛规则、安全代码、硬件参数、你答不上"为什么"的一切 |
| 最终验收 | 以本机真实运行结果为准，不以 AI 的口头结论为准 |
