## 你将学到

- 哪些操作**真的会丢代码**，怎么避免

## 1. 先记住一句话：先判断"改到哪一步了"

撤销命令没有"万能钥匙"，用错参数会丢代码。判断标准只有一个：**我的改动现在待在哪个区？**

| 场景 | 改动在哪 | 想达到的效果 |
|------|---------|-------------|
| (a) 改乱了，还没 `add` | 只在工作区 | 丢弃工作区修改 |
| (b) 已 `add`，还没 `commit` | 已进暂存区 | 退回到工作区，再决定留不留 |
| (c) 已 `commit`，还没 `push` | 已进本地仓库 | 撤销这次提交（历史可以抹掉） |
| (d) 已经 `push` 了 | 已进远程仓库 | 不能用改历史的方式，要"反向提交" |

> 💡 类比：写作业写错了。
> (a) 草稿纸上一行写错 → 橡皮擦掉重写（`git restore`）。
> (b) 已经抄到"待交作业清单"上了 → 先把它划掉，再决定重抄（`restore --staged`）。
> (c) 已经装订进作业本、还没交上去 → 可以拆开重装（`reset`）。
> (d) 已经交到老师手上了 → **不能偷偷抽回来**，只能再交一张"更正说明"（`git revert`）。

## 2. 四种场景对照表（核心）

| 场景 | 命令 | 命令执行后各区域的变化 |
|------|------|----------------------|
| (a) 改乱了，未 add | `git restore camera.py`<br>（旧写法 `git checkout -- camera.py`） | 工作区 → 恢复成上次提交的样子；暂存区、本地仓库不变 |
| (a) 全部文件都想丢 | `git restore .` 或 `git checkout -- .` | 工作区所有改动清空，回到上一次提交状态 |
| (b) 已 add，未 commit | `git restore --staged camera.py`<br>再 `git restore camera.py` | 第一条：暂存区 → 回到工作区（改动还在！）；<br>第二条：工作区 → 丢弃改动 |
| (c) 已 commit，未 push，要留改动 | `git reset --soft HEAD~1` | HEAD 回退 1 个提交；**暂存区和工作区保留改动**（改动处于已 add 状态） |
| (c) 已 commit，未 push，改动退回工作区 | `git reset HEAD~1`（= `--mixed`，默认） | HEAD 回退；暂存区清空；**工作区保留改动** |
| (c) 已 commit，未 push，改动全丢 | `git reset --hard HEAD~1` | HEAD 回退；暂存区和工作区**全部清空**，未提交改动永久丢失 |
| (d) 已 push | `git revert <提交哈希>` | 不改历史，**新建一条反向提交**把那次改动抵消掉，可正常 `push` |
| 临时存盘 | `git stash` / `git stash pop` | 工作区与暂存区清空变干净；`pop` 时改动原样回来 |

> 🎯 **试题 4(2)（5 分）标准答案，一眼可查：**
> 修改后还没 commit 发现改乱了，想放弃修改并恢复到上一次提交的状态，用：
> ```bash
> git restore .          # Git 2.23+ 推荐写法（当前文件所在目录及子目录全部还原）
> git restore camera.py  # 只还原某一个文件
> git checkout -- .      # 旧写法，效果相同（Git 2.34 仍可用）
> ```
> **如果已经 `add` 过了**，得先把它从暂存区退回来，再还原工作区：
> ```bash
> git restore --staged .   # 先取消暂存（改动仍在工作区）
> git restore .            # 再丢弃工作区修改
> ```

> ⚠️⚠️ **警告：`git reset --hard` 会永久丢失未提交的修改。**
> 它同时清空暂存区和**工作区**，被抹掉的改动没有提交记录，`git log` 里找不到、`reflog` 也救不回来（reflog 只能救"已经 commit 过又被 reset 掉"的提交，不能救从未提交过的改动）。
> **用之前务必先 `git status` 确认一遍，或者先 `git stash` 存一份。**

> ⚠️ 常见坑：已 push 的提交不要用 `git reset` + 强推去抹掉历史。队友本地还有旧历史，强推会让别人的仓库炸掉。用 `git revert` 才是团队安全做法。

## 3. git reset 三种模式的区别（一张图看懂）

假设当前是 `A <- B <- C`，`C` 是刚提交的，执行 `git reset --xxx B`：

```text
--soft   提交历史：A <- B         暂存区：保存 C 的改动（已 add）      工作区：保存改动
--mixed  提交历史：A <- B         暂存区：清空                       工作区：保存改动（未 add）
--hard   提交历史：A <- B         暂存区：清空                       工作区：清空 ⚠️改动消失
```

> 💡 记忆法：**soft 最温柔**（只退历史，东西都留着）；**mixed 中等**（连暂存区一起退，东西还在工作区）；**hard 最狠**（连工作区一起扫掉）。

## 4. git stash：写一半要切走

代码写了一半，突然要修紧急 Bug，又不想把半成品提交进去：

```bash
git stash            # 把当前未提交的改动打包存起来，工作区变干净
git stash list       # 查看存了几份
git stash pop        # 恢复最近一份，并从列表里删掉
git stash apply      # 恢复但不删掉列表记录
```

> 💡 类比：`git stash` 就像**把桌上的东西一股脑扫进抽屉**，桌面立刻干净；`pop` 就是把抽屉的东西倒回桌面。

## 🎯 课后练习（约8分钟）

```bash
mkdir -p ~/git-undo && cd ~/git-undo
git init
git config user.name "你的名字"; git config user.email "你@example.com"   # 没配过全局时用

echo "v1" > note.txt
git add note.txt && git commit -m "feat: 初版"

# 场景(a)：改乱了，还没 add
echo "乱改的内容" > note.txt
git status                       # modified: note.txt
git restore note.txt             # 放弃修改
cat note.txt                     # ✅ 你应该看到： v1

# 场景(b)：已 add，未 commit
echo "又乱改" > note.txt
git add note.txt
git status                       # Changes to be committed
git restore --staged note.txt    # 先退出暂存区
git restore note.txt             # 再丢弃
cat note.txt                     # ✅ 你应该看到： v1

# 场景(c)：已 commit，未 push，用 --soft 回退
echo "v2" > note.txt
git add note.txt && git commit -m "feat: v2"
git reset --soft HEAD~1
git status                       # ✅ 你应该看到：修改还在暂存区（Changes to be committed）
git commit -m "feat: v2 重新提交一次"

# 场景(c)危险版：--hard（先 stash 保命）
git reset --hard HEAD~1
git log --oneline                # ✅ 你应该看到：只剩一条 "feat: 初版"

# 场景(d)：revert（模拟已 push 的提交）
git revert --no-edit HEAD        # ✅ 会打开编辑器/直接生成一条 Revert "..." 的反向提交
git log --oneline
```

> ✅ 你应该看到（类似）：
> ```
> v1
> v1
> Changes to be committed:   modified: note.txt
> 1a2b3c4 (HEAD -> main) feat: 初版
> 4d5e6f7 (HEAD -> main) Revert "feat: 初版"
> 1a2b3c4 feat: 初版
> ```

## 本讲小结

| 场景 | 命令 | 备注 |
|------|------|------|
| 未 add，想丢弃改动 | `git restore <文件>` / `git restore .` | 旧写法 `git checkout -- <文件>` |
| 已 add，想取消暂存 | `git restore --staged <文件>` | 改动**仍在工作区** |
| 已 commit 未 push，保留改动 | `git reset --soft HEAD~1` | 只退历史 |
| 已 commit 未 push，改动回工作区 | `git reset HEAD~1` | `--mixed` 是默认模式 |
| 已 commit 未 push，全丢 | `git reset --hard HEAD~1` | ⚠️ 永久丢失未提交修改 |
| 已 push | `git revert <哈希>` | 新增反向提交，历史安全 |
| 临时存盘 | `git stash` / `git stash pop` | 写一半切任务专用 |
| 通用原则 | 动 `--hard` 之前先 `git status` 或 `git stash` | 保命习惯 |
