## 1. 三类障碍物，三种打法

"障碍物"不是一类东西。**行人、物块、锥桶的视觉特征几乎没有交集**，用同一个方法硬吃三个类别，是最常见的翻车方式。

| 目标 | 视觉特征 | 识别难度 | 推荐方法 |
|------|----------|----------|----------|
| **行人** | 垂直细长（高宽比约 2:1~4:1）、表面有纹理（衣服）、可能是移动的、颜色不定、有腿间隙 | 中高（姿态多变、可能蹲下/穿迷彩） | 几何法（高宽比+垂直梯度）+ 运动检测（帧差/光流）+ 学习法（行人检测器） |
| **物块** | 体积小、贴地、颜色不固定（土块/石块/木板）、轮廓不规则 | 最高（无颜色先验、太小易被当噪声、与土路颜色接近） | 深度/几何（离地高度、地面平面外点）+ 学习法为主，颜色法基本无效 |
| **高锥桶** | 橙红色、圆锥形（高宽比约 1.5:1~2:1）、高度固定（约 50~70 cm）、通常成组排列 | 低（特征最鲜明） | 颜色法（HSV 橙色阈值 + 形态学）为主，几何法复核 |

> 💡 类比：这就像在操场上找人、找一块掉在地上的橡皮、找一排路障。找人靠"形状+会不会动"，找橡皮靠"仔细看地面上的突起"，找路障**远远看颜色就够了**。**先分清目标类型，再决定用什么特征**——这一步想错了，后面调参调到天亮也没用。

> ⚠️ 常见坑：把高锥桶的颜色阈值直接套用在物块上。物块（土块、木块）在泥地里的颜色与背景几乎一样，颜色法只会给你一堆噪声。**物块的正确依据是"凸出地面的几何体"，不是"什么颜色"。**

## 2. 三条技术路线对比

| 维度 | 几何法 | 颜色法 | 学习法 |
|------|--------|--------|--------|
| 核心原理 | 连通域分析 + 长宽比/面积/离地高度筛选 | HSV/Lab 阈值 + 形态学处理 | 卷积神经网络端到端检测（YOLO/DETR） |
| 典型流程 | 二值化 → 连通域 → 特征筛选 | 转 HSV → `inRange` → 开闭运算 → 轮廓 | 图像输入 → 网络推理 → 输出框+类别+置信度 |
| 优点 | 逻辑透明、零训练、极快 | 实现最简单、对锥桶极准、算力最低 | 类别通用、抗外观变化、上限最高 |
| 缺点 | 阈值敏感、易碎成多块、难分辨语义类别 | 光照一变就崩（见第02讲）、物块完全失效 | 需标注数据、算力大、黑盒难调试、小目标差 |
| 算力开销 | 极低 | 极低 | 高（需量化加速） |
| 开发成本 | 低（1 天可跑通） | 极低（几小时） | 高（采标数据 + 训练 + 调参，以周计） |
| 适用场景 | 结构化/半结构化场景、需快速兜底 | 颜色鲜明的固定目标（锥桶、标志牌） | 类别多、外观多变、有数据积累时 |
| 在巴哈的定位 | ✅ 兜底与后处理 | ✅ 锥桶专用，必须配自适应阈值 | ✅ 长期主力，必须轻量化 |

**工程结论**：三条路线不是"选一个"，而是**分工**——颜色法专管锥桶，几何法做兜底和误检过滤，学习法负责行人和物块。跑不动学习法时先降级为"几何+运动检测"，别让整条流水线停摆。

## 3. 边缘端轻量化设计（8 条）

**边缘端（edge）**：指算力和功耗都受限的车载计算设备（如 NVIDIA Jetson、华为昇腾、瑞芯微 RK3588）。它们没有机房里的空调和市电，所以"能跑"比"跑得准"更稀缺。

| # | 手段 | 省什么资源 | 精度/功能代价 |
|---|------|------------|---------------|
| 1 | 换轻量 backbone（YOLOv8n / NanoDet / MobileNet） | 参数量降 10~20 倍，显存、算力同比例下降 | mAP 下降 3~8 个百分点；小目标和密集目标变差 |
| 2 | INT8 量化 + TensorRT / ONNX Runtime 加速 | 内存降 4 倍，速度提升 2~4 倍 | 精度损失约 1~2 个百分点；极暗/极亮输入下量化误差放大 |
| 3 | 降低输入分辨率（640→320） | 算力约降为 1/4（像素数按平方减少） | 12 m 以外的行人/小物块基本检不出，小目标召回率明显下降 |
| 4 | ROI 限制 + 图像下半部优先 | 只算有用区域，算力降 40%~70% | 高空/远距离目标被裁掉；急弯时 ROI 需动态调整否则漏检 |
| 5 | 抽帧检测 + 帧间跟踪补偿（KCF / ByteTrack） | 检测帧率减半即算力减半 | 高速目标（横穿行人）可能追丢；跟踪框会漂移，需定期重检 |
| 6 | 模型剪枝 + 知识蒸馏 | 通道裁剪 30%~50%，算力与内存同步下降 | 剪枝过多不可逆地损伤精度；蒸馏需先训出大"教师模型"，训练成本上升 |
| 7 | 提前退出 + 级联检测（先小模型筛，再大模型复核） | 大部分帧只跑小模型，平均算力大幅下降 | 级联阈值难调：小模型漏掉的候选永无复核机会（漏检不可恢复） |
| 8 | 异构部署（Jetson GPU / 昇腾 NPU / 瑞芯微 NPU） | 用硬件专用加速单元，能效比提升数倍 | 需为不同芯片重写推理后端、算子兼容性有坑；开发与维护成本上升 |

> 💡 类比：轻量化就像给快递车省油——换小排量发动机（轻量 backbone）、少装货（降分辨率）、只送必要的那几条街（ROI）、隔一趟送一次全靠导航猜（抽帧+跟踪）、把大箱子拆成小箱子（剪枝蒸馏）、能走高速就走高速（TensorRT/NPU）。**每一招都省了油，也都牺牲了一部分运力，关键是知道自己牺牲的那部分能不能接受。**

> ⚠️ 常见坑：为了提帧率无脑降分辨率。降到 320 后，15 m 外的行人只剩十几个像素，检测器直接瞎了。**正确做法是"分区降分辨"**：下方近处保高分辨率（行车安全最关键），上方远处用低分辨率粗筛，再用 ROI 放大复核。

## 4. 轻量化设计决策表

指标之间是**互相抢资源**的关系，必须先排优先级，否则每次调参都在原地打转。

| 指标 | 优先级（巴哈场景） | 理由 | 达不到时的降级顺序 |
|------|-------------------|------|-------------------|
| **速度 FPS** | 🥇 最高（≥20 FPS 硬门槛） | 50 km/h ≈ 14 m/s，低帧率直接等同于"看不见" | 先降分辨率 → 再抽帧+跟踪 → 最后减类别 |
| **召回率 Recall** | 🥈 很高（行人必须 ≥95%） | 漏检行人 = 事故，安全项不可协商 | 单独给"行人"通道保留高分辨率 ROI，其它类别让路 |
| **功耗 / 散热** | 🥉 高 | 车载电池有限、封闭车厢散热差，过热降频会让帧率雪崩 | 降低功耗墙 + 主动散热 + 限制 NPU 满载时长 |
| **内存** | 中 | 一般不是首位瓶颈，但 OOM 会直接崩 | 缩小 batch、复用缓冲区、不缓存历史帧图像 |
| **误报率 FPR** | 中 | 误报只导致不必要减速，损失可控 | 靠时域投票（连续 3 帧确认）压制，而不是提高单帧阈值 |
| **精度 mAP（全类别）** | 最低 | 综合指标好看 ≠ 行车安全 | 最后再动，别为了 mAP 牺牲 FPS |
| **开发成本** | 视团队阶段 | 招新/初期应优先"能跑起来"，成熟期再追精度 | 初期选成熟开源方案（YOLOv8n + TensorRT），别自研网络 |

### 30 FPS 目标下的推荐配置

```text
硬件：Jetson Orin Nano（或同级 NPU 板）8 GB，功耗墙 15 W，主动散热
输入：全局快门相机 1280×720 @60fps（全局快门避免运动果冻效应）
分辨率策略：下半部 ROI 裁剪为 640×360 送检测网络；上半部仅做粗筛
模型：YOLOv8n，INT8 量化 + TensorRT 引擎，输入 416×416
调度：检测 15 FPS（抽帧）+ ByteTrack 跟踪补帧 → 输出 30 FPS 目标轨迹
专用通道：HSV 橙色阈值并行检测锥桶（几乎零算力，与网络同时跑）
流水线预算：去畸变 2 ms + CLAHE 2 ms + 检测 25 ms + 跟踪 3 ms + 后处理 3 ms ≈ 35 ms
预期性能：行人召回率 ≥92%、锥桶召回率 ≥95%、端到端延迟 ≤60 ms
```

这套配置的取舍逻辑很清楚：**用"抽帧检测 + 跟踪补帧"换帧率，用"ROI 限制 + INT8 量化"换速度，把省下的算力留给"行人必须看清"这一条安全底线。**

### 练习 1：用颜色法抓锥桶，并看看它有多脆

```python
# demo03_cone.py —— 把一张赛道照片里的橙色锥桶抠出来
import cv2
import numpy as np

img = cv2.imread("track.jpg")        # 换成有锥桶（或任何橙色物体）的照片
if img is None:                      # ⚠️ 忘了这句，图片路径写错时会抛出难懂的断言错误
    raise SystemExit("读不到 track.jpg，检查路径与文件名")
hsv = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)

# 橙色在 HSV 的 H 轴上横跨色环零点：橙 11~25，红 0~10 与 170~179
# ⚠️ 只写 0~15 会漏掉标准交通橙（BGR 0,140,255 → H=16），必须两段合并
m1 = cv2.inRange(hsv, (0,   80, 80), (25,  255, 255))    # 红 + 橙
m2 = cv2.inRange(hsv, (170, 80, 80), (179, 255, 255))    # 红色绕回的那一段
mask = cv2.bitwise_or(m1, m2)

# 形态学：开运算去噪点，闭运算把断开的锥桶连起来
k = np.ones((5, 5), np.uint8)
mask = cv2.morphologyEx(mask, cv2.MORPH_OPEN,  k)
mask = cv2.morphologyEx(mask, cv2.MORPH_CLOSE, k)

# 连通域 + 几何筛选：面积够大、高宽比合理才认
n, labels, stats, _ = cv2.connectedComponentsWithStats(mask)
out = img.copy()
found = 0
for i in range(1, n):
    x, y, w, h, area = stats[i]
    if area < 200 or h < 20:
        continue
    ratio = h / float(w + 1e-6)                 # 锥桶高宽比约 1.5~2.0
    if not (1.0 <= ratio <= 3.0):
        continue
    found += 1
    cv2.rectangle(out, (x, y), (x + w, y + h), (0, 255, 0), 2)

print(f"候选连通域总数 = {n - 1}, 通过几何筛选的锥桶 = {found} 个")
cv2.imwrite("out_cones.png", out)
```

> ✅ 你应该看到：终端打印 `候选连通域总数 = 37, 通过几何筛选的锥桶 = 2 个`（数字随图片变化），`out_cones.png` 里只在真正的锥桶上画了绿框。
> **接着做实验**：把同一张图用图像编辑软件调暗 50% 再跑一次，记录 `found` 的变化。你会发现锥桶"消失"了——这就是为什么颜色法必须配自适应阈值（第02讲 (a) 方案）。

## 本讲小结

| 概念 | 要点 |
|------|------|
| 三类障碍物 | 行人靠形状+运动；物块靠几何（凸出地面）；锥桶靠颜色（橙红+固定高宽比） |
| 三条路线 | 几何法（透明但脆）、颜色法（最快但怕光照）、学习法（最强但吃算力数据） |
| 分工原则 | 颜色法管锥桶、几何法兜底过滤、学习法管行人/物块——不是三选一 |
| 轻量化 8 招 | 轻 backbone、INT8+TensorRT、降分辨率、ROI、抽帧+跟踪、剪枝蒸馏、级联提前退出、异构部署 |
| 指标优先级 | FPS ≥20 ＞ 行人召回率 ＞ 功耗散热 ＞ 内存 ＞ 误报率 ＞ 全类 mAP |
| 30 FPS 配置 | YOLOv8n + INT8 + TensorRT @416，下半部 ROI，检测 15 FPS + ByteTrack 补到 30 FPS |
