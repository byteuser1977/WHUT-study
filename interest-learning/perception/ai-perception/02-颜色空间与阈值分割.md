---

## 1. 为什么需要"颜色空间"

计算机里的彩色图，每个像素存的是三个数（B、G、R 三个通道的亮度）。这套坐标系叫 **RGB（或 BGR）颜色空间**。

RGB 很直观，但有一个致命问题：**三个通道全都跟光照强度强耦合**。

> 💡 类比：想象你在不同灯光下看同一个红苹果。
> - 太阳底下：`(200, 60, 50)`
> - 阴天：`(110, 33, 27)`
> - 晚上路灯下：`(180, 90, 60)`
>
> 你想用代码说"我要找红色"，用 RGB 就得写 `R > 150 and G < 80 and B < 80`——可阴天那个苹果直接不满足了。**同一个东西，换个光照，数值全变。**

我们想要的是：**把"这是什么颜色"和"这里有多亮"分开**。HSV 就是干这个的。

---

## 2. 三种常用颜色空间

| 颜色空间 | 三个通道的含义 | 特点 |
|---|---|---|
| **RGB / BGR** | 红、绿、蓝的亮度 | 直观但光照敏感，三通道互相影响 |
| **HSV** | **H**ue 色相（什么颜色，0~179）<br>**S**aturation 饱和度（颜色多纯，0~255）<br>**V**alue 明度（多亮，0~255） | **H 通道只表示颜色种类，与光照基本无关** —— 视觉识别的首选 |
| **Lab** | L 亮度 + a/b 两个颜色对立轴 | 与设备无关，色彩差异度量最准，适合做颜色距离比较 |
| **GRAY** | 单个亮度值 | 丢掉颜色信息，用于形状/边缘分析 |

**核心结论**：在 HSV 里，"红色物体"的 H 值不管在太阳下还是阴天都差不多 → 只要卡 H 的范围，光照变化就影响不大了。**这就是为什么视觉识别偏爱 HSV。**

```python
import cv2
import numpy as np

img = cv2.imread("src.jpg")
hsv = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)
lab = cv2.cvtColor(img, cv2.COLOR_BGR2LAB)
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
```

> ⚠️ 坑：**OpenCV 里的 H 范围是 0~179，不是 0~360**（因为它把 360 压缩成 uint8 的 180 个值，但实际在 0-179）。很多网上教程写 0~360，直接抄会全部失效。S 和 V 都是 0~255。

## 3. HSV 常用颜色阈值参考表

这是工程里最实用的一张表，直接抄：

| 颜色 | H 范围（OpenCV） | S 范围 | V 范围 |
|---|---|---|---|
| 红（第一种） | 0 ~ 10 | 43 ~ 255 | 46 ~ 255 |
| 红（第二种） | 170 ~ 179 | 43 ~ 255 | 46 ~ 255 |
| 橙（锥桶常用） | 11 ~ 25 | 43 ~ 255 | 46 ~ 255 |
| 黄 | 26 ~ 34 | 43 ~ 255 | 46 ~ 255 |
| 绿 | 35 ~ 77 | 43 ~ 255 | 46 ~ 255 |
| 蓝 | 100 ~ 124 | 43 ~ 255 | 46 ~ 255 |
| 紫 | 125 ~ 155 | 43 ~ 255 | 46 ~ 255 |

> ⚠️ 红色在 H 轴上分布在**两端**（0~10 和 170~179），因为色环是首尾相接的。所以抠红色必须做**两次 inRange 再按位或**，只写一次会漏掉一半。
>
> 💡 类比：红色跨越了色环的"零点"，就像经度 179° 和 -179° 其实是挨着的。

## 4. 阈值分割：把颜色变成掩膜

### 4.1 `cv2.inRange` —— 范围筛选

```python
# 抠橙色（锥桶）
lower = np.array([11, 43, 46])
upper = np.array([25, 255, 255])
mask = cv2.inRange(hsv, lower, upper)
```

`inRange` 的规则很简单：**三个通道的值都落在 [lower, upper] 区间内 → 该像素为 255（白）；否则 0（黑）**。

结果是一张**二值掩膜（mask）**——白色代表"我想要的区域"。

用掩膜可以把原图里的目标"抠出来"：

```python
result = cv2.bitwise_and(img, img, mask=mask)
cv2.imwrite("result.png", result)   # 只保留橙色区域，其余变黑
```

### 4.2 红色的正确写法（两段合并）

```python
mask1 = cv2.inRange(hsv, np.array([0, 43, 46]),   np.array([10, 255, 255]))
mask2 = cv2.inRange(hsv, np.array([170, 43, 46]), np.array([179, 255, 255]))
mask = cv2.bitwise_or(mask1, mask2)
```

### 4.3 灰度图的阈值：固定阈值 / Otsu / 自适应

如果目标是"亮暗差异"而不是"颜色差异"，可以直接在灰度图上做阈值。

```python
# (a) 固定阈值：暗于 127 的变 0，亮于 127 的变 255
_, th_fixed = cv2.threshold(gray, 127, 255, cv2.THRESH_BINARY)

# (b) Otsu 自动阈值：让算法自己找一个"把两类分得最开"的阈值
_, th_otsu = cv2.threshold(gray, 0, 255, cv2.THRESH_BINARY + cv2.THRESH_OTSU)
print("Otsu 自动算出的阈值 =", _)     # 第一个返回值就是它选的门限

# (c) 自适应阈值：每个小区域单独算一个阈值，专治光照不均
th_adapt = cv2.adaptiveThreshold(
    gray, 255,
    cv2.ADAPTIVE_THRESH_GAUSSIAN_C,   # 用高斯加权求局部均值
    cv2.THRESH_BINARY,
    11,   # 邻域大小，必须是奇数
    2     # 从局部均值里减掉的常数，用来微调
)
```

| 方法 | 什么时候用 | 缺点 |
|---|---|---|
| 固定阈值 | 光照稳定、目标与背景对比固定 | 换个场地就失效 |
| **Otsu** | 图像里**明显只有两类**（目标/背景），但整体亮度会变 | 目标占比过小时会跑偏 |
| **自适应阈值** | **光照不均**（一半亮一半暗、有阴影） | 计算量大，容易把纹理噪点也分出来 |

> 💡 类比：
> - 固定阈值 = 全班用同一条及格线
> - Otsu = 根据全班成绩分布自动找一条分得最开的线
> - 自适应阈值 = 每个小组各定一条及格线（有的组题难、有的组题简单）

## 5. 完整实战：抠出橙色锥桶

```python
import cv2
import numpy as np

img = cv2.imread("cone.jpg")
hsv = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)

# 1) 颜色范围筛选（橙红两段都算，因为锥桶颜色偏红橙）
m1 = cv2.inRange(hsv, np.array([0, 70, 70]),   np.array([10, 255, 255]))
m2 = cv2.inRange(hsv, np.array([11, 70, 70]),  np.array([25, 255, 255]))
mask = cv2.bitwise_or(m1, m2)

# 2) 形态学去噪（本讲不展开，见大类二第04讲）
kernel = np.ones((5, 5), np.uint8)
mask = cv2.morphologyEx(mask, cv2.MORPH_CLOSE, kernel)   # 补小洞
mask = cv2.morphologyEx(mask, cv2.MORPH_OPEN, kernel)    # 去小噪点

# 3) 找轮廓并框出来
contours, _ = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
for c in contours:
    area = cv2.contourArea(c)
    if area < 500:            # 太小的当噪声丢掉
        continue
    x, y, w, h = cv2.boundingRect(c)
    cv2.rectangle(img, (x, y), (x + w, y + h), (0, 255, 0), 2)

cv2.imwrite("cone_out.png", img)
cv2.imwrite("cone_mask.png", mask)
print(f"检测到 {len([c for c in contours if cv2.contourArea(c) >= 500])} 个锥桶候选")
```

✅ 你应该看到：`cone_out.png` 里每个锥桶被绿框圈住，`cone_mask.png` 里锥桶是白色、其余全黑。

## 6. 一句话说清"为什么颜色识别会脆"

HSV 已经比 RGB 抗光照了，但它在巴哈赛道上依然会失效，原因有三：

1. **光照还是会影响**：S 和 V 通道依然随光照变化，极端逆光/阴影下 HSV 也不准
2. **颜色会变**：泥水覆盖、扬尘、镜头脏污会直接改变物体的反射颜色
3. **颜色不是唯一特征**：同一个颜色可能是路面、可能是路标、也可能是队友的衣服

> 这正是"大类六 巴哈赛道感知实战"第 02 讲要展开的问题。**先在这里记住：HSV 是工具，不是万能解。**

## 🎯 课后练习（约6分钟）

### 练习 1：看清光照的影响

```python
import cv2
import numpy as np

img = cv2.imread("src.jpg")
hsv = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)

# 模拟"变暗 50%"（相当于阴影）
dark = (img.astype(np.float32) * 0.5).astype(np.uint8)

# 在 BGR 和 HSV 里分别取同一个像素点比较
for name, im in [("原图", img), ("变暗", dark)]:
    b, g, r = im[240, 320]
    h, s, v = cv2.cvtColor(im, cv2.COLOR_BGR2HSV)[240, 320]
    print(f"{name}: BGR=({b},{g},{r})  HSV=({h},{s},{v})")
```

✅ 你应该看到（数值随图片不同，但规律是固定的）：
```
原图: BGR=(180,90,60)  HSV=(12,170,180)
变暗: BGR=(90,45,30)   HSV=(12,85,90)
```
**BGR 三个通道全变了（180→90），而 HSV 的 H 通道几乎没变（12→12）**。这就是"用 HSV 抗光照"的直接证据。

### 练习 2：给图片换个颜色空间

用 `cv2.split()` 把 HSV 拆成三个单通道图，各自用 `cv2.imshow` 看一遍，观察：
- H 通道像不像一张"颜色分类图"（同一颜色的物体亮度接近）？
- V 通道像不像一张普通的灰度照片？

```python
h, s, v = cv2.split(hsv)
cv2.imshow("H 色相", h)   # 同一颜色的区域亮度接近
cv2.imshow("S 饱和度", s)
cv2.imshow("V 明度", v)   # 接近灰度图
cv2.waitKey(0)
cv2.destroyAllWindows()
```

### 练习 3：动手抠一个颜色

拍一张桌面上有彩色物品的照片，选一个颜色，用第 3 节的 HSV 阈值表 + `cv2.inRange` 把它抠出来（输出掩膜），再叠加回原图看效果。

**调参口诀**：抠不干净 → 缩小 S、V 的下界（提高纯度要求）；目标被抠碎 → 放宽 H 范围或降低 V 下界。

## 本讲小结

| 概念 | 要点 |
|---|---|
| 颜色空间 | RGB/BGR（直观但光照敏感）、**HSV**（H 与光照解耦，识别首选）、Lab（颜色距离最准）、GRAY |
| HSV 通道 | H 色相 0~179（OpenCV），S 饱和度 0~255，V 明度 0~255 |
| 红色陷阱 | H 分布在两端（0~10 与 170~179），必须两段 inRange 再 or |
| inRange | 三通道都落在区间内 → 255，得到二值掩膜 |
| 固定阈值 | 光照稳定时用，换场地就废 |
| Otsu | 自动找最佳分割阈值，适合明显的两类图像 |
| 自适应阈值 | 每块小区域单独算阈值，专治光照不均 |
| 工程现实 | HSV 比 RGB 抗光照，但在泥水/扬尘赛道上依然会失效，需要多特征融合 |
