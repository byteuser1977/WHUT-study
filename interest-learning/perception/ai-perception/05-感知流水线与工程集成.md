## 1. 一条完整的感知流水线

前面几讲是「单点算法」，这一讲把它们串成**车上真正运行的链路**：

```
┌─────────────┐
│  摄像头采集  │  30 FPS, 640×480, BGR
└──────┬──────┘
       ▼
┌─────────────┐
│  去畸变      │  cv2.remap（用标定好的内参+畸变系数）
└──────┬──────┘
       ▼
┌─────────────┐
│  预处理      │  降分辨率 → ROI 裁剪 → 灰度化/模糊
└──────┬──────┘
       ▼
┌─────────────┐        抽帧：每 2 帧处理 1 帧
│ 感知算法     │  ←── 可行驶区域分割 / 障碍物检测（03、04 讲）
└──────┬──────┘
       ▼
┌─────────────┐
│ 后处理       │  形态学清理 + 时序滤波（连续 3 帧都判为障碍才确认真障碍）
└──────┬──────┘
       ▼
┌─────────────┐
│ ROS 2 发布   │  /perception/drivable_mask（Image）
└──────┬──────┘  /perception/occupancy（OccupancyGrid）
       ▼
┌─────────────┐
│  规划 / 控制 │  订阅上面的话题，决定方向盘与油门
└─────────────┘
```

> 💡 类比：这就是一条**洗车流水线**。摄像头是进水口，去畸变是矫正「镜头把直线拍弯」的整形环节，预处理是过滤大颗粒（降尺寸、砍掉无关区域），感知算法是真正的刷洗，后处理是擦干抛光（去掉毛刺），ROS 2 发布是把车交出去——交给了停在外面的规划模块。任何一环堵了，后面全部停摆。

## 2. 相机标定与去畸变

### 为什么必须做

现实中的镜头（尤其是广角镜头）没法把三维世界完美投影到平面上，结果是**直线被拍成弧线**（桶形畸变）。你看画面里一条笔直的车道线变成了弯的，那么「车道左侧 30 cm」这个判断就是错的——**控制模块会照着一条弯曲的假车道线打方向盘**。

### 两个关键量

| 名称 | 符号 | 是什么 | 怎么来 |
|------|------|--------|--------|
| 内参矩阵 | `K`（3×3） | 焦距（像素单位 fx, fy）和光心（cx, cy） | 标定得到 |
| 畸变系数 | `D`（1×5） | 径向畸变 k1,k2,k3 + 切向畸变 p1,p2 | 标定得到 |

标定做法（OpenCV 官方流程）：
1. 打印一张**棋盘格**（checkerboard，比如 9×6 格、格子 25 mm），贴在硬板上；
2. 从不同角度拍 15~20 张照片，要求棋盘格铺满画面不同区域；
3. 用 `cv2.findChessboardCorners` 找角点，再用 `cv2.calibrateCamera` 解出 `K` 和 `D`；
4. **标定一次，参数存成 `.npz` 文件，以后每次启动直接加载**（不用重标）。

```python
# calibrate.py —— 跑一次就够，把结果存下来
import numpy as np
import cv2
import glob

BOARD = (9, 6)          # 内角点数量（注意是"角点"，不是格子数，比格子少 1）
SQUARE_MM = 25.0

objp = np.zeros((BOARD[0] * BOARD[1], 3), np.float32)
objp[:, :2] = np.mgrid[0:BOARD[0], 0:BOARD[1]].T.reshape(-1, 2) * SQUARE_MM

obj_points, img_points = [], []
for fname in sorted(glob.glob("calib/*.jpg")):
    img = cv2.imread(fname)
    gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
    ok, corners = cv2.findChessboardCorners(gray, BOARD, None)
    if ok:
        obj_points.append(objp)
        img_points.append(corners)
print(f"成功检测到角点的照片数: {len(obj_points)}")

ret, K, D, _, _ = cv2.calibrateCamera(obj_points, img_points, gray.shape[::-1], None, None)
print("重投影误差 (越小越好, <0.5 像素算优秀): %.4f" % ret)
print("内参矩阵 K =\n", np.round(K, 2))
print("畸变系数 D =", np.round(D.ravel(), 4))
np.savez("camera_calib.npz", K=K, D=D)
print("已保存 camera_calib.npz")
```

> ✅ 你应该看到（类似）：
> ```
> 成功检测到角点的照片数: 17
> 重投影误差 (越小越好, <0.5 像素算优秀): 0.2134
> 内参矩阵 K =
>  [[612.45   0.   319.83]
>  [  0.   611.97 241.06]
>  [  0.     0.     1.  ]]
> 畸变系数 D = [-0.3121  0.0987 -0.0012  0.0007 -0.0213]
> 已保存 camera_calib.npz
> ```

### 去畸变：实时要用 `remap`，别用 `undistort`

`cv2.undistort` 每帧都要重新算一遍映射表，慢；**工程上先用 `cv2.initUndistortRectifyMap` 算一次映射表，之后每帧只做 `cv2.remap` 查表**，速度能翻倍。

```python
# undistort_live.py
import numpy as np
import cv2

calib = np.load("camera_calib.npz")
K, D = calib["K"], calib["D"]

cap = cv2.VideoCapture(0)
ok, frame = cap.read()
if not ok:
    raise SystemExit("打不开摄像头")
h, w = frame.shape[:2]

# 只算一次映射表
map1, map2 = cv2.initUndistortRectifyMap(K, D, None, K, (w, h), cv2.CV_16SC2)

for _ in range(10):
    ok, frame = cap.read()
    if not ok:
        break
    fixed = cv2.remap(frame, map1, map2, interpolation=cv2.INTER_LINEAR)
    cv2.imshow("origin | undistorted", np.hstack([frame, fixed]))
    if cv2.waitKey(1) & 0xFF == ord("q"):
        break
cap.release()
cv2.destroyAllWindows()
print("去畸变演示结束")
```

> ✅ 你应该看到：左右两个画面并排，**右边的直线（门框、显示器边缘）明显更直**，画面边缘被拉伸修正。
> ⚠️ 常见坑：如果标定用的分辨率（比如 1280×720）和实际使用的不一致，`K` 里的 fx/fy/cx/cy 必须按比例缩放，否则去畸变结果会整体偏移。

## 3. 三个最省算力的工程手段

思维类第 3 题（算力优化）的核心答案就在这——**算力不是靠换硬件省出来的，是靠「少算」省出来的**。

| 手段 | 怎么做 | 省多少 | 代价 |
|------|--------|--------|------|
| **ROI 裁剪** | 只处理画面下半部分（`img[h//2:, :]`） | 直接省 50% 像素 | 上半部分的目标（远处行人）看不见 |
| **降分辨率** | 640×480 → 320×240（`cv2.resize`） | 像素数降到 1/4，耗时约降到 1/3 | 小目标、细车道线精度下降 |
| **抽帧** | 30 FPS 只处理 15 FPS，中间帧用上一帧结果 | 省 50% 算力 | 高速移动时结果有滞后，需跟踪补偿 |

```python
# 三个手段一起上
small = cv2.resize(frame, (320, 240), interpolation=cv2.INTER_AREA)  # 降分辨率
small = small[120:, :]                                              # ROI：只留下半
if frame_id % 2 == 0:                                              # 抽帧：每 2 帧处理 1 次
    mask = run_perception(small)
    last_mask = mask
else:
    mask = last_mask                                               # 复用上一帧
```

> 💡 类比：这三招就像**考试时间不够时的做题策略**——先跳过难题（ROI 砍掉无关区域）、字写小一点省纸（降分辨率）、没时间做完就先把会做的做完再回头（抽帧）。不是偷懒，是**把有限算力花在最有价值的地方**。

> ⚠️ 常见坑：`cv2.resize` 缩小时用 `INTER_AREA`（区域平均，抗摩尔纹），放大时用 `INTER_LINEAR`。用错插值方法会导致图像出现锯齿或糊成一团。

## 4. 把结果发到 ROS 2 话题

感知模块的产物最终要给规划模块用，中间的「快递通道」就是 ROS 2 话题。车上最常用的两种消息：

| 消息类型 | 用途 | 关键字段 |
|----------|------|----------|
| `sensor_msgs/Image` | 传（处理后的）图像，比如掩膜、渲染图 | `height`, `width`, `encoding`, `data` |
| `nav_msgs/OccupancyGrid` | 传**栅格地图**：把画面压成一张粗网格，每格标「空闲/占用/未知」 | `info.resolution`, `info.width/height`, `data[]` |

**OccupancyGrid（占据栅格地图）** 是规划模块最爱的格式：它把世界（或图像）切成小方格，每个格子的值有三种：

- `0`：空闲（free）——可以走
- `100`：占用（occupied）——有障碍
- `-1`：未知（unknown）——没看到，别赌

比传一整张 640×480 的图像（30 万字节）省得多，一张 40×20 的栅格只有 800 个字节。

```python
# perception_node.py —— 可行驶区域 → 发布 Image + OccupancyGrid
import numpy as np
import cv2
import rclpy
from rclpy.node import Node
from rclpy.qos import QoSProfile, ReliabilityPolicy, HistoryPolicy
from sensor_msgs.msg import Image
from nav_msgs.msg import OccupancyGrid
from cv_bridge import CvBridge

GRID_W, GRID_H = 40, 20          # 栅格尺寸（粗粒度，远小于像素尺寸）
RES = 0.1                        # 每格 0.1 m


class PerceptionNode(Node):
    def __init__(self):
        super().__init__("drivable_perception")
        self.bridge = CvBridge()

        # 传感器数据用 BEST_EFFORT：丢一两帧没关系，绝不阻塞
        qos = QoSProfile(depth=1,
                         reliability=ReliabilityPolicy.BEST_EFFORT,
                         history=HistoryPolicy.KEEP_LAST)

        self.pub_img = self.create_publisher(Image, "/perception/drivable_mask", qos)
        self.pub_grid = self.create_publisher(OccupancyGrid, "/perception/occupancy", qos)
        self.pub_raw = self.create_publisher(Image, "/perception/debug_view", qos)
        self.create_timer(1.0 / 15.0, self.timer_cb)   # 15 Hz 处理
        self.cap = cv2.VideoCapture(0)
        self.frames = 0
        self.get_logger().info("感知节点已启动，发布 /perception/drivable_mask")

    def segment(self, img):
        """第03讲的最简方案（真实项目替换为 SegFormer）"""
        h, w = img.shape[:2]
        gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
        blur = cv2.GaussianBlur(gray, (7, 7), 0)
        roi = blur[h // 2:, :]
        _, binary = cv2.threshold(roi, 0, 255, cv2.THRESH_BINARY + cv2.THRESH_OTSU)
        seed = binary[-60:, w // 2 - 30: w // 2 + 30]
        if (seed > 0).mean() < 0.5:
            binary = cv2.bitwise_not(binary)
        kernel = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (25, 25))
        closed = cv2.morphologyEx(binary, cv2.MORPH_CLOSE, kernel)
        num, labels, stats, _ = cv2.connectedComponentsWithStats(closed, 8)
        mask = np.zeros((h, w), np.uint8)
        if num > 1:
            biggest = 1 + int(np.argmax(stats[1:, cv2.CC_STAT_AREA]))
            mask[h // 2:, :] = np.where(labels == biggest, 255, 0).astype(np.uint8)
        return mask

    def timer_cb(self):
        ok, frame = self.cap.read()
        if not ok:
            self.get_logger().warn("读取摄像头失败")
            return
        self.frames += 1

        frame = cv2.resize(frame, (320, 240), interpolation=cv2.INTER_AREA)
        mask = self.segment(frame)

        # ---- 1) 发布掩膜图（Image）----
        img_msg = self.bridge.cv2_to_imgmsg(mask, encoding="mono8")
        img_msg.header.stamp = self.get_clock().now().to_msg()
        img_msg.header.frame_id = "camera_link"
        self.pub_img.publish(img_msg)

        # ---- 2) 发布占据栅格（OccupancyGrid）----
        small = cv2.resize(mask, (GRID_W, GRID_H), interpolation=cv2.INTER_AREA)
        grid = OccupancyGrid()
        grid.header = img_msg.header
        grid.info.resolution = RES
        grid.info.width = GRID_W
        grid.info.height = GRID_H
        grid.info.origin.position.x = -GRID_W * RES / 2.0
        grid.info.origin.position.y = -GRID_H * RES
        # 0=空闲(可行驶) / 100=占用 / -1=未知
        data = np.where(small > 127, 0, 100).astype(np.int8)
        grid.data = data.ravel().tolist()
        self.pub_grid.publish(grid)

        # ---- 3) 发布调试图 ----
        overlay = frame.copy()
        overlay[mask > 0] = (0, 255, 0)
        vis = cv2.addWeighted(frame, 0.6, overlay, 0.4, 0)
        self.pub_raw.publish(self.bridge.cv2_to_imgmsg(vis, encoding="bgr8"))

        if self.frames % 30 == 0:
            self.get_logger().info(f"已处理 {self.frames} 帧，可行驶占比 "
                                   f"{((mask > 0).mean() * 100):.1f}%")


def main():
    rclpy.init()
    node = PerceptionNode()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.cap.release()
        node.destroy_node()
        rclpy.shutdown()


if __name__ == "__main__":
    main()
```

## 5. 延迟与帧率怎么量化

「跑得动吗」不能凭感觉，要有数。三个必须量的指标：

| 指标 | 含义 | 怎么量 | 目标 |
|------|------|--------|------|
| **处理帧率（FPS）** | 每秒能处理多少帧 | `ros2 topic hz`，或代码统计 1/t | ≥ 15 FPS |
| **单帧耗时** | 一次算法跑多久 | `time.perf_counter()` 打点 | ≤ 66 ms（对应 15 FPS） |
| **端到端延迟** | 从相机曝光到结果发出 | 采集时打时间戳，发布时算差值 | ≤ 150 ms |

### 方法一：ROS 2 命令行（最省事）

```bash
ros2 topic hz /perception/drivable_mask
```

> ✅ 你应该看到（类似）：
> ```
> average rate: 14.872
> 	min: 0.061s max: 0.078s std dev: 0.00312s window: 30
> ```
> `average rate` 就是实际帧率；`max 0.078s` 说明最坏一帧要 78 ms——**这个最坏值才决定系统会不会卡顿**，平均值好看不代表稳。

### 方法二：代码里打点，算出 P95（工程上更有意义）

```python
import time
import numpy as np

latencies = []
for i in range(100):
    t0 = time.perf_counter()
    ok, frame = cap.read()
    t1 = time.perf_counter()
    mask = segment(frame)
    t2 = time.perf_counter()

    latencies.append((t2 - t0) * 1000)     # 端到端毫秒

lat = np.array(latencies)
print(f"帧数 {len(lat)}")
print(f"平均耗时 {lat.mean():.1f} ms  → 平均 {1000/lat.mean():.1f} FPS")
print(f"最大耗时 {lat.max():.1f} ms")
print(f"P95 耗时  {np.percentile(lat, 95):.1f} ms   ← 95% 的帧都比它快")
print(f"采集耗时 {((t1-t0)*1000):.1f} ms（相机读一帧的时间，别忽略它！）")
```

> ✅ 你应该看到（类似）：
> ```
> 帧数 100
> 平均耗时 22.4 ms  → 平均 44.6 FPS
> 最大耗时 51.8 ms
> P95 耗时  31.2 ms   ← 95% 的帧都比它快
> 采集耗时 6.3 ms（相机读一帧的时间，别忽略它！）
> ```

**为什么看 P95 而不是平均？** 因为控制环最怕的是「偶发卡顿」：平均 20 ms 但每 20 帧抖一下 200 ms，车就画龙了。P95 的意思是「95% 的帧都在这条线以内」——用它做验收标准，比平均值靠谱得多。

> ⚠️ 常见坑：只统计算法耗时（`t1→t2`）而漏掉 `cap.read()` 的相机读取时间和 `imwrite`/可视化时间，会得到「我算法只要 8 ms」的错觉。工程统计必须**从采集到发布整条链路**一起量。

## 本讲小结

| 概念 | 要点 |
|------|------|
| 感知流水线 | 采集 → 去畸变 → 预处理 → 感知算法 → 后处理 → ROS 2 发布 → 规划 |
| 相机标定 | 用棋盘格 + `cv2.calibrateCamera` 求内参 `K` 和畸变系数 `D`，标一次存 `.npz` |
| 去畸变 | 实时用 `initUndistortRectifyMap` + `remap`（查表），别每帧 `undistort` |
